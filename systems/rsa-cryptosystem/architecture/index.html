Three properties of this architecture hold throughout. First, the bignum layer is the foundation: a wrong limb-level add propagates to a wrong signature at every layer above it, so Phase 1 (§13) is differentially tested against num-bigint before anything else is built. Second, the private-key hot path (mod_exp_ct) is constant-time by construction — secret- dependent branches are eliminated at the algorithm choice (the Montgomery ladder), not patched in afterward. Third, CRT-based decryption is the only place in the stack that can leak the private key under a single-bit fault; the algorithm-level defense (re-encrypt and compare before returning) is architecturally mandatory and has no configuration flag to disable it (I6).

8. Domain Model

8.1 Modular arithmetic — the ring Z/nZ

RSA operates over the multiplicative group of integers modulo n = p·q. Key equations, used throughout §14–§16:

  • Euler's totient: φ(n) = (p−1)(q−1).
  • Carmichael function (the tighter, FIPS-186-5-mandated choice): λ(n) = lcm(p−1, q−1).
  • Public/private exponent relation: e·d ≡ 1 (mod λ(n)).
  • Encryption/decryption: c = m^e mod n; m = c^d mod n (textbook form — never used directly; always through EME-OAEP/EME-PKCS1-v1.5, §18).
  • Montgomery form: for odd modulus n and R = 2^(64·limb_count), represent a as ā = a·R mod n; Montgomery multiplication computes MontMul(ā, b̄) = a·b·R mod n in O(limb_count²) word operations with no division (§14.2).

8.2 CRT decryption — equations and state

Given private key (p, q, dP, dQ, qInv) where dP = d mod (p−1), dQ = d mod (q−1), qInv = q^{-1} mod p, and ciphertext c:

Step Computation State produced
1 m1 = c^dP mod p partial result mod p
2 m2 = c^dQ mod q partial result mod q
3 h = qInv · (m1 − m2) mod p CRT correction term
4 m = m2 + h·q recombined result mod n
5 (I6) c' = m^e mod n; require c' = c fault-injection check

Steps 1–2 are each ~4× cheaper than a full-width exponentiation mod n (half the bit-length, cubed cost — derived in §32 #6), which is the entire performance motivation for CRT and, simultaneously, the entire fault-injection attack surface Boneh-DeMillo-Lipton (1997) exploited: corrupt only m1, and step 4 recombines a consistent-looking but wrong m, whose difference from the correct value shares a large factor with p — gcd(m_faulty^e − c, n) recovers p directly. Step 5 closes this by construction (I6).

8.3 Padding schemas

EME-OAEP encoding (RFC 8017 Section 7.1.1; k = modulus byte length, hLen = hash output length):

DB        = lHash || PS || 0x01 || M                (PS = zero bytes, pads to k-hLen-1)
seed      = random(hLen)
maskedDB  = DB XOR MGF1(seed, k-hLen-1)
maskedSeed= seed XOR MGF1(maskedDB, hLen)
EM        = 0x00 || maskedSeed || maskedDB

EMSA-PSS encoding (RFC 8017 Section 9.1.1; emLen = encoded message byte length):

mHash  = Hash(M)
M'     = 0x00 x8 || mHash || salt
H      = Hash(M')
DB     = PS || 0x01 || salt                          (PS = zero bytes)
maskedDB = DB XOR MGF1(H, emLen-hLen-1)
EM     = maskedDB || H || 0xbc

Both schemas share MGF1 (a hash-based mask generation function, RFC 8017 Appendix B.2.1) as their building block; both are "masking," not "encryption" — the security proof (Bellare-Rogaway 1996 for PSS; the OAEP IND-CCA2 reduction cited in Katz & Lindell for OAEP) depends on the exact byte layout above, which is why P1/P2/P3 forbid deviation.

8.4 Sequence — sign then verify (round trip)

Step Operation Data state
1 caller computes mHash = Hash(message) 32-byte digest (SHA-256 example)
2 EMSA-PSS-Encode(mHash, salt) → EM emLen-byte encoded message
3 OS2IP(EM) → integer m big integer < n
4 RSASP1(private_key, m) → s (CRT + blinding, §16/§19) big integer < n
5 I2OSP(s) → signature bytes k-byte signature
6 (verify) OS2IP(signature) → s big integer
7 RSAVP1(public_key, s) → m' big integer
8 I2OSP(m') → EM' emLen-byte candidate
9 EMSA-PSS-Verify(EM', mHash) → accept/reject boolean (I11: byte-exact)

8.5 Worked example (illustrative parameters only — production keys are ≥2048-bit per P9/ADR-12)

Classic small-parameter walkthrough (the standard pedagogical values): p = 61, q = 53, n = p·q = 3233, φ(n) = 60·52 = 3120, e = 17 (gcd(17, 3120) = 1), d = 17^{-1} mod 3120 = 2753. Encrypting m = 65: c = 65^17 mod 3233 = 2790. Decrypting: m = 2790^2753 mod 3233 = 65. This demonstrates the textbook primitive only (§8.1); production encryption always wraps m/c in EME-OAEP (§8.3) first.

8.6 Malformed-input example

An EME-OAEP ciphertext arrives with a corrupted label hash (lHash mismatch after unmasking). A naive decoder distinguishes "label hash mismatch" from "padding boundary 0x01 not found" via a different error return or a different number of comparisons — this is exactly the distinguishing oracle Manger (2001) exploits. The correct decoder (§18.2, I9) combines both checks into one constant-time Choice and returns a single, ciphertext-derived decoy value on either failure — the caller cannot distinguish "wrong label" from "wrong padding" from "corrupted ciphertext" by return value, error type, or timing.

8.7 Failure-path example

A single-bit fault flips one bit of m1 (§8.2 step 1) during signing — e.g., a voltage- glitching attacker targets the mod p exponentiation. Step 4 recombines a m_faulty that is wrong only in its residue mod p, consistent mod q. Without I6, the signer returns s_faulty; the attacker computes gcd(s_faulty^e − message, n), which shares the factor q, recovering the full factorization in one multiplication and one gcd. With I6 (§16 step 5), the signer's own re-encryption check (s_faulty^e mod n ≠ original message representative) fails before the value ever leaves the function, and the call returns Err(FaultInjection) — the attacker observes only a failed operation, no distinguishing arithmetic.
