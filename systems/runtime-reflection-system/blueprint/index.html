Project Number: 346

Project Name: Runtime Reflection System from Scratch

Document: FINAL_BLUEPRINT.md

Owner: Mujir Qureshi

Status: specification — locked

1. Goal

1.1 What Is Built

A pure-Rust runtime reflection library built entirely from scratch: a trait hierarchy that exposes any type's structure at runtime, a type-info model describing fields/variants/elements, a registry mapping type identity to capability objects, dynamic proxy types for partially-constructed values, and higher-level consumers (path traversal, serde integration, function reflection) all driven by a proc-macro #[derive(Reflect)].

System boundaries:

  • In scope: trait hierarchy (PartialReflect, Reflect, subtrait set), TypeInfo tree, TypeRegistry, all Dynamic* proxy types, #[derive(Reflect)] proc-macro, FromReflect, property-path API, registry-keyed serde, function reflection.
  • Out of scope: FFI/C ABI interop, cross-process type exchange, JIT compilation, stackful coroutines, async reflection, schema versioning / migration, network transport, WASM ABI.

Deployment model: single-process, in-memory library crate. No daemon, no IPC, no persistence layer. Consumers link the crates into their binary; the registry lives in application memory for the process lifetime.

Language: Rust — rationale (exact): Rust has no built-in runtime reflection or RTTI beyond std::any::Any, which makes "from scratch" meaningful: you build the type registry, the type-info model, the dynamic proxy types, and the derive macro yourself. Rust's proc-macro system generates the per-type glue at compile time; its trait-object + downcast model gives the dynamic dispatch. Model: bevy_reflect. Single process, in-memory; the reflection layer is library-level, no FFI ABI in scope.

2.2 Historical and Architectural Significance

  • C# System.Reflection (1.0, 2002): first widely-used managed-language reflection; PropertyInfo.GetValue / MethodInfo.Invoke model is the direct ancestor of DynamicFunction + GetPath.
  • Java java.lang.reflect: Class.getDeclaredFields(), Field.get(obj) — the field-by-name access pattern mirrors trait Struct::field(name).
  • Qt meta-object system (MOC): compile-time code generation (moc) → runtime property/signal dispatch; exact analog of refl-derive → TypeRegistry.
  • Go reflect package: Type / Value / Kind decomposition is the direct template for TypeInfo / ReflectRef / ReflectRef variant arms.
  • bevy_reflect: the direct design model; demonstrates that a zero-overhead-at-unuse reflection layer is possible in Rust; used in production game-engine contexts.
  • facet crate: alternative Rust reflection design; contrast with bevy_reflect on TypePath stability and proc-macro strategy.

3.2 Subsystem Descriptions

refl-derive proc-macro (compile time). Consumes DeriveInput from syn; emits impl PartialReflect, impl Reflect, impl Struct (or Enum/TupleStruct/Tuple), impl Typed, and impl GetTypeRegistration for the annotated type. Processes #[reflect(ignore)], #[reflect(default)], #[reflect(SomeTrait)] attributes. Outputs are purely code; no runtime state produced. Trust boundary: operates on caller source AST; hygiene must prevent identifier capture. No I/O, no filesystem access.

TypeRegistry (runtime, refl-registry). Central mutable store: HashMap<TypeId, TypeRegistration> plus a HashMap<TypePath, TypeId> index. Guarded by RwLock; cloneable as Arc<RwLock<TypeRegistry>>. Accepts register::<T>() (calls T::get_type_registration()), register_type_data::<T, D>() (inserts a TypeData object keyed by TypeId::of::<D>()). Trust boundary: all public mutating methods require &mut self or write-lock. No persistence; contents live for the process.

Reflect value (runtime, refl-core). Any concrete value that implements Reflect can produce a ReflectRef (or ReflectMut/ReflectOwned) describing its structure. as_any() / as_any_mut() provide TypeId-checked downcasting (P8, I5). apply() and set() mutate in-place. Concurrency: the value itself is not synchronized; callers hold &mut for mutation — standard Rust borrow rules.

ReflectRef / ReflectMut / ReflectOwned (enum dispatch, refl-core). Enum arms: Struct, TupleStruct, Tuple, List, Array, Map, Set, Enum, Opaque. Each arm carries a &dyn Struct (or respective subtrait) borrow. Consumers match on the arm to obtain the subtrait interface; no unsafe in the match itself. Trust boundary: lifetimes tie the borrow to the originating value.

Dynamic* proxies (refl-dynamic). DynamicStruct, DynamicTupleStruct, DynamicTuple, DynamicEnum, DynamicList, DynamicArray, DynamicMap — each carries an optional represented_type (&'static TypeInfo) plus a runtime-typed collection of fields/elements. Implement the same subtrait as their concrete counterpart. apply() / try_apply() copy overlapping fields. represented_type_info() returns the set TypeInfo (I2). Data flows in via insert(name, Box<dyn Reflect>) and out via field(name) -> Option<&dyn PartialReflect>. No unsafe; all downcasts deferred to refl-core.

GetPath / ParsedPath (refl-path). Parses "a.b[0].c" strings into Vec<OffsetAccess> (each wrapping an Access variant: Field(name), FieldIndex(usize), TupleIndex(usize), ListIndex(usize)). GetPath::reflect_path walks the ReflectRef tree, checking kind and type at each step (I7). Returns Result<&dyn PartialReflect, ReflectPathError>. No heap allocation for short cached ParsedPath; parsed form is reusable. Trust boundary: returns errors rather than panics on any type mismatch.

refl-serde (registry-keyed serde). ReflectSerializer wraps &dyn PartialReflect + &TypeRegistry; walks ReflectRef recursively using serde Serialize visitor; emits {type_path: value} envelope. ReflectDeserializer + TypedReflectDeserializer accept a registry reference; look up TypePath to find TypeRegistration; use ReflectDeserialize type-data to reconstruct a Box<dyn Reflect>. Produces dynamic values (I6); FromReflect converts to concrete. Trust boundary: untrusted bytes enter here; type-path lookup must be against a validated registry.

refl-func (function reflection). IntoFunction erases concrete fn pointers/closures into DynamicFunction { info: FunctionInfo, f: Box<dyn Fn(ArgList) -> Return> }. FunctionInfo carries arg TypeInfo + return TypeInfo. call(args: ArgList) -> Result<Return, FunctionError> type-checks each argument by TypeId before invoking f. Trust boundary: no unsafe in call path; type errors surface as FunctionError::ArgTypeMismatch.

6. Design Principles

P1. Derive-driven registration

#[derive(Reflect)] in refl-derive generates the complete impl surface: PartialReflect, Reflect, Struct/TupleStruct/Enum/Tuple, Typed, TypePath, GetTypeRegistration, and optionally FromReflect. Hand-written impl Reflect is reserved for types the derive grammar cannot express: trait objects, extern type, primitive intrinsics, and third-party types blocked by the orphan rule.

  • Tradeoff: compile time grows with number of derived types; mitigated by isolating refl-derive as a standalone proc-macro = true crate compiled once, not recompiled with the workspace on source changes.
  • Operational implication: adding a field to a struct triggers re-derive, automatically updating StructInfo::fields — no manual sync required. Removing a field removes it from registry automatically.
  • Attribute surface:
    • #[reflect(ignore)] — field excluded from Struct::field*, iter_fields, serde, path traversal.
    • #[reflect(default)] — supplies Default::default() for ignored fields in FromReflect construction.
    • #[reflect(Trait)] — generates impl FromType<Self> for ReflectTrait inserting trait-object TypeData.
    • #[reflect(skip_serializing)] — excludes from ReflectSerializer without removing from Struct reflection.
  • Generated impls anatomy: impl Typed uses OnceLock<TypeInfo> statics; impl GetTypeRegistration creates TypeRegistration and inserts any requested TypeData; impl Struct uses const index arrays derived at codegen time.
  • Violation example: hand-writing Struct::field_len returning 3 when the struct has 4 fields — iter_fields iterates only 3, path traversal returns Err(IndexOutOfBounds) for index 3, serde silently skips the fourth field.

P2. Partial vs full reflection

PartialReflect models an incomplete or dynamic value: it has reflection behavior (subtrait dispatch, reflect_ref/reflect_mut/reflect_owned, try_apply) but no concrete identity. Reflect: PartialReflect adds as_any()/as_any_mut() enabling TypeId-gated downcast to &T. Dynamic* proxies implement only PartialReflect. Concrete types implement both.

  • Two-trait motivation: DynamicStruct has no concrete type to downcast to; collapsing the split would require a fake TypeId on dynamic proxies.
  • ReflectOwned motivation: consuming APIs (into_partial_reflect, into_reflect) must transfer ownership; the owned counterpart avoids cloning when ownership is available.
  • Tradeoff: two-trait API surface increases learning curve; offset by PartialReflect being the "wide" API for structural operations and Reflect being the "narrow" API for concrete identity.
  • Function signatures: accept &dyn PartialReflect for structural reads/patches; require &dyn Reflect (or generic T: Reflect) when downcast or concrete identity is needed.
  • represented_type_info bridge: DynamicStruct::represented_type_info() returns Some(&'static TypeInfo) pointing at the concrete struct's info; enables registry lookup without implementing Reflect.
  • Violation example: collapsing into a single Reflect and assigning a fabricated TypeId to DynamicStruct — downcast_ref::<ConcreteStruct>() on a DynamicStruct would succeed with garbage data, violating I5 and producing UB.

P3. Dynamic proxy mirrors concrete

Every reflectable kind has a Dynamic* twin in refl-dynamic: DynamicStruct, DynamicTupleStruct, DynamicTuple, DynamicEnum, DynamicList, DynamicArray, DynamicMap. Each proxy's reflect_ref() returns the same ReflectRef arm as its concrete counterpart. Proxies carry an optional represented_type_info so the registry knows their intended target type.

  • Construction: proxies can be built field-by-field without the concrete type being known at the construction site — enabling deserialization pipelines and over-the-wire patching.
  • apply() semantics: a DynamicStruct applies to a concrete struct by matching fields by name; unmatched fields are skipped; this is the Phase 6 merge primitive.
  • FromReflect pipeline: DynamicStruct → FromReflect::from_reflect → concrete T; requires represented_type_info to be set so the registry can find the right FromReflect impl.
  • Violation example: a proxy that returns ReflectRef::List(self) but holds named fields (struct shape) — apply() attempts list-element copy, producing ApplyError::MismatchedKind for every field.

P4. TypePath is the stable serialization key

In-memory TypeId is a compiler-session-local hash; it changes across compilations, differs between programs, and must never appear in serialized data. TypePath is a stable string (crate::module::TypeName) derived from the type's logical location. It serves as: (a) TypeRegistry lookup key by name; (b) the "type" field in ReflectSerializer output; (c) the disambiguation key for short-path lookup.

  • Registry index: TypeRegistry maintains a HashMap<String, TypeId> path-to-id index alongside the primary HashMap<TypeId, TypeRegistration> id-to-registration store; both must be kept in sync on register and remove.
  • Short path: TypePath::short_type_path() (e.g., Vec<u32> instead of alloc::vec::Vec<u32>) used for human display; full path used for all serialization and storage to avoid ambiguity.
  • Generic type paths: alloc::vec::Vec<my_crate::Foo> — the full path recursively embeds element type paths; TypePath must be const-constructible or lazily initialized to handle generics.
  • Module refactor impact: moving a type from crate::foo::Bar to crate::baz::Bar changes its TypePath; serialized assets using the old path fail to deserialize; document migration procedure alongside any module rename.
  • Migration: registration alias pattern — registry.register_type_data::<NewType, ReflectTypePathAlias>(old_path) — enables loading old assets while using the new path for new writes.
  • Violation example: serializing TypeId as a u64 into a save file — the next compilation produces a different TypeId for the same type; file becomes unreadable on reload, violating I6.

P5. Apply semantics for partial updates

apply(target: &mut dyn PartialReflect, source: &dyn PartialReflect) copies fields/elements present in source into target by structural matching. Fields absent from source retain their current value. The target's concrete type and pointer identity are never changed. Incompatible kinds return ApplyError::MismatchedKind.

  • Error taxonomy: ApplyError::MismatchedKind { expected_kind, received_kind }, ApplyError::MissingField { field_name }, ApplyError::InvalidValue.
  • Use cases: scene patch loading (send partial DynamicStruct over network, apply to live component); config override (apply partial override on top of defaults).
  • Field matching: Struct-to-Struct matches by name; Tuple-to-Tuple matches by index; List-to-List element-wise; Map-to-Map key-wise.
  • try_apply vs apply: try_apply returns Result<(), ApplyError>; apply delegates to try_apply and panics on error (convenience for cases where kinds are known to match).
  • Violation example: an apply that mem::swaps the target with a clone of the source — pointer identity changes, violating I3; any &mut target_field held by a caller becomes dangling.

P6. The registry is the single source of dynamic capability

All name-keyed, path-keyed, and type-data-keyed operations accept an explicit &TypeRegistry (or &RwLock<TypeRegistry>) parameter. No global mutable statics hold reflection metadata. Covered operations: deserialize by type name, invoke ReflectDefault, construct via ReflectFromReflect, query ReflectSerialize/ReflectDeserialize, resolve DynamicFunction by type path.

  • Threading model:
    • Arc<RwLock<TypeRegistry>> for shared ownership across threads.
    • Read guard: registry.read() for all runtime queries (hot path); multiple concurrent readers.
    • Write guard: registry.write() for registration; expected only at startup; writer starvation is acceptable.
  • Testability: each test constructs its own TypeRegistry::new() with only needed types; failures cannot leak into other tests; #[cfg(test)] helpers provide pre-populated registries.
  • Short-path ambiguity handling:
    • get_with_short_type_path(short) → None + log when two types share the same short name.
    • get_with_type_path(full_path) is always unambiguous.
    • Ambiguity is a WARN-level diagnostic, not a panic.
  • Violation example: lazy_static! { static ref REGISTRY: Mutex<TypeRegistry> = ... } — test-parallel runs share registrations; registration from test A leaks into test B; order-dependent pass/fail.

P7. Round-trip fidelity

For any registered type T with FromReflect impl:

let reflected = t.as_partial_reflect();
let reconstructed = T::from_reflect(reflected).unwrap();
assert!(t.reflect_partial_eq(reconstructed.as_partial_reflect()) == Some(true));

The serde extension: ReflectDeserializer::deserialize(ReflectSerializer::serialize(t)) produces a DynamicStruct (or appropriate proxy), and FromReflect on that proxy reconstructs t (I6).

  • #[reflect(ignore)] fields break the round-trip unless #[reflect(default)] is also set — the reconstruct falls back to the field's default.
  • reflect_partial_eq semantics: element-wise structural equality; None = type does not support equality comparison; Some(false) = structurally unequal; Some(true) = equal.
  • reflect_clone shortcut: reflect_clone(t) = Reflect::from_reflect(t.as_partial_reflect()) under the hood — same round-trip guarantee, packaged as a clone primitive in refl-from.
  • Dynamic proxy round-trip: DynamicStruct ↔ from_reflect is the canonical deserialization pipeline (Phase 13); the fidelity guarantee holds as long as represented_type_info is set correctly before from_reflect is called.
  • FromReflect return type: Option<Self> not Result — None means a field was missing or of wrong kind; callers must handle None explicitly and log the failing type path for diagnostics.
  • Violation example: ignoring a non-Default field without #[reflect(default)] — from_reflect returns None; the caller may silently skip reconstruction, losing data rather than surfacing a clear error.

P8. Soundness is non-negotiable

No public API surface in refl-core, refl-info, refl-dynamic, refl-registry, or refl-path may produce a reference of the wrong type or lifetime. All downcasts use TypeId::of::<T>()-gated pointer casts (via std::any::Any). Transmutes are forbidden in the public API layer.

  • unsafe scope: permitted only in blanket impl Reflect bodies (for as_any) and in DynamicList/DynamicMap internal storage if raw-pointer optimization is used; each unsafe block has a // SAFETY: comment explaining the invariant being relied upon.
  • Miri requirement: cargo miri test -p refl-core -p refl-dynamic must pass on every PR; Miri detects use-after-free, type-confusion, and lifetime violations that the borrow checker cannot.
  • Fuzz requirement: cargo fuzz run fuzz_downcast (Phase 14) exercises every downcast_ref call path with wrong-type inputs; asserts None return in all cases.
  • Soundness review: Phase 14 includes a dedicated audit of every unsafe block; any unsound pattern is a P0 blocker.
  • Violation example: forging &'static dyn Reflect from a stack value via std::mem::transmute — produces use-after-free when the stack frame is popped; Miri reports this as UB immediately.

P9. Type checking at every access

Path traversal (refl-path), Struct::field(name), Struct::field_at(i), Enum::field(name), List::get(i), and Map::get(key) validate kind and key before returning. No access returns a reference to a mistyped slot.

  • ReflectPathError variants: InvalidAccess { offset, actual_kind, expected_kind }, MissingField { name }, IndexOutOfBounds { index, len }, WrongType { expected_type_path, actual_type_path }.
  • ParsedPath amortization: parse once into Vec<OffsetAccess>, traverse many; OffsetAccess caches type_path of the type at that offset for O(1) type checks on repeat traversals without re-parsing.
  • Lazy vs eager validation: ParsedPath::parse(str) validates syntax eagerly; type checks (kind and field name) are deferred until traversal against a concrete value, since the path is type-agnostic.
  • Hot-path optimization: reflect_path::<T> (typed variant) checks TypeId at the final access; reflect_path_unchecked is unsafe and skips the final TypeId check — for benchmarks only, not exposed in public API.
  • Violation example: skipping variant_type() check before calling Enum::field_at(0) on a Unit variant — field_at(0) returns None in correct impl, but a naive impl returning Some referencing out-of-bounds storage is memory-unsafe.

P10. No reflection without registration cost visibility

Every function that requires a TypeRegistration takes &TypeRegistry and returns Option<_> or Result<_, ReflectError> on missing registration. No implicit fallback. No panic on unregistered type.

  • Registration must be explicit: TypeRegistry::register::<T>() or app.register_type::<T>() in application wrappers. Unregistered types produce None / Err, not silent no-ops.
  • Diagnostic logging:
    • TypeRegistry::get_with_type_path returning None → tracing::warn!("unregistered type: {path}") at the call site.
    • Startup audit: TypeRegistry::iter_type_registrations().count() logged at DEBUG level to confirm expected registration count.
  • Registration manifest: treat register::<T>() calls as an explicit manifest; CI test loads a serialized asset file and confirms every type path in it is registered; fail on missing type.
  • TypeData registration sub-cost: each register_type_data::<T, D>() call is also explicit; omitting ReflectSerialize means that type cannot be serde-serialized through the registry — the error appears at serde time, not at registration.
  • Violation example: silently returning Default::default() when ReflectDefault TypeData is absent — caller cannot distinguish "default value" from "unregistered type"; data integrity guarantee collapses; missing-type bugs surface only on save-load roundtrip, not at startup.

P11. TypeId Stability & Uniqueness

std::any::TypeId is the runtime type key every downcast, registry lookup, and TypeData retrieval is gated on (ADR-07). Within a single compiled binary, TypeId::of::<T>() is a stable, one-to-one identifier: every distinct concrete T maps to exactly one TypeId, and no two distinct types alias the same TypeId. The registry's TypeId → TypeRegistration map (the other half of I1's bijection) is only sound if this holds.

  • Tradeoff: TypeId is a compiler-session-local opaque hash (P4) — collision-free identity within a build, at the cost of being meaningless across builds or processes; that instability is exactly why TypePath exists as the serialized key instead.
  • Operational implication: any hand-written Reflect impl that fabricates or forwards a TypeId (rather than deriving it from Self) breaks every downcast_ref call site that trusts TypeId::of::<T>(); this is the mechanism I5's soundness guarantee depends on.
  • Registry dependency: TypeRegistry::register::<T>() inserts under TypeId::of::<T>(); safe Rust cannot alias two distinct types onto one TypeId, but a transmute-based or FFI-boundary shortcut could forge one — forbidden outright by P8.
  • Detection surface: refl-registry's registration audit (iter_type_registrations()) enumerates every inserted TypeId; a debug-build assertion on register rejects a second registration attempt for an already-present TypeId under a different TypePath.
  • Violation example: a #[repr(transparent)] newtype whose hand-written Reflect::as_any() forwards to the inner field's as_any() instead of self — TypeId::of::<Wrapper>() (what the registry believes it registered) no longer matches the TypeId actually returned by as_any(), so downcast_ref::<Wrapper>() fails silently (None) even though the registry reports Wrapper as registered and resolvable.

P12. Zero-Alloc Reflection Fast Path

Field access (Struct::field/field_at), positional access (TupleStruct/Tuple), path traversal (refl-path::GetPath), and list/map indexing (List::get/Map::get) return borrowed references (&dyn PartialReflect) and perform zero heap allocation per call. Only dynamic construction — building a DynamicStruct/DynamicEnum/DynamicList field-by-field, or reflect_owned()/reflect_clone() — allocates, because those paths produce new owned values rather than borrowing existing ones.

  • Tradeoff: keeping the read path alloc-free means Dynamic* proxies pay the allocation cost at construction (Box<dyn PartialReflect> per field, per P3) instead of amortizing it away; deliberate, since proxies are construction/deserialization artifacts (ADR-11), not the hot path.
  • Operational implication: reflect_ref()/reflect_mut() on concrete types (Phase 1) are proven zero-alloc in that phase's Acceptance Criteria (#[global_allocator] allocation counter asserts 0 heap allocations); any future blanket impl that boxes on read instead of borrowing is a hot-path regression, not a style nit.
  • Path traversal cost: ParsedPath traversal (Phase 12) walks pre-parsed OffsetAccess entries with no allocation per hop; only the initial ParsedPath::parse(&str) call allocates, once — the basis for P9's "parse once, traverse many" guidance.
  • Boundary case: reflect_owned() and T::from_reflect/reflect_clone (P7) are explicitly exempt — they exist to produce a new owned value and cannot avoid at least one allocation; the fast-path guarantee covers borrowing reads (field, get, path), not construction or cloning.
  • Violation example: an Enum::field(name) implementation that clones the field value into a boxed temporary before returning Some(&boxed_value) — the reference dangles the moment the temporary drops, and the extra allocation defeats the reason callers use borrowed field access over a full reflect_clone inside hot loops.

Invariant Debugging Methodology

I1 — TypeId ↔ TypePath bijection

  • Enable RUST_LOG=refl_registry=debug; TypeRegistry::register logs path + TypeId hex on insert and on collision.
  • Diagnostic: TypeRegistry::iter_type_registrations() returns a sorted iterator; dump to a manifest file in CI; diff against the previous-commit manifest to detect accidental renames.
  • Common root cause: two crates define a type with the same short name in modules with different paths; full-path collision is rarer but possible with generics like Vec<MyType> across crates.

I2 — Dynamic proxy structural consistency

  • DynamicStruct::set_represented_type(info) validates field_len match when debug_assertions is on; production builds skip the check for throughput.
  • When apply() panics mid-way, the target is partially updated; the opt-in ApplyGuard::new(target, source) wrapper clones target before mutating, rolling back on Err.
  • Debugging partial-apply corruption: compare target.reflect_ref() before and after; mismatched field count shows as missing None from field_at(i).

I3 — apply() pointer stability

  • Test harness: let ptr = &raw const *target as usize; target.apply(&source); assert_eq!(ptr, &raw const *target as usize).
  • Third-party PartialReflect impls that violate I3 are unsound; Phase 14 soundness review checks every impl in the workspace.
  • Common violation: apply on a DynamicList replacing the inner Vec allocation — pointer changes; fix by clear + extend in-place.

I4 — FromReflect round-trip

  • cargo test -p refl-from -- --include-ignored round_trip_all_types: failures print the diverging field path and the before/after Debug representations.
  • proptest generates random field values using Arbitrary impls; shrinking finds the minimal failing field combination.
  • Ignored fields without #[reflect(default)] produce from_reflect → None; the test harness should distinguish None (missing field) from Some(diverged_value).

I5 — Downcast soundness

  • cargo miri test -p refl-core: any UB in the downcast path (wrong-type pointer alias) manifests as a Miri error; run on every PR.
  • Fuzz harness: fuzz_downcast calls downcast_ref::<T> on every concrete type in the registry; asserts None for all mismatched T; asserts Some for the correct T.
  • AddressSanitizer (RUSTFLAGS=-Z sanitizer=address cargo test) catches use-after-free in as_any_mut if lifetime annotation is wrong.

I6 — Serde round-trip

  • cargo fuzz run fuzz_serde_roundtrip with seed corpus: empty structs, deeply nested enums, unit variants, types with #[reflect(ignore)] fields, generic types Vec<T>, Option<T>.
  • CI runs 60-second fuzz on every PR touching refl-serde; failures are minimized via cargo fuzz tmin.
  • Integration test: round-trip through both JSON (serde_json) and RON (ron) backends; assert reflect_partial_eq on result.

I7 — Path access type safety

  • cargo fuzz run fuzz_path_parser inputs arbitrary byte strings as paths; all paths return either Ok(value) or Err(ReflectPathError), never panics or UB.
  • Test matrix: cross-product of { Field("x"), FieldIndex(0), TupleIndex(0), ListIndex(0) } × { Struct, TupleStruct, Tuple, List, Array, Map, Enum(Struct variant), Enum(Unit variant), Opaque } — 40 cells; each asserts correct Ok or Err variant.
  • Common edge case: Field("x") on Opaque — must return Err(InvalidAccess), not None; distinguish missing-field from wrong-kind.

I8 — OnceLock static type_info stability

  • loom test: 4 threads each call <MyStruct as Typed>::type_info() in a loop; assert std::ptr::eq on every returned reference.
  • Failure mode: replacing OnceLock with static mut introduces a data race; loom's scheduler explores all interleavings and reports the race.
  • ThreadSanitizer (RUSTFLAGS=-Z sanitizer=thread) as an alternative to loom for larger thread counts.

I9 — Enum active-variant guard

  • Test: construct MyEnum::VariantA { x: 1 }, call DynamicEnum::set_variant("VariantB", DynamicVariant::Unit), call field("x") — assert None.
  • Full matrix: for each variant kind (Struct, Tuple, Unit) × each access method (field by name, field by index, field_len) — assert that accessing non-active-variant fields returns None or 0.
  • Failure mode: if DynamicEnum does not clear fields on set_variant, stale field data from the old variant leaks into the new; wrong-type field returned.

I10 — TypeData FromType contract

  • The generic bound D: FromType<T> on register_type_data::<T, D> is enforced at compile time; mismatched type produces a type-error, not a runtime bug.
  • Audit script: grep -r 'register_type_data' --include='*.rs' | grep -v test — every production call site should pair the correct T and D; review checklist in Phase 9 + Phase 14 soundness audit.
  • Edge case: calling register_type_data twice with the same D for the same T on the same registry — second call overwrites the first (last-write-wins); document this in API docs; test that overwrite is observable.
  • Related invariant: I10 is the runtime counterpart of this compile-time guarantee; together they ensure the TypeData retrieved is always the one inserted for the correct T.

8.3 ReflectRef State Machine

A value v: &dyn PartialReflect is classified into exactly one variant of ReflectRef. The variant is determined at the concrete type level by the impl, never at call time.

State: concrete type T
       │
       ├─ struct {named fields}          → ReflectRef::Struct(&dyn Struct)
       ├─ struct (T0, T1, ..)            → ReflectRef::TupleStruct(&dyn TupleStruct)
       ├─ (T0, T1, ..)                   → ReflectRef::Tuple(&dyn Tuple)
       ├─ enum { V0(..), V1{..}, V2 }    → ReflectRef::Enum(&dyn Enum)
       ├─ Vec<T> / SmallVec / Deque      → ReflectRef::List(&dyn List)
       ├─ [T; N]                         → ReflectRef::Array(&dyn Array)
       ├─ HashMap<K,V> / BTreeMap<K,V>   → ReflectRef::Map(&dyn Map)
       ├─ HashSet<T> / BTreeSet<T>       → ReflectRef::Set(&dyn Set)
       └─ i32/bool/String/f64/...        → ReflectRef::Opaque(&dyn PartialReflect)

Transition rules:

  • Dynamic* proxies return the same variant their represented_type reports when set; fall back to the proxy's own kind when unset.
  • A DynamicStruct with no represented_type set returns ReflectRef::Struct(self).
  • Changing represented_type does not alter the values stored; callers must validate field names/types match (I2).

8.4 apply / try_apply Semantics

apply(src: &dyn PartialReflect) — in-place merge. Source must be same kind as target. Defined recursively:

Target kind Rule
Struct For each field name present in src, set matching target field by name. Ignore src fields absent in target.
TupleStruct / Tuple For each positional index in src, set target field at same index. Panic if src.field_len() != target.field_len().
Enum If variant name differs: call set_variant on target (replaces entire variant payload). Then apply fields within the new active variant.
List Clear target, push-clone every element of src.
Array Element-wise apply at matching index; lengths must match.
Map For each key in src, insert (clone key) → apply value.
Set Clear target, insert-clone every element of src.
Opaque Call set(src.clone_value()) — full replacement.

try_apply returns Result<(), ApplyError> instead of panicking. ApplyError variants:

  • MismatchedKinds { expected, got }
  • MismatchedVariant (enum variant name mismatch when non-enum target)
  • InvalidDowncast (field clone failed due to type mismatch)
  • InvalidField { field_name } (src field absent in target)

Invariant I3: apply never replaces the concrete type of target; it only mutates field values in place.

8.7 Property Path Grammar (EBNF)

path         ::= segment ( '.' segment | '[' idx ']' | '#' digit+ )*
segment      ::= identifier                    (* named field *)
identifier   ::= [a-zA-Z_] [a-zA-Z0-9_]*
idx          ::= digit+                        (* list/array index *)
digit        ::= [0-9]
'#' digit+                                     (* tuple index shorthand *)

Access variants derived from above:
  Field(name)       ← segment
  FieldIndex(n)     ← .segment resolved to index at parse time (optional)
  ListIndex(n)      ← [n]
  TupleIndex(n)     ← #n

Parse rules:

  • Leading . is optional at path start.
  • [] with non-numeric content is a parse error → ReflectPathError::InvalidAccess.
  • Consecutive # or [] without a separating . is legal: a[0][1] = nested list.

ParsedPath stores Vec<OffsetAccess> where OffsetAccess = { access: Access, offset: usize } (byte offset into original string for error reporting).

8.8 Path Traversal: Type-Check State Machine

Input: &dyn PartialReflect, Vec<OffsetAccess>

for each access in path:
  match (reflect_ref(current), access):
    (Struct(s),       Field(name))       → current = s.field(name) or Err(NoSuchField)
    (Struct(s),       FieldIndex(i))     → current = s.field_at(i)  or Err(OutOfBounds)
    (TupleStruct(ts), TupleIndex(i))     → current = ts.field_at(i) or Err(OutOfBounds)
    (Tuple(t),        TupleIndex(i))     → current = t.field_at(i)  or Err(OutOfBounds)
    (Enum(e),         Field(name))       → current = e.field(name)  or Err(NoSuchField)  (I9: active variant only)
    (Enum(e),         TupleIndex(i))     → current = e.field_at(i)  or Err(OutOfBounds)
    (List(l),         ListIndex(i))      → current = l.get(i)       or Err(OutOfBounds)
    (Array(a),        ListIndex(i))      → current = a.get(i)       or Err(OutOfBounds)
    (Map(m),          Field(key))        → current = m.get_by_key(key) or Err(NoSuchKey)  (**)
    _                                    → Err(ExpectedKind { expected, got })

(**) Map keyed by field-name string uses ReflectHash + ReflectPartialEq on the reflected key type.

Return types: GetPath::reflect_path(path) -> Result<&dyn PartialReflect, ReflectPathError>. Typed variant path::<T>(path) -> Result<&T, ReflectPathError> adds a final downcast_ref::<T>() check (I5, I7).

8.10 Serialization Wire Format

ReflectSerializer emits a self-describing format where the type path is the outer key:

JSON wire shape — struct:
  { "my_crate::module::Foo": { "x": 1, "y": "hello" } }

JSON wire shape — enum:
  { "my_crate::module::Color": { "Rgb": { "r": 255, "g": 0, "b": 0 } } }
  { "my_crate::module::Color": { "Unit": {} } }

JSON wire shape — list:
  { "std::vec::Vec<i32>": [1, 2, 3] }

JSON wire shape — tuple struct:
  { "my_crate::Pair": [10, 20] }

JSON wire shape — opaque primitive:
  { "i32": 42 }

TypedReflectDeserializer receives an outer type_path string, looks up TypeRegistration, reads ReflectDeserialize type-data, deserializes the inner value into a Box<dyn PartialReflect>. Callers then call FromReflect to get concrete T (I6).

Failure modes during deserialization:

  • UnregisteredType(type_path) — registry has no entry for that path.
  • MissingTypeData(type_path, "ReflectDeserialize") — type registered but data not inserted.
  • InvalidValue { message } — serde error from the inner deserializer.
  • AmbiguousShortPath(short) — short path matches multiple registered types.

8.12 Worked Example: Full Round-Trip

// --- define ---
#[derive(Reflect)]
struct Pos { x: f32, y: f32 }

// --- register ---
registry.register::<Pos>();
registry.register_type_data::<Pos, ReflectSerialize>();
registry.register_type_data::<Pos, ReflectDeserialize>();

// --- reflect ---
let p = Pos { x: 1.0, y: 2.0 };
let r: &dyn Reflect = &p;
// r.reflect_ref() == ReflectRef::Struct(s)
// s.field("x").unwrap() -> &dyn PartialReflect (opaque f32, value 1.0)

// --- dynamic build ---
let mut d = DynamicStruct::default();
d.set_represented_type(Pos::type_info());
d.insert("x", 3.0_f32);
d.insert("y", 4.0_f32);
let p2: Pos = Pos::from_reflect(&d).unwrap();   // I4
// p2 == Pos { x: 3.0, y: 4.0 }

// --- path access ---
let parsed = ParsedPath::parse("x").unwrap();
let xv: &f32 = parsed.path::<f32>(&p).unwrap(); // I7

// --- serde ---
let json = ReflectSerializer::new(&p, &registry).to_json();
// {"my_crate::Pos": {"x":1.0,"y":2.0}}
let boxed: Box<dyn PartialReflect> =
    TypedReflectDeserializer::new("my_crate::Pos", &registry).from_json(&json)?;
let p3: Pos = Pos::from_reflect(boxed.as_ref()).unwrap(); // I6

Named struct codegen (struct_derive.rs) Steps, each emitting a TokenStream2 block:

  1. Collect non-ignored fields → active_fields: Vec<(Ident, Type, FieldAttrs)>.

  6. Emit impl Reflect for T — as_any()/as_any_mut() via cast; reflect_partial_eq().

  • Empty DynamicStruct (no fields) applied to a non-empty concrete struct: no fields copied, target unchanged, not an error.
  • Source is a concrete Struct (not Dynamic*): struct_apply works on &dyn Struct since both concrete and dynamic implement it — apply is kind-based, not type-based.
  • DynamicTuple applied to concrete tuple (i32, bool): positional match by index; if lengths differ, zip stops at the shorter one, excess target indices unchanged.
  • represented_type set to a type whose field layout differs from the actual fields vec (invariant I2): try_apply validates field count against TypeInfo; mismatch → ApplyError::Internal.
  • set() on a DynamicStruct: allowed, replaces inner storage; represented_type must be reset separately if the replacement has a different structure.

7.6 Pitfalls

  • Hashing dynamic keys: dyn PartialReflect has no Hash; map proxy walks pairs linearly — this is intentional but must be documented; using DynamicMap as a real HashMap substitute fails silently on large inputs without O(n) documentation.
  • Array const-generic Typed impl: OnceLock keyed by TypeId::of::<[T;N]>() — two different N values for the same T must produce distinct TypeInfo; missing const parameter in the OnceLock path causes aliased static info.
  • Vec<Box<dyn Reflect>> item cloning in apply: applying a DynamicList into Vec<T> requires downcast_ref::<T> on each element; if T is not the element's actual concrete type, apply silently skips or panics depending on implementation — must return ApplyError not panic.
  • BTreeMap iteration order vs HashMap: iter() contract does not guarantee order for Map trait; callers relying on order must use a concrete BTreeMap or DynamicMap; document explicitly.
  • Set containment without PartialEq on dyn: contains for DynamicMap / Set uses reflect_partial_eq fallback; if the concrete type lacks PartialEq, containment silently returns false.

7.7 Performance Concerns

  • DynamicMap::get is O(n) linear scan — acceptable for dynamic-proxy use (scene editor, scripting) but not for hot-path game logic; document ceiling of n ≤ 128 for interactive use.
  • Vec blanket impl push boxes every element — one heap allocation per pushed item; batch construction via DynamicList::from_iter amortizes.
  • apply for large Vec triggers per-element downcast_ref — no branch-prediction benefit; keep apply off hot paths.
  • HashMap<K,V> blanket get: requires cloning key into Box<dyn PR> then downcasting — two heap ops per lookup; prefer typed API when key type is known.
  • [T; N] blanket Typed impl with const generics: each distinct N instantiates a separate monomorphization + OnceLock; binary size grows O(distinct N values).

7.8 Edge Cases

  • Empty Vec / HashMap / HashSet — len() == 0, iter() yields nothing, apply is no-op; verify no panic.
  • Vec<Vec<i32>> nested — get(i) returns &dyn PartialReflect which is itself a List; recursive reflect_ref must work.
  • [T; 0] zero-length array — ArrayInfo::capacity == 0; iter() empty; apply with mismatched-size DynamicArray returns error not panic.
  • HashMap with key f32/f64 — Hash + Eq not implemented for floats; blanket impl excludes them; reflect returns ReflectRef::Opaque; must not silently compile via auto-deref.
  • DynamicMap insert duplicate key — second insert replaces first (same semantics as HashMap); test explicitly.
  • apply source is concrete Vec, target is DynamicList — valid; DynamicList::apply from a List source must iterate source via List::iter.

7.9 Failure Analysis

  • Wrong element type in apply: downcast_ref fails → ApplyError::MismatchedTypes; blast radius = single element skip or abort; recovery = caller checks ApplyError variant.
  • OnceLock poisoning: type_info() closure panics → OnceLock poisoned; subsequent calls on same type always panic; detection: unwrap on poisoned lock surfaces in test output; recovery = fix closure, rebuild.
  • DynamicMap memory growth: unbounded insert without remove → unbounded Vec<(Box,Box)> growth; detection: heap profiler; containment: bound capacity in proxy constructor.

  • Instrumentation: tracing::trace! on apply entry with represented_type path and element count.

Wire / Serialized Format Compatibility

  • Serialized format: {"type_path": "<TypePath>", "value": <serde-value>} envelope; keyed by stable TypePath (P4).
  • Forward compatibility: unknown fields in a struct's serialized form are ignored by ReflectDeserializer (configurable: strict mode rejects unknowns).
  • Backward compatibility: added fields with #[reflect(default)] deserialize to default when absent from older serialized data.
  • TypePath stability: renaming a type breaks deserialization of stored bytes; migration required (refl-cli migrate --from-path --to-path).
  • ParsedPath strings are stable as long as field names and variant names are stable; rename = breaking change for stored paths.
  • Enum variant rename: stored bytes and stored path expressions both break; migration required.

  • Serialized data written by version N is readable by version N+1 under backward-compatible schema changes (additive fields with defaults).
  • Serialized data written by version N+1 with new fields is readable by version N under forward-compatible mode (unknown fields ignored).
  • For breaking changes (rename, removal): all instances must be on new version before old serialized data is discarded; blue-green deployment recommended.

Deprecation Policy

  • Deprecated items marked #[deprecated(since = "X.Y", note = "...")] in source.
  • Deprecated items remain functional for one major version cycle.
  • Removal announced in CHANGELOG; minimum 2 minor releases notice before removal.
  • Deprecated TypeData types: remain registered but emit tracing::warn! on access after deprecation version.
  • Deprecated derive attributes: proc-macro emits #[deprecated] re-export or compile warning; removed after one major cycle.

Tie to Sections 8 and 11

  • Section 8 (Domain Model) defines the canonical TypePath format: crate::module::TypeName<Args>. This string is the wire key; all compatibility guarantees above apply to it.
  • Section 11 (Core Types / type signatures) defines NamedField, VariantInfo, TypeRegistration shapes. Structural changes to these (field additions) follow the minor-version rule above; removals require major bump.
  • DynamicStruct serialized form mirrors StructInfo field order; any reordering is a wire-breaking change (major version).
  • ParsedPath syntax (field.name, [index], #tuple_index) is stable after 1.0; new Access forms (e.g., {key} for Map) are additive (minor version).

Scalability Analysis

Dominant Scaling Pressure

The system's scaling pressure is registry size × type-data cardinality: each registered type carries a TypeRegistration holding a TypeInfo (static, cheap) plus a HashMap<TypeId, Box<dyn TypeData>> (per-registration heap). With N types and D type-data variants, peak memory is O(N × D). At N = 10,000 types and D = 8 (FromReflect, Default, Serialize, Deserialize, 4 custom), TypeData maps dominate RSS.

Secondary pressure: path traversal depth × reflect_ref call chain. A 20-hop ParsedPath performs 20 reflect_ref + kind-check + downcast sequences; cost grows linearly with depth.

Horizontal / Vertical Scaling

  • TypeRegistry is process-local; horizontal scaling means independent registries per process (no shared mutable global per P6).
  • Registry can be wrapped in Arc<RwLock<TypeRegistry>> for multi-threaded read; writes are startup-time only in production use.
  • No network or distributed coordination; scaling to multiple machines means per-process registry construction from the same codebase.
  • Vertical: adding CPU cores improves parallel reflect_ref traversal throughput (read-only path is lock-free after startup).

Metadata Fragmentation

  • Each #[derive(Reflect)] type emits one TypeRegistration. Large codebases with many generic monomorphisations (e.g., Vec<T> for 50 T) multiply registration count; each monomorphisation is a distinct TypeId + TypePath.
  • Mitigation: #[reflect(ignore)] on fields of unneeded generic instantiations; or implement GetTypeRegistration manually to share TypeData across monomorphisations where semantically valid.
  • StructInfo stores fields as Box<[NamedField]> (not Vec) to avoid over-allocation; EnumInfo stores variants similarly.

Coordination Overhead

  • No synchronization on the hot reflect_ref / field_at / path_get path: all read-only after startup.
  • TypeRegistry::get acquires a RwLock read guard: ~5–10 ns uncontended; measure under load.
  • refl-func DynamicFunction::call: no registry access; purely stack-local ArgList dispatch.
  • Serde serialization: read-only registry access for type_path lookup; no write lock.
  • Single write-lock scenario: register_type_data after startup (rare); document as not safe for hot-path.

Mental Models & First Principles

The compressed insights an expert holds before writing a line. Each names what it predicts, the bug class you write without it, and the section where this blueprint applies it.

MM1 — Reflection is a second, opt-in type system layered over the compiler's erased one. After monomorphization the compiler has discarded field names, variant shapes, and most structure; Typed/TypeInfo re-materialize exactly the subset you opt into via #[derive(Reflect)]. Predicts: a value that was never derived is structurally invisible at runtime — nothing can "discover" it. Bug class without it: calling field-by-name access on a type that was never reflected and expecting it to work. Applied in: §8 Domain Model, Phase 2, Phase 5.

MM2 — TypeId is identity within one binary; TypePath is identity across binaries. std::any::TypeId is an opaque per-compilation token — stable in-process, meaningless across builds or machines. Anything persisted (serde, on-disk, wire) must key on the stable TypePath string. Predicts: a TypeId-keyed blob silently fails to resolve after a recompile. Bug class: serializing a TypeId and reading it back in a different build. Applied in: ADR-07, I1, Phase 2, Phase 13.

MM3 — Reflect is a tower of trait objects; every layer must stay object-safe or the whole tower collapses. PartialReflect → Reflect → Struct/TupleStruct/Tuple/List/Map/Enum are all dyn-compatible. A single generic method, or a Self-by-value method, anywhere in the tower makes dyn Reflect impossible — and the error surfaces far from the cause. Predicts: object-safety breakage is non-local. Bug class: adding fn clone(&self) -> Self to a reflected trait. Applied in: Phase 1, Phase 3, Phase 8, §6 Design Principles.

MM4 — Static TypeInfo is built once, leaked for 'static, and OnceLock is its clock. Each type's TypeInfo is lazily constructed on first type_info() and stored in a per-type OnceLock, yielding &'static TypeInfo. Predicts: warm type_info() is a ≤2 ns atomic load (§4.1); the only cost is the one-time build. Bug class: recomputing TypeInfo per call (allocation on a hot path) or racing initialization without once-semantics. Applied in: ADR-08, I8, Phase 2.

MM5 — Dynamic proxies are type-compatible stand-ins, never type-identical to the concrete value. A DynamicStruct carries a TypePath and named fields but is not T; you cannot downcast it to T. To get a real T you must call FromReflect. Predicts: as_any().downcast::<T>() on a proxy returns None. Bug class: downcasting a proxy and panicking instead of from_reflect-ing it. Applied in: Phase 6, Phase 11, I5.

MM6 — apply() is a total structural merge keyed on names/indices. Every field either applies or yields ApplyError; there is no silent drop (failure budget §4.2). It merges field-wise, it does not wholesale-replace, and it does not default missing fields. Predicts: shape mismatches are diagnosable, never lossy. Bug class: assuming apply overwrites the whole value or fills gaps with defaults. Applied in: Phase 6, I3, §4.2.

MM7 — A property path is a compiled, type-checked access sequence, not repeated string indexing. ParsedPath is parsed once into Vec<OffsetAccess>; each hop is checked against the current node's TypeInfo. Predicts: parse cost (≤1 µs) is paid once and the cached path traverses in ≤200 ns (3 hops). Bug class: re-parsing the path string on every access, turning O(1) traversal into O(len) parsing per call. Applied in: ADR-12, Phase 12, §4.1.

MM8 — Reflection buys operation-on-unknown-types for a bounded, local cost — and types you never reflect pay nothing. Each reflect_ref() is one vtable dispatch (≤5 ns); enabling reflection on a type adds ≤5 KB binary (§4.1) and per-call dispatch, never a global slowdown. Predicts: the design is "zero-cost at unuse." Bug class: reaching for reflection inside a tight numeric loop where monomorphized code is orders of magnitude faster. Applied in: §2.6, ADR-01, Phase 1, §4.1.

bevy_reflect is the direct design model: an opt-in, derive-driven reflection layer for Rust with a TypeRegistry, TypeData capability objects, apply, and reflection-driven serde. Its decision that differs is tighter coupling to an ECS/game-engine runtime; that wins where reflection exists primarily to patch components and drive scene serialization, which is exactly the niche it was built for.

Java java.lang.reflect bakes universal metadata into every .class and exposes it through the VM. The decision that differs is universality with no opt-in plus first-class method invocation and annotations. That wins when you control the runtime and can afford always-on metadata — enabling frameworks (Spring, Jackson) that reflect over arbitrary user types with zero cooperation from those types.

C# System.Reflection reads CLR metadata tables and added PropertyInfo.GetValue/MethodInfo.Invoke — the direct ancestor of the GetPath + DynamicFunction model here. It wins where attribute-driven frameworks and runtime code generation (System.Reflection.Emit) are needed, which a no-VM Rust design cannot match.

Go reflect decomposes values into Type/Value/Kind, the template for this design's TypeInfo/ReflectRef split. Its differing decision is universal reflection on every value with no derive, paid for by allocation-heavy Value boxing. That wins for Go's encoding/json and ORM ecosystems where simplicity beats per-call cost.

RTTR (C++) is the closest C++ analog: opt-in registration macros build a runtime type database, much like TypeRegistry. Its differing decision is manual RTTR_REGISTRATION blocks rather than a compiler-driven derive. That wins in C++ where no stable proc-macro equivalent exists and explicit registration is the idiomatic path.

Every number is derived from the §4.1 System Constraints table with the formula shown.

C1 — Registry memory for N types. §4.1: ≤2 KB per registered type; ≤4 MB total at N=1000 including all TypeData. Formula: mem ≈ N × (2 KB + Σ type_data_size). At N=1000 → ≤4 MB; fits L3 on commodity hardware.

C2 — Hot-path type_info() throughput. §4.1: ≤2 ns warm (OnceLock initialized). Formula: 1 / 2 ns = 5×10⁸/s/core. Type introspection is effectively free once warm.

C3 — Dispatch budget walking a struct. §4.1: reflect_ref() ≤5 ns. A 10-field walk = 10 × 5 ns = 50 ns of pure dispatch. Formula: fields × 5 ns. This is the floor under the ≤500 ns apply budget (C4).

C4 — apply() on a 10-field struct. §4.1: ≤500 ns p50. Formula: 1 / 500 ns = 2×10⁶ applies/s/core. The 10× gap over C3 covers per-field name lookup + try_apply.

C5 — Path parse-vs-traverse break-even. §4.1: parse 10-element path ≤1 µs (once); traverse 3 hops ≤200 ns. Formula: break_even = parse_cost / traverse_cost = 1 µs / 200 ns = 5. Caching ParsedPath pays off from the 2nd access; never re-parse per call (MM7).

C6 — Serde round-trip throughput. §4.1: 10-field struct round-trip ≤10 µs. Formula: 1 / 10 µs = 10⁵ round-trips/s/core. Reflection-driven serde is ~100× slower than monomorphized serde — expected, and the cost of schema-freedom.

C7 — Startup registration budget. §4.1: register 1000 types ≤50 ms; each register() write ≤2 µs p99. Formula: per_type = 50 ms / 1000 = 50 µs; only ≤2 µs is the locked write, so ~48 µs/type is TypeData/Default construction, not lock contention (C12).

C8 — DynamicStruct heap footprint. §4.1: ≤64 B fixed + per-field Box<dyn PartialReflect>. Formula: 64 B + fields × (16 B fat-ptr + sizeof(field_payload)). A 10-field proxy of 8-byte fields ≈ 64 + 10×24 = 304 B — cheap to build, but allocation-per-field (C-relevant to ADR-11).

C9 — Binary bloat per derive. §4.1: ≤5 KB per #[derive(Reflect)] (release, thin-LTO). Formula: derived_types × 5 KB. 200 reflected types → ≤1 MB added .text; this is the price of MM8's opt-in model.

C10 — Structural ceilings. §4.1: field index u16 → ≤65,535 fields/struct; variant index u16 → ≤65,535 variants/enum; path depth ≤256 hops (returns ReflectPathError::TooDeep). Hard caps, not perf targets.

C11 — Proc-macro compile cost. §4.1: ≤50 ms per 100 derived types (incremental). Formula: (derived/100) × 50 ms. 1000 derives → ≤500 ms incremental-compile delta from syn parse + codegen.

C12 — Concurrent read scaling. §4.3: read-only after startup; RwLock reads are shared. Formula: throughput ≈ cores × (1 / get_latency) while writers=0. With ≤50 ns p50 get, 8 cores → ~1.6×10⁸ lookups/s. Contention appears only if registration runs in steady state (see ADR-09 "rejected wins").

Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same goal — not parameter tweaks.

Alt-1 — Compile-time codegen only (no runtime metadata)

#[derive(Serialize, Deserialize)]  ->  concrete visitor impls
                                       (no TypeRegistry, no dyn Reflect)
value ──serialize──▶ format          (operations fixed at compile time)

The derive emits concrete per-type impls; there is no runtime type object, no registry, no dyn Reflect. Wins when the set of operations is known at compile time (serialize/deserialize to a fixed format) and maximum speed + minimal surface matter. Real system: serde + serde_derive. Rejected here because it cannot support open-ended, data-driven access — edit-by-path, inspect-an-unknown-value, scripting — which require a runtime type object to query (MM1, Phase 12, Phase 14).

Alt-2 — VM / managed-runtime universal metadata

toolchain bakes full metadata into every type  ->  reflection reads VM tables
(Java .class / .NET metadata)                        no opt-in, method invoke free

Every type carries complete metadata; reflection reads VM/CLR tables. Wins when you own the runtime and can afford always-on metadata, giving universal reflection plus method invocation and attributes for free. Real systems: Java java.lang.reflect, C# System.Reflection. Rejected here because Rust has no VM; baking universal metadata into every binary violates zero-cost-at-unuse (MM8) and bloats every artifact (C9).

Alt-3 — Single monolithic Reflect trait + central Value enum

trait Reflect { fn kind(&self) -> Kind; fn as_any(&self) -> &dyn Any; }
enum Value { Struct(..), List(..), Map(..), .. }   // callers match + downcast

One trait returns a kind enum; callers match and downcast. Wins for a small, fixed set of types where the subtrait tower is overkill — many config/interpreter systems use exactly this. Real systems: ad-hoc enum Value interpreters and config layers. Rejected here because it does not compose (each new container type edits the central enum) and loses the generality of structural apply and typed path traversal (MM5, MM6, Phase 7).

Alt-4 — Arena / columnar dynamic storage instead of boxed proxies

DynamicStruct { arena: Vec<u8>, fields: [(name, offset, type)] }
                          // vs Box<dyn PartialReflect> per field

Proxies store fields in a typed arena / offset table rather than a Box per field. Wins for bulk deserialization of millions of dynamic records where per-field allocation dominates (the ADR-11 "rejected wins" regime). Real systems: columnar engines (Arrow-style) and ECS component storage. Rejected here because it complicates ownership and the apply/proxy model, and proxies in this design are construction artifacts, not a hot path (ADR-11, C8).

Glossary

Alphabetical; every entry is implementation-relevant and operationally precise. Cross-references to invariants (I1–I10), principles (P1–P10), phases, and crates.

apply / try_apply Mutation primitive on PartialReflect.

  • Copies overlapping structure from a source &dyn PartialReflect into self.
  • Field matching: by name for Struct, by index for Tuple/TupleStruct, element-wise for List/Array.
  • try_apply → Result<(), ApplyError>; apply panics on mismatch.
  • Preserves the target's concrete type — never replaces the allocation (I3, P5).
  • Defined in refl-core/src/apply.rs; implemented by every Dynamic* proxy (Phase 6–8).

ApplyError Error enum returned by try_apply.

  • Variants: MismatchedKinds { from_kind, to_kind }, InvalidField { field_name }, InvalidVariant { variant_name }, ElementCountMismatch { expected, got }.
  • Never silently discards data; always identifies the mismatch site.

ArgInfo Per-argument metadata inside FunctionInfo: name: &'static str, TypePath, TypeId, positional index. Captured at IntoFunction conversion time; available for inspection before call().

ArgList Owned container of reflection-erased arguments for DynamicFunction::call().

  • Each Arg slot: owned (Box<dyn Reflect>), immutable borrow (&dyn Reflect), or mutable borrow (&mut dyn Reflect).
  • Consumed entirely by call(); not reusable after invocation.
  • Wrong arity or wrong TypeId at a slot position → FunctionError.

blanket impl A PartialReflect + Reflect implementation generated for a whole category of types (all integer primitives, tuples up to arity 12, arrays up to size 32) in refl-core/src/impls.rs using macro repetition. Ensures primitives report ReflectRef::Opaque and support reflect_partial_eq / downcast without derive.

custom attribute Arbitrary metadata attached to a NamedField or UnnamedField via #[reflect(attribute = expr)].

  • Stored as Vec<Box<dyn Any + Send + Sync>> keyed by TypeId in the field info struct.
  • Accessible at runtime through StructInfo::field()?.custom_attribute::<A>().
  • Pattern: embed editor metadata, validation hints, or UI labels without touching core reflection logic.

derive macro / proc-macro The #[derive(Reflect)] attribute proc-macro in refl-derive that emits, at compile time: PartialReflect, Reflect, the relevant subtrait (Struct/TupleStruct/Tuple/Enum), Typed (with OnceLock init), TypePath (crate/module/name strings), and GetTypeRegistration. The only sanctioned authoring path (P1); hand-written impls are the documented exception.

downcast dyn Reflect → &T via as_any().downcast_ref::<T>().

  • Succeeds iff the value's runtime TypeId == TypeId::of::<T>() (I5).
  • Failed downcast → None, never undefined behavior (P8).
  • Do not downcast a Dynamic* proxy to a concrete type; proxies do not implement Reflect.

DynamicArray Fixed-length proxy for an array type.

  • Storage: Vec<Box<dyn PartialReflect>> with capacity locked at construction.
  • represented_type: Option<&'static TypeInfo> for the concrete [T; N].
  • apply is element-wise; length mismatch → ApplyError::ElementCountMismatch.

DynamicEnum Owning proxy for a Rust enum value.

  • Stores active variant name, variant index, and fields as one of: DynamicStruct, DynamicTuple, or () for unit variants.
  • set_variant(name, fields) clears prior fields entirely before setting new ones.
  • Field access on inactive variant → ReflectPathError; never silently returns stale data (I9).
  • apply: switches variant of target if source variant name differs, then copies fields.

DynamicFunction Runtime-erased function handle.

  • Fields: info: FunctionInfo, f: Box<dyn Fn(ArgList) -> Return + Send + Sync>.
  • Created by T::into_function() where T: IntoFunction.
  • call(ArgList) -> Result<Return, FunctionError> validates arity and arg TypeIds before invocation.

DynamicList Variable-length proxy for a List type.

  • Backing: Vec<Box<dyn PartialReflect>>.
  • push, insert(idx, val), remove(idx), get(idx), get_mut(idx), len, is_empty, iter.
  • apply: element-wise for existing indices; extra source elements appended; extra target elements removed.

DynamicMap Proxy for a Map type.

  • Backing: Vec<(Box<dyn PartialReflect>, Box<dyn PartialReflect>)>; insertion-order preserved.
  • Key lookup via reflect_partial_eq; no Hash/Eq bound required on the key type.
  • apply: for each source key-value pair, update target entry by key equality.

DynamicSet Proxy for a Set type.

  • Backing: Vec<Box<dyn PartialReflect>>.
  • Membership test via reflect_partial_eq; insert/remove/iter/contains/len.

DynamicStruct Owning proxy for a named-field struct.

  • Fields: Vec<(Cow<'static, str>, Box<dyn PartialReflect>)> plus represented_type: Option<&'static TypeInfo>.
  • apply matches by field name; unmatched fields in either direction are silently skipped (P5).
  • Used to build partial values before a concrete T is available; passed to FromReflect::from_reflect().

DynamicTuple Positional-field proxy.

  • Vec<Box<dyn PartialReflect>> backing.
  • Used standalone as a Tuple mirror, or as the field store of DynamicTupleStruct / tuple-variant DynamicEnum.

DynamicTupleStruct Proxy for a tuple struct.

  • Positional field store + represented_type.
  • Implements TupleStruct; apply is positional.

FunctionError Error from DynamicFunction::call().

  • Variants: ArgCountMismatch { expected, got }, ArgTypeMismatch { index, expected_type_path }, ReturnTypeMismatch { expected_type_path }.
  • Never panics on wrong arity or type; always returns structured error.

FunctionInfo Static description of a reflected function: args: Vec<ArgInfo>, return_info: ReturnInfo.

  • Captured once by IntoFunction; stored in DynamicFunction::info.
  • ReturnInfo: type_path, type_id; Option if return is ().

GetTypeRegistration Trait emitted by #[derive(Reflect)].

  • fn register() -> TypeRegistration: returns a fully-populated registration including TypeInfo, TypeData objects from #[reflect(Trait)] annotations, and ReflectFromReflect when FromReflect is derived.
  • Caller: TypeRegistry::register::<T>() calls this and inserts the result.

IntoFunction Trait converting fn(A, B, ...) -> R into a DynamicFunction.

  • Blanket impls for arities 0–12 via macro repetition in refl-func/src/into_function.rs.
  • Captures FunctionInfo at conversion time using Typed and TypePath bounds on argument and return types.
  • Closures that capture state are also supported if Send + Sync + 'static.

I1–I10 The ten system invariants; see the Invariants section. Any violation is a soundness or correctness bug, not acceptable user-error behavior. Invariant numbers are stable identifiers referenced by code comments, tests, and this glossary.

NamedField Per-field metadata inside StructInfo or a StructVariantInfo.

  • Fields: name: &'static str, TypePath, TypeId, zero-based index, custom attributes.
  • StructInfo holds a HashMap<&'static str, usize> name→index map for O(1) lookup.

OnceLock std::sync::OnceLock<T> used to back Typed::type_info().

  • Initialized on first call via get_or_init; race-free; returns &'static TypeInfo on every call.
  • Guarantees I8: same pointer on every call for the same type.
  • No mutable global state; initialization cost is one TypeInfo construction per type per process.

opaque / value type A type with no reflectable sub-structure (primitives, String, user-opted-in newtypes via #[reflect(opaque)]).

  • Reports ReflectRef::Opaque(&dyn PartialReflect).
  • Accessed only by downcast to the concrete type.
  • apply on opaque type: copies the whole value if TypeId matches; else ApplyError::MismatchedKinds.

P1–P10 The ten design principles; see the Design Principles section. Principle numbers are stable identifiers referenced by architectural decisions throughout the spec.

ParsedPath Pre-parsed sequence of OffsetAccess { access: Access, offset: usize } entries.

  • ParsedPath::parse("a.b[0].#1") → [Field("a"), Field("b"), ListIndex(0), TupleIndex(1)].
  • offset tracks the byte offset of each access in the original string for error messages.
  • Reusable across multiple GetPath calls; created once, applied many times.

PartialReflect Base trait — models an incomplete or dynamic value.

  • Required methods: reflect_ref, reflect_mut, reflect_owned, try_apply, represented_type_info, into_partial_reflect, as_partial_reflect, as_partial_reflect_mut.
  • Does not require Any; Dynamic* proxies implement only PartialReflect, not Reflect.
  • All Reflect types also implement PartialReflect (Reflect: PartialReflect).

property path Dot-bracket string addressing a nested field: .field_name (named), [n] (list/array index), #n (tuple positional).

  • Parsed by ParsedPath::parse() in refl-path.
  • Type-checked at each access step (P9); access on wrong kind → ReflectPathError, not wrong-typed reference.

Reflect Full-value trait: PartialReflect + Any.

  • Adds: as_any(&self), as_any_mut(&mut self), as_reflect(&self), as_reflect_mut(&mut self), set(&mut self, Box<dyn Reflect>) -> Result<(), Box<dyn Reflect>>, reflect_partial_eq.
  • Only concrete (non-proxy) types implement this.
  • set() replaces value in-place using downcast internally; returns the original box on TypeId mismatch.

ReflectDefault TypeData wrapping fn() -> Box<dyn Reflect> for types implementing Default.

  • Registered automatically when #[reflect(Default)] is on the type.
  • Retrieved: registration.data::<ReflectDefault>()?.default().

ReflectDeserializer serde::de::DeserializeSeed adaptor in refl-serde.

  • Reads { "crate::path::Type": <value> } outer envelope; looks up type in TypeRegistry; dispatches to per-kind deserialization.
  • Produces Box<dyn PartialReflect>.
  • Unknown type path → serde::de::Error not panic.

ReflectFromReflect TypeData wrapping fn(&dyn PartialReflect) -> Option<Box<dyn Reflect>>.

  • Enables TypeRegistry-driven from_reflect calls without naming T in scope.
  • Inserted by GetTypeRegistration::register() when FromReflect is derived.
  • Used by ReflectDeserializer after building a dynamic value to produce a concrete one.

ReflectMut<'a> Mutable-reference borrow enum; counterpart to ReflectRef<'a>.

  • Same variant set; returned by reflect_mut().
  • Borrow scope is 'a; cannot alias with any other borrow.

ReflectOwned Owning counterpart to ReflectRef; returned by reflect_owned().

  • Each variant holds a Box<dyn Struct>, Box<dyn List>, etc.
  • Moves the value out of the Box<dyn PartialReflect>.

ReflectPathError Error enum from property-path traversal.

  • Variants: NoSuchField { field, type_path }, NoSuchVariant { variant }, WrongType { expected_path, got_path }, IndexOutOfBounds { index, len }, InvalidAccess { access_kind, reflect_kind }.
  • Never returns a wrong-typed reference (I7).

ReflectRef<'a> Immutable shared-reference enum returned by reflect_ref().

  • Variants: Struct(&'a dyn Struct), TupleStruct(&'a dyn TupleStruct), Tuple(&'a dyn Tuple), List(&'a dyn List), Array(&'a dyn Array), Map(&'a dyn Map), Set(&'a dyn Set), Enum(&'a dyn Enum), Opaque(&'a dyn PartialReflect), Function(&'a dyn PartialReflect).
  • The primary dispatch surface for serialization, path traversal, and display tools.

ReflectSerializer serde::Serialize adaptor in refl-serde.

  • Walks &dyn PartialReflect via ReflectRef dispatch; emits a { type_path: value } map.
  • Handles all ReflectRef variants recursively; opaque values serialized via ReflectSerialize type-data.
  • No compile-time serde::Serialize required on T (P1, Phase 13).

reflect_clone Free function in refl-from: fn reflect_clone(value: &dyn Reflect) -> Box<dyn Reflect>.

  • Walks structure via reflect_ref; recurses into fields; reconstructs via FromReflect.
  • Does not require Clone on the concrete type.
  • Panics only if FromReflect::from_reflect returns None (structural mismatch; should not happen for well-formed types).

represented_type_info PartialReflect::represented_type_info() -> Option<&'static TypeInfo>.

  • Returns the TypeInfo of the concrete type a Dynamic* proxy stands in for.
  • None for untyped/anonymous proxies.
  • Used by apply to validate structural compatibility (I2) and by serializers to look up the type-path envelope key.

RTTI Runtime Type Information: type identity and structural metadata available at runtime. Rust provides only TypeId (via std::any); this system adds TypeInfo, TypePath, Typed, and TypeRegistry to build a full RTTI layer without compiler support. Analogous to C# System.Type, Java Class<?>, or Qt QMetaObject.

short_type_path Unqualified type name string from TypePath::short_type_path() (e.g., Vec<u32> vs alloc::vec::Vec<u32>).

  • For display and editor UI only; not a stable registry key.
  • Ambiguous short paths (two types with same short name in one registry) are detected and reported explicitly by TypeRegistry (P4, P10).

subtrait One of Struct, TupleStruct, Tuple, List, Array, Map, Set, Enum.

  • Each extends PartialReflect and provides kind-specific access methods.
  • Returned through the corresponding ReflectRef/ReflectMut/ReflectOwned variant.
  • Object-safe; all methods take &self or &mut self and return &dyn PartialReflect.

TypeData dyn Any + Send + Sync capability object stored in TypeRegistration.

  • Keyed by the TypeId of the data type, not of the reflected type.
  • Retrieved: registration.data::<D>() -> Option<&D>.
  • Produced once per T by FromType<T> at registration time; no later mutation (I10).

TypeId std::any::TypeId: opaque compiler-assigned integer identity for a monomorphic type.

  • Primary TypeRegistry key.
  • One-to-one with TypePath inside a single registry (I1).
  • Not stable across compilations; use TypePath for serialization/persistence.

TypeInfo enum TypeInfo { Struct(StructInfo), TupleStruct(TupleStructInfo), Tuple(TupleInfo), Enum(EnumInfo), List(ListInfo), Array(ArrayInfo), Map(MapInfo), Set(SetInfo), Opaque(OpaqueInfo) }.

  • Static structural description; holds field/variant metadata.
  • Stored in a OnceLock; returned by Typed::type_info() as &'static TypeInfo (I8).

TypePath Trait providing stable dotted-path strings as serialization and registry keys.

  • type_path() -> &'static str → fully qualified: alloc::vec::Vec<u32>.
  • short_type_path() -> &'static str → unqualified: Vec<u32>.
  • crate_name() -> Option<&'static str>, module_path() -> Option<&'static str>.
  • Must remain stable across compilations and crate renames.
  • Emitted by #[derive(Reflect)]; stored in DynamicTypePath for proxies (P4).

TypeRegistration One entry in TypeRegistry: type_info: &'static TypeInfo, type_id: TypeId, data: HashMap<TypeId, Box<dyn TypeData>>.

  • Created by GetTypeRegistration::register().
  • Inserted via TypeRegistry::register::<T>().
  • insert_type_data::<D>(d: D) merges additional type-data post-registration.

TypeRegistry The authoritative runtime map from TypeId → TypeRegistration.

  • Also: HashMap<String, TypeId> for TypePath-keyed lookup.
  • Wrapped in RwLock; typically Arc<RwLock<TypeRegistry>> for sharing across systems.
  • No global mutable static; ownership is explicit (P6, P10).
  • get_by_name(path) returns None for unregistered paths; never reflects unknown types silently.

UnnamedField Per-field metadata for positional fields in TupleStructInfo, TupleInfo, and tuple-variant VariantInfo.

  • Fields: zero-based index, TypePath, TypeId, custom attributes.

variant One arm of a Rust enum.

  • In reflection: a VariantInfo (one of StructVariantInfo, TupleVariantInfo, UnitVariantInfo).
  • Active variant in DynamicEnum governs field access (I9).
  • Enum::variant_name(), variant_index(), variant_type() expose identity; field access dispatch requires active-variant match.

VariantInfo enum VariantInfo { Struct(StructVariantInfo), Tuple(TupleVariantInfo), Unit(UnitVariantInfo) }.

  • Held in EnumInfo::variants: Box<[VariantInfo]>.
  • StructVariantInfo and TupleVariantInfo hold field metadata analogous to StructInfo/TupleInfo.

VariantType Runtime discriminant: Struct, Tuple, Unit.

  • Returned by Enum::variant_type().
  • Used by apply and path traversal to dispatch field access within the active variant.
