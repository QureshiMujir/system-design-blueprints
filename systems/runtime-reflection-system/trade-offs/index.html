Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust (stable channel, MSRV 1.75)

Rejected

C++, Go, Zig

When the rejected choice is right

C++ wins when embedding into an existing C++ engine with established template/RTTR machinery where an FFI boundary would cost more than it saves

Why: Memory safety without GC; trait system maps 1-to-1 to subtrait model; proc-macros native; bevy_reflect prior art

ADR-02

Build system

Chosen

Cargo workspace (Cargo.toml root; 11 members)

Rejected

Bazel, Buck2, Meson

When the rejected choice is right

Bazel/Buck2 win in a multi-language monorepo at thousands-of-targets scale where remote build caching dominates iteration time

Why: First-class crate graph; feature flags; no cross-tool friction; reproducible via Cargo.lock

ADR-03

Proc-macro crate isolation

Chosen

refl-derive is a separate proc-macro = true crate

Rejected

Combined single crate (inline macros)

When the rejected choice is right

A single combined crate wins when the library exposes no derive at all (pure runtime registration), so no proc-macro crate is needed

Why: Proc-macro crates cannot export non-macro items; isolation required by Cargo rules; cleaner dep graph

ADR-04

Dependency policy

Chosen

Minimal external deps; only serde (optional, feature-gated) and smallvec (optional) in public API

Rejected

heavy dep trees (tokio, anyhow as mandatory)

When the rejected choice is right

Heavy deps win when the crate is an application-level framework (not infrastructure) and tokio/anyhow are already universal in the target stack

Why: Reflection is infrastructure; impose no async/error runtime on consumers; serde opt-in via refl-serde feature

ADR-05

No-std compatibility

Chosen

refl-core, refl-info, refl-path are no_std + alloc

Rejected

std-only

When the rejected choice is right

std-only wins when the library targets only hosted platforms and uses std-only facilities (threads, std::time, std::io) pervasively

Why: Embedded / wasm consumers; TypeId is available in core; HashMap replaced by BTreeMap in no-std mode via feature

ADR-06

Serialization format

Chosen

serde data model (JSON in tests; format-agnostic in library)

Rejected

custom binary, CBOR mandatory

When the rejected choice is right

A mandated custom binary/CBOR codec wins when wire size and zero-copy decode dominate (high-rate telemetry) and serde's generality is overhead

Why: serde's Serialize/Deserialize traits are the Rust ecosystem standard; ReflectSerializer emits to any serde sink

ADR-07

Type identity key

Chosen

std::any::TypeId (runtime), TypePath string (stable / serialized)

Rejected

numeric hash, UUID, symbol pointer

When the rejected choice is right

A numeric hash/UUID wins for cross-process or cross-language identity, where the process-local TypeId is meaningless (distributed schema registries)

Why: TypeId is the only sound per-type unique identity in Rust; TypePath decouples identity across compilations for serde

ADR-08

Static TypeInfo storage

Chosen

OnceLock<TypeInfo> per type in a fn type_info_cell() -> &'static TypeInfo

Rejected

lazy_static, once_cell::sync::OnceCell, parking_lot::Once

When the rejected choice is right

once_cell/parking_lot win when MSRV must drop below 1.70 or you need init semantics (re-entrancy, takeable cells) OnceLock lacks

Why: OnceLock is stable since Rust 1.70; no extra dep; write-once semantics; I8

ADR-09

Registry concurrency model

Chosen

RwLock<RegistryInner> (std); arc-shared as Arc<RwLock<TypeRegistry>>

Rejected

DashMap, append-only lock-free map

When the rejected choice is right

DashMap/lock-free wins for hot-reload plugin systems that register continuously at runtime under heavy concurrent read+write

Why: Registration is rare (startup); read-heavy; RwLock sufficient; avoids unsafe lock-free complexity

ADR-10

TypeData storage key

Chosen

TypeId of the TypeData implementor (not the reflected type)

Rejected

string key, enum discriminant

When the rejected choice is right

String/enum keys win when TypeData must be addressed across a process boundary or selected by name from external config/data files

Why: Allows multiple TypeData impls per reflected type; TypeId is globally unique per data type; I10

ADR-11

Dynamic proxy heap allocation

Chosen

Box<dyn PartialReflect> per field in DynamicStruct/DynamicList

Rejected

Vec<u8> blob + offsets, arena

When the rejected choice is right

A blob+offsets/arena layout wins when proxies are hot-path and bulk-allocated (deserializing millions of dynamic records) and per-field Box dominates

Why: Simple ownership model; proxy types are construction artifacts, not hot-path; correctness > throughput for proxies

ADR-12

Path parser

Chosen

Hand-written recursive-descent in refl-path

Rejected

nom, pest, winnow

When the rejected choice is right

A combinator/PEG crate wins when the path grammar grows complex (custom operators, escapes, predicates) and maintainability beats the zero-dep goal

Why: Zero parse-crate dep; grammar is simple (see EBNF §8.7); error offsets trivial to track manually

ADR-13

Error types

Chosen

Per-module enum errors (ApplyError, ReflectPathError, FunctionError); no anyhow/eyre in public API

Rejected

Box<dyn Error>, anyhow::Error

When the rejected choice is right

anyhow/Box<dyn Error> win in binary/application code (e.g. refl-cli) where ergonomics beat match-on-variant and no downstream consumer is bound

Why: Structured errors enable match-on-variant; library crates must not impose error-handling crates on consumers

ADR-14

Logging / tracing

Chosen

tracing (optional feature) for registry warnings (ambiguous short path, duplicate registration)

Rejected

log, println

When the rejected choice is right

log wins when integrating with an existing log-based stack, or in a tiny embedded build where tracing's span machinery is unwanted weight

Why: tracing is the Rust async-ecosystem standard; structured spans; opt-in; zero overhead when disabled

ADR-15

Metrics / instrumentation

Chosen

None in public API; refl-bench exposes criterion benchmarks

Rejected

embedded Prometheus counters

When the rejected choice is right

Embedded counters win when the registry is shipped as a standalone reflection service (the product itself), not as a linked library

Why: Reflection is a library; runtime metrics belong to the consuming application

ADR-16

Testing strategy

Chosen

Unit tests inside each crate (#[cfg(test)]); integration tests in tests/ per crate; property tests via proptest for round-trip (I4, I6)

Rejected

only doc-tests, snapshot tests

When the rejected choice is right

Snapshot tests win for large stable serialized artifacts (golden TypeInfo dumps) where a structural diff is the natural assertion

Why: Integration tests exercise cross-crate behavior; proptest covers combinatorial round-trip cases that unit tests miss

ADR-17

Fuzzing

Chosen

cargo-fuzz (libFuzzer) targets for ParsedPath::parse and ReflectDeserializer; in fuzz/ directory

Rejected

afl.rs, manual corpus only

When the rejected choice is right

afl.rs wins where AFL's forkserver/instrumentation reaches deeper paths, or when fuzzing a binary (non-Rust) corpus format

Why: cargo-fuzz is the Rust ecosystem standard; ParsedPath and deserializer are attacker-controlled string inputs

ADR-18

Benchmarking

Chosen

criterion in refl-bench; benches: registration throughput, reflect_ref dispatch, path traversal 5-hop, serde round-trip

Rejected

divan, iai

When the rejected choice is right

iai/iai-callgrind wins in CI where instruction-count determinism beats wall-clock variance from noisy-neighbor runners

Why: criterion statistical rigor; wall-time and throughput; HTML reports in CI artifacts

ADR-19

CI/CD

Chosen

GitHub Actions; jobs: cargo test --all-features, cargo test --no-default-features, cargo clippy, cargo fmt --check, fuzz (10 min), bench (nightly, comment delta)

Rejected

GitLab CI, Jenkins

When the rejected choice is right

GitLab CI/Jenkins win inside enterprises with self-hosted runners, existing pipelines, and compliance requirements GitHub-hosted runners can't meet

Why: GitHub Actions native to OSS; matrix over stable + MSRV; fuzz job on schedule

ADR-20

MSRV policy

Chosen

1.75 (minimum); tested in CI matrix

Rejected

rolling latest only

When the rejected choice is right

Rolling-latest wins for an internal-only consumer that always builds on the newest toolchain and wants newest language features immediately

Why: OnceLock stable since 1.70; proc-macro2 / syn 2.x require ~1.56+; 1.75 gives headroom

ADR-21

syn / proc-macro2 version

Chosen

syn 2.x, proc-macro2 1.x, quote 1.x in refl-derive

Rejected

syn 1.x

When the rejected choice is right

syn 1.x wins when a heavy transitive dependency still pins syn 1 and avoiding a duplicate major version cuts compile time

Why: syn 2 has stable API, better error spans, attribute parsing improvements needed for #[reflect(...)]

ADR-22

Feature flags

Chosen

default = ["std"]; optional: "serde" (enables refl-serde), "smallvec", "tracing", "functions" (refl-func)

Rejected

single monolithic feature set

When the rejected choice is right

A single feature set wins for a private application where build-matrix complexity isn't worth it and every feature is always enabled

Why: Consumers pay only for what they enable; refl-func adds non-trivial API surface and dep on no external crate but is optional

Licensing

Chosen

MIT OR Apache-2.0 (dual)

Rejected

MIT-only, GPL

When the rejected choice is right

GPL wins when copyleft is a deliberate strategy to force downstream openness; MIT-only when a consumer's policy resists the Apache-2.0 patent grant

ADR-24

Reproducible builds

Chosen

Cargo.lock committed; rust-toolchain.toml pinning stable channel + MSRV

Rejected

floating toolchain

When the rejected choice is right

A floating toolchain wins for a canary CI lane whose purpose is to surface breakage against the newest compiler as early as possible

Why: Ensures CI and developer builds match; fuzz target corpus reproducible

ADR-25

Packaging / distribution

Chosen

crates.io publish per crate; workspace publish = true with version parity

Rejected

monorepo private only

When the rejected choice is right

Private-only wins for proprietary internal reflection never intended for public distribution, where crates.io publishing is pure risk

Why: Public distribution enables downstream use; semver enforced; refl-derive version must match refl-core

ADR-26

Soundness review

Chosen

Dedicated Phase 14 soundness audit: review all unsafe blocks (downcast via as_any), lifetime annotations on ReflectRef<'a>, variance; cargo geiger zero-unsafe target for refl-core

Rejected

ad-hoc review

When the rejected choice is right

Ad-hoc review suffices for a zero-unsafe prototype with no downcast or lifetime-extension hazards yet to audit

Why: Reflection systems are downcast-heavy; lifetime variance errors here cause UB; structured audit gate before 1.0

ADR-27

Async / runtime

Chosen

None; all APIs are synchronous

Rejected

async fn traits, tokio dep

When the rejected choice is right

Async wins when reflection drives I/O-bound work (lazily loading TypeData from a remote registry) where blocking the caller is unacceptable

Why: Reflection is a synchronous data-structure library; async adds no value and complicates dyn Reflect object safety

ADR-28

Example CLI (refl-cli)

Chosen

Separate binary crate showing inspect / edit-by-path / serialize without compile-time serde

Rejected

integration test only

When the rejected choice is right

Integration-test-only wins when there is no human-facing use case and a shipped binary would be dead weight in the release artifact

Why: Demonstrates real-world use; smoke-tests the full pipeline; doubles as a user-facing tutorial entry point

Roads not taken

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt-1 — Compile-time codegen only (no runtime metadata)

#[derive(Serialize, Deserialize)]  ->  concrete visitor impls
                                       (no TypeRegistry, no dyn Reflect)
value ──serialize──▶ format          (operations fixed at compile time)

The derive emits concrete per-type impls; there is no runtime type object, no registry, no dyn Reflect. Wins when the set of operations is known at compile time (serialize/deserialize to a fixed format) and maximum speed + minimal surface matter. Real system: serde + serde_derive. Rejected here because it cannot support open-ended, data-driven access — edit-by-path, inspect-an-unknown-value, scripting — which require a runtime type object to query (MM1, Phase 12, Phase 14).

Alt-2 — VM / managed-runtime universal metadata

toolchain bakes full metadata into every type  ->  reflection reads VM tables
(Java .class / .NET metadata)                        no opt-in, method invoke free

Every type carries complete metadata; reflection reads VM/CLR tables. Wins when you own the runtime and can afford always-on metadata, giving universal reflection plus method invocation and attributes for free. Real systems: Java java.lang.reflect, C# System.Reflection. Rejected here because Rust has no VM; baking universal metadata into every binary violates zero-cost-at-unuse (MM8) and bloats every artifact (C9).

Alt-3 — Single monolithic Reflect trait + central Value enum

trait Reflect { fn kind(&self) -> Kind; fn as_any(&self) -> &dyn Any; }
enum Value { Struct(..), List(..), Map(..), .. }   // callers match + downcast

One trait returns a kind enum; callers match and downcast. Wins for a small, fixed set of types where the subtrait tower is overkill — many config/interpreter systems use exactly this. Real systems: ad-hoc enum Value interpreters and config layers. Rejected here because it does not compose (each new container type edits the central enum) and loses the generality of structural apply and typed path traversal (MM5, MM6, Phase 7).

Alt-4 — Arena / columnar dynamic storage instead of boxed proxies

DynamicStruct { arena: Vec<u8>, fields: [(name, offset, type)] }
                          // vs Box<dyn PartialReflect> per field

Proxies store fields in a typed arena / offset table rather than a Box per field. Wins for bulk deserialization of millions of dynamic records where per-field allocation dominates (the ADR-11 "rejected wins" regime). Real systems: columnar engines (Arrow-style) and ECS component storage. Rejected here because it complicates ownership and the apply/proxy model, and proxies in this design are construction artifacts, not a hot path (ADR-11, C8).
