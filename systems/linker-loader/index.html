Loader-specific flow (§18), a separate process/address-space from the static linker above: mmap PT_LOAD segments -> resolve DT_NEEDED (recursive, cycle-safe) -> bind PLT (lazy or BIND_NOW) -> allocate TLS (DTV + per-module blocks) -> jump to _start.

Box paragraphs. CLI Drivers — the only externally-facing trust boundary; every byte from argv, response files, and input files is treated as untrusted until validated (§23 T1). Driver Layer — classifies inputs by magic byte, never by file extension; resolves -L/-rpath/sysroot before any file is opened, so search-path logic has no dependency on reader state. Static Link Pipeline — a streaming pipeline: each stage produces an immutable artefact consumed by the next; the only cross-stage mutable state is the global symbol table, built once at §14 and read-only thereafter (I7). Dynamic Link Pipeline — runs in its own process at execve time, never inside the linker; it is a state machine with five reachable ObjectStates (I10). Object Reader — every InputFile variant borrows from an Mmap owned by the driver; the persistence boundary is the mmap itself, never a copy. Symbol Resolver — the one place mutable shared state exists (I7); protected by 64 shards (ADR-05). Layout Engine — a pure function of the resolved symbol table and LinkOptions (P11); no relocation is applied until this stage settles. GC + ICF — two dual passes over the same reachability graph (§17, MM7). Relocator — per-architecture arithmetic kernels behind the ArchBackend trait (§11.6, P7); no shared mutable state across output sections, so this stage parallelises per-section (§20.1). Output Writer — the single owner of all mmap/pwrite calls (P3, P14); the build-id is a pure function of the final bytes with its own field zeroed (I14). LTO — the only stage that hands control to an external toolchain (LLVM via inkwell, ADR-09) before returning ELF objects to the normal pipeline. Loader — a #![no_std] self-relocating program (MM4) that never shares runtime state with the static linker beyond the object-format contract they both implement (P6).

8. Domain Model

8.1 ELF Container Model

An ELF64 file is: a fixed 64-byte header, an optional program-header table (absent in ET_REL), a section-header table, and section bodies. The header layout:

Offset Field Size Meaning
0x00 e_ident[0..4] 4 Magic 0x7F 'E' 'L' 'F'
0x04 e_ident[EI_CLASS] 1 1 = 32-bit, 2 = 64-bit
0x05 e_ident[EI_DATA] 1 1 = LE, 2 = BE
0x10 e_type 2 ET_REL/ET_EXEC/ET_DYN/ET_CORE
0x12 e_machine 2 EM_X86_64=62, EM_AARCH64=183, EM_RISCV=243
0x18 e_entry 8 Entry virtual address (0 for ET_REL)
0x20 e_phoff 8 Program-header table file offset
0x28 e_shoff 8 Section-header table file offset
0x38 e_phnum/e_shnum/e_shstrndx 2 each Header counts + string-table index

8.2 Section & Program Header Layout

Elf64_Shdr (64 bytes): sh_name(4) · sh_type(4) · sh_flags(8) · sh_addr(8) · sh_offset(8) · sh_size(8) · sh_link(4) · sh_info(4) · sh_addralign(8) · sh_entsize(8). Elf64_Phdr (56 bytes): p_type(4) · p_flags(4) · p_offset(8) · p_vaddr(8) · p_paddr(8) · p_filesz(8) · p_memsz(8) · p_align(8).

8.3 Symbol Table Model

Elf64_Sym (24 bytes): st_name(4) · st_info(1, bind<<4 | type) · st_other(1, visibility) · st_shndx(2) · st_value(8) · st_size(8). Resolution precedence (§14.2): STB_GLOBAL > STB_WEAK > STB_LOCAL-never-global > SHN_COMMON-tentative > undefined; STB_GNU_UNIQUE behaves as STB_GLOBAL for resolution; STT_GNU_IFUNC resolves to WinningDef::Ifunc.

8.4 Relocation Model

Elf64_Rela (24 bytes): r_offset(8) · r_info(8, symbol index in high 32 bits, type in low 32 bits) · r_addend(8, signed). A representative subset of the x86_64 table:

Type Field Size Formula Notes
R_X86_64_64 64-bit S + A Absolute
R_X86_64_PC32 32-bit signed S + A − P PC-relative
R_X86_64_PLT32 32-bit signed L + A − P Via PLT stub at L
R_X86_64_GOTPCREL 32-bit signed G + GOT + A − P GOT-indirect load
R_X86_64_GOTPCRELX 32-bit signed as GOTPCREL, relaxable to LEA when local+in-range Linker relaxation (§15.2)
R_X86_64_TPOFF32 32-bit signed S + A − TLS_offset Local-Exec TLS
R_X86_64_GOTTPOFF 32-bit signed G + GOT + A − P (GOT slot filled by loader) Initial-Exec TLS
R_X86_64_TLSGD 32-bit signed G + GOT + A − P (two GOT slots: DTPMOD64,DTPOFF64) General-Dynamic TLS
R_X86_64_RELATIVE 64-bit B + A (B = load bias) Dynamic-only, self-relocation
R_X86_64_IRELATIVE 64-bit resolver return value IFUNC dynamic

Worked example. Resolve R_X86_64_PLT32 for a call printf@plt at .text offset 0x20, output section .text at vaddr 0x401000 (so P = 0x401020), printf's PLT stub at L = 0x401300, addend A = -4 (x86 call disp is relative to the instruction's end): value = L + A − P = 0x401300 − 4 − 0x401020 = 0x2DC. Patch bytes at offset 0x20 (little-endian 32-bit): DC 02 00 00. Range check: 0x2DC fits signed 32-bit — pass.

8.5 GOT/PLT/Dynamic Section Model

The x86_64 PLT entry is a fixed 16-byte instruction sequence:

.plt[i]:  jmp *got.plt[i+3](%rip)   ; steady state: direct jump to resolved target
          push $i                   ; first call: index for the resolver
          jmp .plt[0]               ; common resolver stub
.plt[0]:  push got.plt[1](%rip)     ; loader-private linkage-map pointer
          jmp *got.plt[2](%rip)     ; loader's _dl_runtime_resolve

.dynamic (DT_* entries, Elf64_Dyn: d_tag(8) + d_val/d_ptr(8)) carries DT_NEEDED, DT_SONAME, DT_RPATH/DT_RUNPATH, DT_HASH/DT_GNU_HASH, DT_PLTGOT, DT_JMPREL, DT_RELA/DT_RELASZ, DT_INIT_ARRAY, DT_VERSYM/DT_VERDEF/DT_VERNEED, DT_FLAGS_1.

8.6 TLS Model

PT_TLS holds p_filesz (= .tdata size), p_memsz (= .tdata+.tbss), p_align. Four access models, increasing indirection/decreasing linker-time-binding: Local-Exec (offset from %fs:0 known at link time) → Initial-Exec (GOT-held offset, filled at load time) → General-Dynamic (__tls_get_addr(modid, offset) call, supports dlopen) → Local-Dynamic (GD-style call amortised across same-module accesses).

8.7 Loader State Machine

ObjectState: Mapped → RelocsApplied → InitArrayCalled → Running → Detached (I10). Boot sequencing (§18.3) walks this once per LoadedObject, breadth-first across the DT_NEEDED DAG (I11).

8.8 Malformed-Input & Failure-Path Examples

Malformed ELF: e_shoff = 0x50000 but file size 0x400 → ElfParseError::SectionHeaderOffsetOutOfBounds { offset: 0x50000, file_size: 0x400 }, rendered as bad.o: e_shoff 0x50000 exceeds file size 0x400 (truncated or corrupt section header table) — never a panic (§13.6).

Missing symbol: a reference to undefined_func from .text+0x10 in bad.o, satisfied by no input, archive, or shared library → Diagnostic code lk0012: undefined reference to 'undefined_func', referenced from bad.o:.text+0x10; no shared library provides it (pass --allow-shlib-undefined to suppress) (P5, I12).
