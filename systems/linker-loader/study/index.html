Hard questions (§34)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does the mmap-based writer (ADR-04, P3) make --gc-sections+--icf=all change output size but not the wall-clock-dominant phase? (§17, §20, §33)
  2. Why must symbol resolution (§14) reach a fixed point (I7) before layout (§16) begins, and what breaks if a partial table leaks through? (§7 I7, §16.1)
  3. Why is the archive crawl worst-case bounded at 16 --start-group iterations, and what is the failure mode past that bound? (§14.1, §24 FM-4, §33 #11)
  4. Why does -z now -z relro close the GOT-overwrite exploit class while lazy binding cannot be retrofitted with the same guarantee? (§16.2, §23 T6)
  5. Why must the loader self-relocate (MM4) before calling any Rust code, and what crashes if it does not? (§18.2, §31 MM4)
  6. Why do the LE/IE/GD/LD TLS models form a latency/flexibility tradeoff curve rather than four independent mechanisms? (§16.4, §31 MM5)
  7. Why does sharding the symbol table at 64, not 1 or 1024, matter specifically for the chrome-class benchmark? (§9 ADR-05, §33 #1–2, §20.1)

  9. Why does ICF require a byte-and-relocation verifier pass after hash-match grouping instead of trusting the hash alone? (§17.2, §7 I9)
  10. Why is .eh_frame the GC "sealant," and what is the difference between the conservative and aggressive GC strategies for it? (§17.1, §17.6)
  11. Why must the build-id be computed over output bytes with its own field zeroed (I14), and what would break if it were not? (§7 I14, §9 ADR-15)
  12. Why is Rust's ownership model specifically suited to the newtype-per-concept principle (P4), and what bug class does it eliminate at compile time that C++ could not? (§6 P4, §9 ADR-01)
  13. Why must the resolver distinguish "originally internal" from "LTO-promoted" symbols, and what leaks if it does not? (§19.2, §24 FM-12)
  14. Why must the loader's ObjectState machine be monotonic (I10), and what real bug does a backward transition cause? (§7 I10, §18.2)
  15. Why does DT_RPATH search before LD_LIBRARY_PATH while DT_RUNPATH searches after, and why does this ordering difference generate the most common loader bug report? (§18.6, §26)
  16. Why is reproducibility a "sorting discipline" (MM3) rather than an absence of parallelism, and where would non-determinism first leak if a sort were dropped? (§31 MM3, §20.2)
  17. Why does the comparative-architecture analysis (§32) treat mold's mmap-writer as a discontinuity rather than an incremental improvement over gold's design? (§32, §9 ADR-04)

  21. Why must IFUNC resolvers avoid referencing TLS (§18.6), and what does that constraint reveal about the ordering of the loader's boot steps? (§18.2, §18.6)

31. Mental Models & First Principles

  • MM1 — A relocation is a deferred write. Insight: every relocation is "patch this byte range with a value computed later," nothing more. Predicts: relocation application fully parallelises once symbol values are known (§20.1). Bug class without it: serialising relocation application under a false assumption that order matters. Applies at §15, §20.
  • MM2 — The GOT is an indirection contract, not a data structure. Insight: the GOT's slots are allocated at link time but its values are a runtime contract fulfilled by the loader. Predicts why -z now vs lazy binding is a security/latency tradeoff, not two unrelated features. Bug class without it: conflating GOT allocation timing with GOT initialization timing. Applies at §16, §18.
  • MM3 — Determinism is a sorting discipline, not an absence of parallelism. Insight: parallelise freely as long as every merge step sorts by a stable key. Predicts I3 holds under any thread count. Bug class without it: assuming "parallel" implies "nondeterministic," leading to unnecessary serialisation. Applies at §20, P1/P2.
  • MM4 — The loader is a program that hasn't linked itself yet. Insight: lk-ld.so is itself an ET_DYN requiring relocation before its own globals are valid. Predicts why self-relocation must precede any Rust/global-state code. Bug class without it: calling into globals before self-relocation, crashing nondeterministically depending on load address. Applies at §18.3.
  • MM5 — TLS is per-thread virtual memory with a compile-time-chosen indirection cost. Insight: LE/IE/GD/LD are one latency/flexibility tradeoff curve, not four unrelated mechanisms. Predicts which model a given code shape (static executable vs dlopen-able library) should use. Bug class without it: treating TLS models as arbitrary compiler choices rather than a spectrum. Applies at §16.4, §18.
  • MM6 — A symbol table is a last-writer-wins log with typed precedence, not a set. Insight: the multiple-definition/weak/strong rules fall out of one total precedence order (§14.2). Predicts the exact winner for any combination of bind types without special-casing. Bug class without it: ad hoc special-casing for each new bind-type combination instead of one ordered rule. Applies at §14.2.
  • MM7 — ICF and GC are dual passes over the same reachability graph. Insight: GC finds reachable, ICF finds redundant — both walk the same section-relocation graph. Predicts they can share infrastructure (the graph builder) even though their outputs differ. Bug class without it: building two independent, divergent graph representations. Applies at §17.
  • MM8 — A conformance fixture is a frozen bug report. Insight: every fixture encodes one specific failure made permanently impossible to reintroduce. Predicts why the Deferred/Fail count should only shrink, never silently regrow (M14). Bug class without it: treating conformance as a checkbox rather than a living regression firewall. Applies at §22, §27, P9.

5. Required Reading

Books

  • Levine, Linkers and Loaders, Morgan Kaufmann, 1999 — ch.5 (relocation), ch.7 (loading and overlays); extract the taxonomy of relocation processing and the loader state machine. Applied in §15 (Phase 3), §18 (Phase 6).
  • Bryant & O'Hallaron, Computer Systems: A Programmer's Perspective, 3rd ed., 2015 — ch.7 (Linking); extract symbol-resolution intuition and the static-vs-dynamic tradeoff. Applied in §2, §14 (Phase 2).
  • System V Application Binary Interface — Generic ABI, Edition 4.1 + errata — ch.4 (Object Files), ch.5 (Program Loading and Dynamic Linking); extract the ELF structure contract every reader/writer obeys. Applied in §13 (Phase 1), §16 (Phase 4), §18 (Phase 6).
  • System V ABI — AMD64 Architecture Processor Supplement (psABI-x86_64), v1.0 + errata — the relocation-type table (appendix); extract exact patch arithmetic per R_X86_64_*. Applied in §15 (Phase 3).
  • System V ABI — AArch64 Architecture Processor Supplement (psABI-aarch64), latest ARM-maintained revision — the relocation-type table; extract ADRP/ADD/CALL26 patch arithmetic. Applied in §19.1 (Phase 7).
  • RISC-V ELF psABI Specification (riscv-non-isa/riscv-elf-psabi-doc, latest tag) — relocation types + linker relaxation (R_RISCV_RELAX); extract HI20/LO12 pairing rules. Applied in §19.2 (Phase 7).
  • Tool Interface Standard (TIS) ELF Specification, v1.2, 1995 — the historical baseline the SysV ABI assumes; extract note-section tag/length/value framing. Applied in §13 (Phase 1).

Papers

  • Ian Lance Taylor, "Linkers" (20-part blog series), 2007–2008 — an implementer's rigorous walkthrough of symbol resolution, relocation, and archive semantics. Applied in §14 (Phase 2 resolver), §15 (Phase 3 relocations).
  • Ian Lance Taylor, gold linker design notes (binutils-gdb/gold/README and his 2008 blog entries specifically on gold) — motivates the section/symbol data-structure split that predates mold's parallelism. Applied in §20 (Phase 8), ADR-04.
  • Rui Ueyama, mold project README and design documentation (github.com/rui314/mold) — mmap-based output construction, sharded parallel symbol resolution, the ICF algorithm. Applied in ADR-04, §17 (Phase 5), §20 (Phase 8).
  • David Lattimore, wild project README and design notes (github.com/davidlattimore/wild) — Rust-native crate-boundary design for a parallel ELF linker. Applied in §11 (Core Schema crate boundaries), §20 (Phase 8).
  • Ulrich Drepper, "How To Write Shared Libraries", v4.1.2, Red Hat, 2011 — the canonical treatment of PLT/GOT, symbol interposition, versioning, -Bsymbolic. Applied in §18 (Phase 6).
  • Ulrich Drepper, "ELF Handling For Thread-Local Storage", v0.21, Red Hat, 2013 — the canonical specification of the four TLS access models and the DTV. Applied in §16.4 (Phase 4), §18 (Phase 6).
  • DWARF Standards Committee, DWARF Debugging Information Format, Version 5, 2017 — .debug_info/.eh_frame structure needed for GC-of-FDEs and DWARF merge. Applied in §17 (Phase 5 GC), §20 (Phase 8 DWARF merge).
  • W3C, WebAssembly Core Specification (Recommendation, 2019/2.0 draft) + WebAssembly Community Group, "Module Linking" proposal (draft, WebAssembly/module-linking) — the stretch-surface target format. Applied in §22.8 (Phase 10 Edge Cases), §36.

Reference Implementations

  • GNU ld/bfd (binutils-gdb, bfd/elf.c, bfd/elflink.c, ld/ldlang.c) — lesson: the reference BFD-shaped linker's section/symbol abstraction; pitfall: its global mutable bfd state does not translate to a parallel design — read as a spec reference, not a copy target. Applied in §14, §16.
  • gold (binutils-gdb/gold/, e.g. symtab.cc, layout.cc) — lesson: the first ELF linker to seriously threaded symbol resolution; pitfall: unmaintained upstream, do not chase its exact internal APIs. Applied in §20.
  • LLVM lld (llvm-project/lld/ELF/InputSection.cpp, Relocations.cpp, Writer.cpp, SyntheticSections.cpp) — lesson: the closest thing to a modern ELF-linker textbook in code form; pitfall: heavy C++ class hierarchies do not map directly onto Rust ownership — redesign, don't transliterate. Applied in §16, §19.
  • mold (github.com/rui314/mold, ELF backend under elf/) — lesson: mmap-writer + parallel resolution is the architecture that changes the wall-clock class; pitfall: file layout evolves with ongoing refactors — pin a tag before mining exact paths. Applied in ADR-04, §17, §20.
  • wild (github.com/davidlattimore/wild, wild_lib crate) — lesson: the closest stylistic/architectural reference for our Rust crate boundaries; pitfall: still evolving — do not pin to unstable internal APIs. Applied in §11, §20.
  • glibc dynamic loader (glibc/elf/rtld.c, dl-load.c, dl-reloc.c, dl-lookup.c) — lesson: the reference dynamic loader's TLS/DTV allocation and lazy-PLT machinery; pitfall: heavy macro use obscures control flow — trace with LD_DEBUG=all alongside the source. Applied in §18.
  • musl dynamic loader (musl/ldso/dynlink.c) — lesson: a minimal, single-file loader, often clearer than glibc's; pitfall: musl assumes static-PIE more aggressively — some shortcuts do not generalise to glibc-compatible scenarios. Applied in §18, §35 Alt-4.

RFCs / Specifications

  • Apple, Mach-O Runtime Reference / Mach-O Programming Topics — applied in §21 (Phase 9 Mach-O read path).
  • Microsoft, PE Format Specification (Windows Dev Center) — applied in §21 (Phase 9 PE/COFF read path).
  • IEEE/The Open Group, POSIX.1-2017 System Interfaces (dlopen/dlsym/dlclose semantics) — applied in §18 (Phase 6 loader contract).
  • Linux man-pages, execve(2), elf(5) — applied in §12 (Phase 0), §18 (Phase 6 auxiliary-vector contract).

If the literature changes (a new architecture supplement, a new format revision, a new published parallel-linking technique), open an ADR and pin the change (ADR-01…ADR-25, §9); never silently follow trunk.

Glossary (§37) · 53 terms · site-wide glossary

ELF
Executable and Linkable Format; the container format for all lk-produced output.
ET_REL
relocatable object file type (.o); has no program headers.
ET_DYN
shared-object/PIE file type; base address is not fixed.
ET_EXEC
non-PIE executable; fixed base address (not produced by default, P10).
PT_LOAD
a program-header entry describing a segment to mmap.
PT_DYNAMIC
points at .dynamic, the dynamic-linking metadata table.
PT_TLS
describes the thread-local-storage template (.tdata+.tbss).
PT_INTERP
names the dynamic loader path the kernel should invoke.
PT_GNU_RELRO
marks a region the loader mprotects read-only post-relocation.
PT_GNU_STACK
carries the stack's execute permission (default: none, P10).
GOT
Global Offset Table; indirection slots for external data/PLT addresses.
PLT
Procedure Linkage Table; lazy-binding stubs for external functions.
DT_NEEDED
a .dynamic entry naming a required shared library.
DT_SONAME
the shared object's own canonical name.
DT_RPATH
legacy library search path, searched before LD_LIBRARY_PATH.
DT_RUNPATH
modern library search path, searched after LD_LIBRARY_PATH.
BIND_NOW
resolve all PLT entries at load time, not lazily.
RELRO
Relocation Read-Only; post-relocation mprotect hardening.
TLS
Thread-Local Storage; per-thread data with four access models (§8.6).
DTV
Dynamic Thread Vector; per-thread table mapping module id → TLS block.
IFUNC
indirect function; address resolved by a resolver function at load time.
STB_WEAK/STB_GLOBAL/STB_LOCAL
symbol binding classes (§8.3, §14.2).
STV_HIDDEN
visibility excluding a symbol from the dynamic symbol table.
COMDAT
a section group deduplicated across translation units (§16.6, §17).
ICF
Identical Code Folding; deduplicates byte-identical output sections.
GC-sections
discards unreferenced input sections (§17.1).
LTO
Link-Time Optimisation; cross-module optimisation at link time.
ThinLTO
summary-based LTO avoiding a single monolithic IR merge.
Bitcode
LLVM's serialized IR format, LTO's input (ADR-09).
Build-ID
a content hash embedded in the output for symbol-server matching (ADR-15).
Reproducible build
byte-identical output across hosts/runs for identical inputs (I3).
ASLR
Address Space Layout Randomization; why PIE base addresses vary per run.
PIE
Position-Independent Executable; ET_DYN with an entry point.
Symbol versioning
verdef/verneed mechanism disambiguating symbol@VERSION.
Archive (ar)
a container of relocatable-object "members" with a symbol index.
Thin archive
an ar variant storing paths to members instead of their bytes.
Relocation
an instruction to patch a byte range with a computed value (MM1).
Addend
the constant term in a relocation's value formula.
Auxiliary vector (auxv)
kernel-provided key/value pairs at process start (§18.2).
_start
the true process entry point, before main (§18.2).
DWARF
the debug-information format merged (not synthesized) by lk (ADR-14).
.eh_frame
exception-handling frame data; the GC "sealant" (§17.6, MM7).
FDE
Frame Description Entry; one .eh_frame record per function.
CFI
Call Frame Information; the semantic content of FDEs.
Fixed point
the state where resolution produces no further changes (I7).
Sharded lock
a lock split across N partitions to reduce contention (ADR-05).
Reachability worklist
the GC algorithm's core data structure (§17.1).
LD_PRELOAD
forces a library to the front of the resolution scope.
LD_AUDIT
a hook interface observing loader decisions (ADR-23).
Symbol interposition
one module's symbol shadowing another's at resolution time (§23 T3).
RTLD_GLOBAL/RTLD_LOCAL
dlopen flags controlling a loaded module's symbol visibility to others.
Static PIE
a position-independent executable with no dynamic dependencies (§35 Alt-4).
GNU_HASH
the modern hash-table format for fast dynamic symbol lookup (§8.5, §33 #12).
