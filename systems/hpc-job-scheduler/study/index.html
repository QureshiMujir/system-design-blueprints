Mental Models & First Principles

These are the compressed insights that distinguish an expert designer from someone who has read the code. Each is numbered MM1…MM8, names the exact §/phase where the blueprint applies it, states what a violation produces, and names the failure class you write without the model.

MM1. A scheduler is a transaction log with a priority index. Every scheduling decision — allocate, free, requeue — is a durable state mutation that must be ordered relative to all other mutations. The pending queue is just a view over uncommitted resource reservations. Expert insight: if you cannot replay your scheduling log to reconstruct the exact queue state, your log is missing a record. Predicts: WAL-before-ack correctness (P6, Phase 3). Bug class without it: job appears in queue after WAL loss but controller has already dispatched it — double-dispatch on restart. Applied in: §6 P6, §7 I5, Phase 3.2.

MM2. Bitmap allocation is a compare-and-set over a vector, not a bag of integers. A node's available cores are not a count; they are a set of specific logical CPU indices. Two jobs wanting "4 cores" may want disjoint sets. The correctness invariant is bitwise: (existing_alloc & new_alloc) == 0. Counting alone misses this. Expert insight: the only safe atomicity primitive is a read-modify-write over the entire bitmap under a lock. Predicts: I1 (no double-allocation). Bug class without it: two allocations for adjacent core ranges silently overlap at word boundaries. Applied in: §6 P3, §7 I1/I2, Phase 4.2.

MM3. Backfill correctness is a monotonicity property, not a greedy heuristic. The EASY invariant (Lifka 1995, P2) is: the reservation start for the top job must be non-decreasing after each backfill decision. Any backfilled job that could push that start rightward must be rejected — even if it fits in free nodes today. Predicts: I4. Bug class without it: backfill launches a job with a 3-hour limit into nodes reserved in 2 hours; top job starves. Applied in: §6 P4, §7 I4, Phase 7.2.

MM4. Fair-share without decay is a priority debt that never expires. Without usage decay, a group that burst-submitted 1000 jobs last month has permanently lower priority than all new groups. The half-life formula (P15) ensures the penalty is proportional to recency. Expert insight: select the decay half-life as the ethical "statute of limitations" for overconsumption, not a performance knob. Predicts: §6 P5 (hierarchical decay). Bug class without it: new research groups on the cluster can never compete with legacy power users; cluster becomes a political problem, not a technical one. Applied in: §8 P5, §8 Multifactor Priority Model, Phase 8.2.

MM5. A durable controller with a standby is not two copies of state — it is one log with two readers. The standby does not hold a "copy" of the primary's state; it holds a WAL tail position. Promotion is just: advance the read head to the committed offset, take the write lock, increment the epoch. If the standby diverges at all, it has applied a record the primary did not commit, or skipped one it did. The single source of truth is the WAL, never the in-memory state of either peer. Predicts: I9, failover correctness (Phase 12). Bug class without it: standby applies a record from a partial WAL segment that the primary rolled back — post-failover job counts differ from accounting records. Applied in: §6 P10, §7 I9, Phase 12.2.

MM6. Heartbeat timeout detection must be conservative and symmetric. Setting missed_heartbeat_threshold = 1 causes false positive Down transitions on a single delayed packet; setting it to 10 means 5 minutes of wasted runtime before jobs are requeued. The symmetric failure mode is equally dangerous: marking a node Down whose processes are still running and then reallocating its cores to a new job causes a live double-allocation that neither party knows about. Expert insight: the threshold must be: (max_acceptable_blast_radius) / (jobs_per_node × requeue_cost). Predicts: P7, I6. Bug class without it: NTP-induced 1-second heartbeat delay causes all 4096 nodes to flap Down/Up every hour. Applied in: §4 failure budget, §7 I6, Phase 10.2.

MM7. The scheduling pass is a snapshot function, not a streaming computation. The pass must take a point-in-time snapshot of queue and node state at its start. Any state change that arrives mid-pass — a cancel RPC, a heartbeat from a newly-up node — must be deferred to the next pass. If the pass reads live state incrementally, it may allocate the same node to two jobs in the same pass based on stale bitmap state. Expert insight: the pass produces a deterministic function of (queue_snapshot, node_snapshot) → decisions, with no side-effects during iteration. Predicts: P8 (determinism), I1 (within-pass double-allocation). Bug class without it: a job that completes at the start of the pass returns its nodes to the live bitmap, and two subsequent iterations in the same pass both see those nodes as free. Applied in: §6 P8, Phase 5.2, Phase 7.2.

MM8. Cgroup enforcement is the only source of truth for resource isolation — the scheduler's accounting is advisory. The controller knows how many cores it allocated. It does not know how many CPU cycles a job actually consumed. A job that forks many processes can exceed its cgroup cpu quota and get throttled by the kernel — invisible to the controller. Epilog resource reports (rusage) and cgroup statistics are the ground truth. Expert insight: the scheduler's TRES accounting (I10) measures allocation × time, not actual consumption; these diverge whenever a job is throttled, OOM-killed, or checkpointed. Bug class without it: fair-share usage is computed from allocation time, not CPU time; a throttled job penalizes its account as much as a 100%-utilized job. Applied in: §6 P1, §7 I10, Phase 6.2 (cgroup enforcement), Phase 11.2 (TRES accounting).

Glossary · 35 terms · site-wide glossary

Account
Named billing/accounting entity in the association tree; owns a shares weight; accumulates decayed TRES usage; parent of user associations.
Age factor
Priority component proportional to submit_time elapsed since submission; increases linearly; weight-configurable in PriorityFactors.
Allocation
Controller-assigned binding of CoreBitmap, GpuSet, and mem_per_node on specific nodes to a single JobId; commits atomically to WAL before dispatch.
Association
Leaf node in the fair-share tree; maps (user, account, partition, qos) → limits and usage_decayed; enforced at submit and schedule time.
Backfill (EASY)
Scheduling algorithm: one reservation for the top pending job; fill idle resources before the reservation start with lower-priority jobs whose projected end ≤ reservation start.
Backfill (conservative)
Extension: maintains reservations for all pending jobs, not just the top one; prevents any job from being delayed by backfilled work.
Cgroup enforcement
Per-job-step Linux control group (cpu, memory, devices subsystems) applied by hpcsched-noded to bound actual resource consumption to ResourceSpec.
Checkpoint
Periodic snapshot of full controller state (jobs, nodes, allocations, fair-share tree) appended to durable store; bounds WAL replay window on restart.
Controller (controld)
Single authoritative daemon (hpcsched-controld) owning all scheduling decisions, state transitions, and WAL writes; analogous to slurmctld.
CoreBitmap
Fixed-length bitset with one bit per logical CPU on a node; set bits = allocated; union of all per-job bitmaps ≤ node capacity; allocation is a transactional OR + check.
Decayed usage
Fair-share usage attenuated by a half-life factor each period; prevents historical over-use from penalising a user indefinitely.
Depth limit
Maximum number of pending jobs examined in a single backfill scan; bounds worst-case backfill-pass latency (P9).
Drain / Draining
Administrative NodeState: no new jobs scheduled; running jobs complete normally; used for maintenance without hard disruption.
Eligible set
Jobs that pass partition, limit, and dependency checks and are candidates for allocation in the current scheduling pass.
Epilog / Prolog
Shell scripts invoked by hpcsched-noded after job step exit (epilog) or before launch (prolog); clean up scratch dirs, release GRES, reset cgroups.
Fencing
Mechanism ensuring only one controller (primary or promoted standby) can commit allocations to durable store; prevents duplicate allocations across failover.
Gang scheduling
Time-slicing: co-located jobs from different users/partitions share a node's CPUs in alternating quanta; enforced by hpcsched-noded via SIGSTOP/SIGCONT.
GRES (Generic Resource)
Schedulable device beyond CPU/mem; in this project, GPUs tracked by GpuSet; model extensible to NICs, licenses, FPGAs.
GpuSet
Bitmap of logical GPU indices on a node; analogous to CoreBitmap; allocation is a transactional bitwise OR + capacity check.
Heartbeat
Periodic HeartbeatMsg from hpcsched-noded → hpcsched-controld carrying current resource report; timeout triggers node Down transition.
Job
Unit of work: { id, user, spec, state, priority, submit_time, alloc, times }; submitted by sbatch/srun; owns an Allocation when Running.
Job step
Sub-unit running inside an Allocation; launched by srun; multiple steps may share one allocation; each tracked by StepId.
Multifactor priority
Scalar u32 computed as weighted sum of age, fair-share, partition tier, QoS tier, and job-size factors; determines PendingQueue order.
Node daemon (noded)
Per-compute-node daemon (hpcsched-noded) that registers, sends heartbeats, receives LaunchMsg, spawns job steps, enforces cgroups, and reports state; analogous to slurmd.
NodeState
Enum { Idle, Allocated, Mixed, Down, Drain, Draining }; Mixed = partially allocated; Down = heartbeat-lost or admin-set.
Partition
Logical queue with a node set, time limit, max-nodes, priority tier, and preemption policy; jobs specify target partition in ResourceSpec.
Pending queue
Priority-ordered collection of Jobs in Pending state, maintained by hpcsched-queue; ordered by PriorityFactors-derived scalar; ties broken by submit_time.
Preemption
Controller-initiated action suspending or requeueing a running lower-priority job to free resources for a higher-priority/higher-QoS job; modes: suspend, requeue, checkpoint.
QoS (Quality of Service)
Named policy tier attached to an association; carries limits (max_jobs, max_TRES, GrpTRES), a priority multiplier, and a preemption level.
Requeue
Transition of a Running or Failed job back to Pending with its original ResourceSpec; triggered by node Down or preemption if requeueable = true.
Reservation
{ window, node_set, job_id }: time-bounded hold on a node set for the top pending job computed by the backfill engine; no other job may start within this window on these nodes.
Scheduling pass
Single execution of the hpcsched-sched main loop: sort pending queue, try-allocate top jobs in priority order, then run EASY backfill; produces SchedulePass result.
TRES (Trackable Resource)
Any resource dimension tracked by the accounting system: CPUs, mem, GPUs, nodes, licenses; all appear in ResourceSpec and accrual records.
Usage (fair-share)
Per-association sum of TRES-seconds consumed over all completed jobs, multiplied by decay factor; feeds the fair-share priority component.
WAL (Write-Ahead Log)
Ordered, append-only log of state mutations (JobSubmitted, JobAllocated, JobCompleted, …); written to durable store before controller acks any operation; used for replay on restart.
