3.2 Subsystem Descriptions

hpcsched-cli (user-facing binaries). Trust boundary: untrusted user space; all commands authenticate by Unix UID passed in the submit RPC. Data flow out: submit RPC (sbatch/srun), cancel RPC (scancel), query RPCs (squeue/sinfo/sacct). Data flow in: status responses, job IDs, tabular output. No persistent state; purely a stateless RPC client.

Control-plane RPC (hpcsched-proto). Defines the wire protocol between CLI, controld, and noded. Message types: SubmitReq/Resp, AllocNotify, LaunchMsg, HeartbeatMsg, StepStatusMsg, CancelReq, StatusQuery/Resp. Transport: length-prefixed binary frames over TCP (Tokio async I/O). Trust boundary: controld authenticates noded connections by node hostname + shared secret; CLI connections authenticated by UID. Concurrency boundary: each connection is a Tokio task; messages serialized per-connection; controld's event loop serializes mutations.

Submission + pending queue (hpcsched-queue). Receives validated SubmitReq; constructs Job with initial Pending state; appends JobSubmitted WAL record before acking; inserts into a priority-ordered pending queue (BinaryHeap or sorted skip-list keyed by PriorityFactors). Exposes: eligible_set(partition, node_inventory) — jobs that can in principle run given current resource inventory and partition constraints. Data flow in: submit RPC. Data flow out: ordered job view to hpcsched-sched; priority updates from hpcsched-fairshare.

Fair-share tree + multifactor priority (hpcsched-fairshare). Maintains the Account/Association tree: each node holds shares, usage_decayed, children. On each scheduling pass (and periodically in background): recomputes fair-share factor per user/account; assembles PriorityFactors { age, fairshare, partition, qos, job_size, weights } → scalar u32 priority. Decay: half-life configurable; usage flows from leaf (user) to root (cluster). No I/O; pure in-memory computation seeded from hpcsched-acct usage records. Trust boundary: internal; not directly reachable by users.

Scheduling loop (hpcsched-sched). Core decision engine. Runs on a timer tick (configurable interval, default 0.5–2 s) or on state-change event. Main pass: iterate eligible pending jobs in priority order; call hpcsched-alloc for each; on success transition Pending→Configuring, append JobAllocated WAL, send LaunchMsg to noded. EASY backfill pass: compute Reservation for the top pending job; iterate lower-priority eligible jobs; allocate those whose projected end ≤ reservation start. Invariant P4, I4. Depth-limited: at most backfill_depth (default 500) candidates examined per pass (P9). Concurrency: single-threaded within the pass; no re-entrant scheduling.

Allocator (hpcsched-alloc). Operates on per-Node CoreBitmap, GpuSet, and alloc_mem. allocate(spec, node_inventory) → Option<Allocation>: selects a set of nodes satisfying ResourceSpec (feature constraints, count, contiguity if requested); atomically sets bits transactionally (read-copy-update over the bitmap); returns Allocation { job_id, nodes: Vec<(NodeId, CoreBitmap, GpuSet, mem)> }. free(allocation): clears bits on job completion. Invariants I1, I2, I3. No async I/O; pure in-memory; called synchronously inside the scheduling loop.

Durable state (hpcsched-state). WAL: append-only log of state-change events (JobSubmitted, JobAllocated, JobCompleted, NodeDown, ...) written to disk before any acknowledgement (P6). Checkpoint: periodic full snapshot of controller state; WAL truncated post-checkpoint. Replay: on startup, load latest checkpoint, replay WAL records from that point; produces exact prior state (I5). Used by HA standby (Phase 12) to tail WAL and track primary state. Persistence boundary: only component that touches disk in the controller process.

Accounting / TRES / limits (hpcsched-acct). Records per-job TRES usage (cpu-seconds, mem-seconds, gpu-seconds) on job completion and periodically for running jobs. Enforces association/QoS limits at submit time (max jobs in flight, max TRES, GrpTRES) and at schedule time (remaining quota check). Feeds hpcsched-fairshare with decayed usage. Serves sacct query RPC. Data flow in: JobCompleted events + periodic running-job polls. Data flow out: usage records to fairshare; limit verdicts to submission path; tabular data to sacct CLI.

Node daemons (hpcsched-noded). One process per compute node; no cluster-wide state. On startup: registers with controld (node id, cpu/mem/gpu/features). Periodic heartbeat: HeartbeatMsg { node_id, timestamp, free_cpus, free_mem, free_gpus, running_steps }. On LaunchMsg: spawns job step processes under cgroup v2 hierarchy (cpu quota, memory limit, device allowlist for GPUs); monitors via waitpid + resource sampling. On step exit: sends StepStatusMsg { step_id, exit_code, rusage } → controld advances job FSM. On CancelMsg: sends SIGTERM then SIGKILL after grace period; cleans up cgroup. Trust boundary: compute node; not in user trust domain; controld sends signed launch tokens (Phase 2+). Concurrency: one Tokio task per running step plus one heartbeat task.

State-transition table (authoritative; no other transitions are valid per I7):

From To Trigger / Condition WAL Record
— Pending submit RPC accepted + WAL flushed JobSubmitted
Pending Configuring scheduling pass: alloc succeeds, noded notified JobAllocated
Pending Cancelled scancel before scheduling JobCancelled

Terminal states: Completed, Failed, Cancelled. No transition out of terminal states.

8.2 NodeState Machine

State Accepts new jobs Existing jobs Transition triggers
Idle Yes None first alloc → Mixed or Allocated
Allocated Yes (if space) Running normally last job finishes → Idle; partial free → Mixed
Mixed Yes (if space) Running normally all slots taken → Allocated; all free → Idle
Drain No (I6) Run to completion admin scontrol update node drain; finish → Down
Draining No Run to completion implicit when Drain+jobs present; all done → Down
Down No (I6) Requeued or Failed heartbeat timeout; admin mark; resume → Idle

8.3 ResourceSpec + CoreBitmap Semantics

ResourceSpec {
  nodes:         u32,          // number of nodes required (1..=max_nodes)
  tasks:         u32,          // total MPI ranks / processes
  cpus_per_task: u16,          // logical CPUs per task
  mem_per_node:  u64,          // bytes
  gpus:          u16,          // GPUs per node (GRES)
  time_limit:    Duration,     // wall-clock; checked at admission
  partition:     PartitionId,
  qos:           QosId,
  account:       AccountId,
}

Derivation rules:

  • cpus_needed_per_node = ceil(tasks / nodes) * cpus_per_task
  • Admission gate: cpus_needed_per_node <= node.cpus, mem_per_node <= node.mem, gpus <= node.gpus
  • CoreBitmap: fixed-width bit vector (max 1024 bits); set-bit = allocated core.
  • GpuSet: u64 bitmask (max 64 GPUs per node); set-bit = allocated GPU.
  • Allocation is transactional: all-or-nothing; partial failure rolls back all node bitmaps (P3, I1).

8.4 Allocation Record Layout

Allocation {
  job_id:  JobId,
  nodes:   Vec<NodeAlloc>,
}

NodeAlloc {
  node_id:  NodeId,
  cores:    CoreBitmap,    // which cores assigned on this node
  gpus:     GpuSet,        // which GPU indices
  mem:      u64,           // bytes reserved on this node
}

Invariants per allocation record:

  • I1: ∀ (n, c) : ¬∃ two live Allocations sharing any bit in c on the same n
  • I2: node.alloc_cores.count() * cpu_frequency + alloc_mem ≤ node capacity
  • I3: job.state == Running ↔ job.alloc.is_some()
  • On job completion: bitmap bits freed before WAL JobCompleted record is appended.

8.5 WAL + Checkpoint Record Taxonomy

WAL record variants (hpcsched-state; serialized as MessagePack framed by u32 length + CRC32):

Variant Key fields When appended
JobSubmitted job_id, user, spec, submit_time before submit RPC ack (P6)
JobAllocated job_id, allocation, start_time after bitmap commit, before launch
JobStarted job_id, start_time after all noded ack step-launch
JobCompleting job_id when final step exits
JobCompleted job_id, end_time, exit_code, tres_usage after epilog exits 0
JobFailed job_id, end_time, exit_code, reason after epilog non-zero or step error
JobCancelled job_id, cancel_time, cancelled_by before SIGTERM dispatch
JobRequeued job_id, reason (NodeDown Preempted
JobPreempted job_id, preempt_mode, preemptor_id on preemption decision
NodeStateChange node_id, old_state, new_state, reason on every node state transition
CheckpointRef checkpoint_file, lsn inlined after checkpoint flush
AccountUsageDecay tree snapshot, decay_epoch periodic fair-share decay event

Checkpoint: full controller state snapshot serialized as bincode; compressed (zstd level 3). WAL is truncated after checkpoint is durable (fsync). Replay = load checkpoint + apply WAL records since CheckpointRef.lsn.

Replay correctness invariant (I5):

  • All bitmap operations are idempotent under re-apply given the snapshot baseline.
  • JobAllocated re-applied: set bits, update node maps. JobCompleted re-applied: clear bits.
  • Duplicate record detection: each WAL record carries a monotone lsn: u64; skip lsn <= checkpoint_lsn.

Transport: TCP + TLS 1.3; framing: u32 big-endian length prefix + MessagePack body.

8.7 Scheduling Pass Semantics

Main pass (priority order): main_pass(queue: &PendingQueue, nodes: &NodeMap) -> SchedulePassResult walks queue.eligible_iter() (priority-descending, ineligible jobs already filtered) and for each job attempts alloc::try_allocate(job.spec, nodes). Every successful attempt is accumulated into the result set and its bits are applied tentatively to nodes so later jobs in the same pass see them as used — this tentative-apply step is what prevents double-allocation within a single pass. The result set is what gets committed: a JobAllocated WAL record followed by the real bitmap commit, per accumulated (job, alloc) pair.

Contract invariants:

  • Pass is a deterministic function of (queue snapshot, node snapshot) → P8.
  • Tentative bitmap apply prevents double-allocation within a single pass.
  • Pass bounded at O(pending × nodes); depth-limited via max_sched_iters config → P9.

EASY Backfill semantics: easy_backfill(top_job, queue, nodes, now) first computes a Reservation for the top pending job — the earliest time T at which it fits, reserving those nodes for [T, T+top_job.time_limit]. The backfill candidate set is every lower-priority job whose projected_end(now) is no later than the reservation's start. Candidates are considered in priority order, depth-limited by the backfill_depth config; a candidate is allocated immediately only if it fits within currently-free nodes outside the reservation's node set before the reservation start — I4 is exactly the constraint that no candidate may be allocated in a way that overlaps the reservation window.

Worked example — normal backfill:

now = T0
Nodes: N0(4cpu), N1(4cpu), N2(4cpu)
Queue (priority desc): J1(8cpu, 2h), J2(4cpu, 30m), J3(4cpu, 1h)

main_pass: J1 needs 8 cpu → not enough free (only 12, but J1 needs 2 nodes, possible)
  → J1 alloc: N0+N1; reservation = [T0, T0+2h] on N0+N1.
  J2: needs 4cpu on 1 node; N2 free, projected_end = T0+30m < T0+2h ✓ → backfill J2 on N2 now.
  J3: needs 4cpu; N2 will free at T0+30m; projected_end = T0+30m+1h = T0+1.5h < T0+2h ✓ → schedule.

Failure-path example — backfill violation rejected:

J3 has time_limit = 1h30m; projected_end = T0+2h = reservation.start → NOT < reservation.start.
J3 blocked; top job J1's reservation is not delayed (I4 enforced).

Edge cases:

Case Behavior
Top job never fits (infinite time) Reservation set to now + top_job.time_limit; backfill only below that window
Two jobs tie in priority Tiebreak by job.submit_time ascending; deterministic per P8
Node goes down mid-pass Pass sees pre-snapshot node state; reconciled next cycle; no partial alloc
All nodes drain simultaneously Eligible set = empty; pass produces empty result; no error
Job time_limit = 0 Rejected at admission; not inserted into queue
Job requests 0 nodes Rejected at admission; ResourceSpec validation enforces nodes >= 1
Backfill candidate over limits Filtered by eligible_iter; QoS/association limit checked before backfill attempt

8.8 Multifactor Priority Model

Priority formula (P5, I8):

priority(job) =
  W_age      * age_factor(job)       +
  W_fairshare * fairshare_factor(job) +
  W_partition * partition.priority_tier +
  W_qos      * qos.priority_factor  +
  W_jobsize  * job_size_factor(job)

age_factor(job)        = min(job_age_seconds / age_scale, 1.0)
fairshare_factor(job)  = 2^( -effective_usage(acct) / shares(acct) )
job_size_factor(job)   = 1 - (job.spec.nodes / max_nodes_in_partition)

Fair-share tree traversal:

Association tree (rooted at "root"):
  root  (shares=100)
  ├── dept_A (shares=60)
  │   ├── user_alice (shares=40)
  │   └── user_bob   (shares=20)
  └── dept_B (shares=40)
      └── user_carol (shares=40)

effective_usage(user_alice) = usage_alice + Σ usage_children_alice
                             propagated to parent: dept_A usage includes alice+bob

Decay: usage_decayed(t) = usage_decayed(t-1) * decay_factor + raw_usage(interval). decay_factor default 0.9 per accounting interval. Accounts with zero recent usage approach usage_decayed → 0, boosting their fairshare_factor → 1.

8.9 Preemption Semantics

Preemption modes (ordered by disruption level):

Mode Effect on victim job Job state transition Requires checkpoint
Suspend SIGSTOP to job step processes Running → Preempted No
Checkpoint App-level checkpoint + SIGTERM Running → Preempted Yes
Requeue Kill + reinsert into Pending Running → Requeued No
Cancel SIGTERM/SIGKILL; job lost Running → Cancelled No

Preemption eligibility:

  • victim.partition.preemptible == true
  • victim.qos.priority < preemptor.qos.priority
  • victim.job.priority < preemptor.job.priority (anti-cycle guard)
  • Grace period: SIGTERM → SIGKILL after preempt_grace_sec (default 30 s)

Gang scheduling: time-sliced co-location of jobs on shared nodes; scheduler marks job groups; noded suspends/resumes on tick (default 30 s); configured per partition.

TRES (Trackable Resources): cpu, mem, node, gpu, energy (extensible via plugin registry).

8.11 Durable State Replay Semantics

Sequence for replay after crash:

1. Load latest checkpoint file: deserialize into ControllerState { jobs, nodes, queue, accounts }
2. Open WAL; seek to checkpoint_lsn
3. For each record with lsn > checkpoint_lsn:
   a. JobSubmitted  → insert job into queue (idempotent if already present)
   b. JobAllocated  → apply allocation bitmaps; set job state = Configuring
   c. JobStarted    → set job state = Running
   d. JobCompleted  → free bitmaps; set state = Completed; write AcctRecord
   e. JobFailed     → free bitmaps; set state = Failed
   f. JobCancelled  → free bitmaps (if allocated); set state = Cancelled
   g. JobRequeued   → free bitmaps; set state = Pending; re-insert queue
   h. NodeStateChange → update node state map
4. Reattach to live nodeds: send re-registration challenge; noded responds with current step status
5. Reconcile: any Running job whose noded reports no active step → transition to Completing or Requeued

Post-replay invariant checks (I5, I1, I2, I3): assert no double-allocated bits; assert Running jobs have allocations; assert node alloc sums do not exceed capacity. Fail-fast if any invariant violated (corrupt WAL).

8.12 Heartbeat Timeout + Node Fault Handling

noded heartbeat period: 30 s
missed_heartbeat_threshold: 3 (configurable)
timeout_detection_period: 90 s

on timeout(node_id):
  1. NodeStateChange(node_id, prev_state, Down)        → WAL append
  2. for job in jobs_on_node(node_id):
       if job.spec.requeueable:
         free_bitmaps(job.id); transition Running → Requeued → Pending
       else:
         free_bitmaps(job.id); transition Running → Failed
  3. node removed from eligible set; no new allocations

Drain sequence:

admin issues: drain node_id reason
1. NodeStateChange(node_id, prev, Drain)
2. No new jobs allocated to node (I6)
3. Running jobs complete normally (epilog runs)
4. When last job finishes: NodeStateChange(node_id, Drain, Down)
5. Admin un-drains: NodeStateChange(node_id, Down, Idle) after noded re-registers
