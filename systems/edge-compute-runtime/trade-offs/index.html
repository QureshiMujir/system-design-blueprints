Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust (stable toolchain)

Rejected

C++, Go, Zig

When the rejected choice is right

C++ wins to reuse an existing V8/engine codebase; Go wins where GC pauses are acceptable and dev velocity dominates; Zig wins for manual memory control with simple C interop

Why: Memory safety without GC; zero-cost abstractions; first-class Wasmtime integration; unsafe auditable

ADR-02

Build system

Chosen

Cargo (workspace)

Rejected

Bazel, Buck2, CMake

When the rejected choice is right

Bazel wins for a polyglot monorepo needing hermetic remote caching across languages

Why: Native Rust ecosystem; workspace crates map to locked module names; reproducible via Cargo.lock

ADR-03

WASM engine

Chosen

Wasmtime (Bytecode Alliance)

Rejected

Wasmer, wasm3, V8 Isolates

When the rejected choice is right

V8 isolates win when running JavaScript directly (the Cloudflare Workers model) rather than WASM; wasm3 wins on tiny embedded targets where interpreter size beats JIT speed

Why: First-class fuel metering, epoch interruption, pooling instance allocator; WASI + component model blueprint; audited codebase

ADR-04

Async runtime

Chosen

Tokio (multi-threaded)

Rejected

async-std, smol, blocking threads

When the rejected choice is right

Blocking threads win for a CPU-bound single-tenant runtime with few concurrent invocations; smol wins when minimal runtime footprint matters

Why: De-facto Rust async ecosystem; structured concurrency; tokio::time for wall-clock deadlines; Wasmtime async integration

ADR-05

Dependency policy

Chosen

Minimal pinned deps; cargo deny for license + advisory scan

Rejected

Unpinned; full vendoring

When the rejected choice is right

Full vendoring wins in an air-gapped or compliance environment requiring an auditable frozen dependency tree

Why: Balance supply-chain safety with maintainability; Cargo.lock in VCS; deny unmaintained + unsound advisories

ADR-06

Serialization (cross-PoP wire)

Chosen

MessagePack (rmp-serde) for Invalidation records

Rejected

JSON, Protobuf, FlatBuffers

When the rejected choice is right

Protobuf wins when cross-PoP records need schema evolution and multi-language consumers; JSON wins for human-debuggable propagation streams

Why: Compact binary; no schema compilation step; fast decode; suitable for propagation fan-out

ADR-07

Serialization (guest-memory marshal)

Chosen

Raw byte layout (little-endian, 4-byte aligned)

Rejected

MessagePack, Protobuf

When the rejected choice is right

MessagePack/Protobuf marshal wins when guest and host versions evolve independently and need schema compatibility

Why: Zero-copy; deterministic; no per-call allocation; layout documented in 8.10

ADR-08

Config / deploy format

Chosen

TOML (serde + toml crate)

Rejected

YAML, JSON, HCL

When the rejected choice is right

YAML wins when config is generated by k8s/CI tooling; HCL wins in Terraform-centric orgs

Why: Cargo-native; human-editable; unambiguous typing; no YAML boolean foot-guns

ADR-09

HTTP client (subrequests)

Chosen

hyper + rustls

Rejected

reqwest, curl-sys

When the rejected choice is right

reqwest wins when ergonomics beat fine-grained control; curl-sys wins when needing libcurl's protocol breadth

Why: Low-level control over timeouts + connection pooling; TLS via rustls (no OpenSSL dependency)

ADR-10

HTTP server (ingress)

Chosen

hyper (server-side)

Rejected

axum, actix-web, warp

When the rejected choice is right

axum/actix-web win when building a feature-rich API with routing/extractors rather than a minimal edge ingress

Why: Minimal abstraction layer; direct connection lifecycle control; edge-router wraps hyper directly

ADR-11

KV storage (local replica)

Chosen

sled (embedded B-tree, pure Rust)

Rejected

RocksDB, SQLite, in-memory HashMap

When the rejected choice is right

RocksDB wins for write-heavy LSM workloads with mature tuning; SQLite wins when relational queries are needed at the edge

Why: Pure Rust, no C FFI; acceptable read latency for edge; TTL expiry enforced at application layer

ADR-12

In-memory cache layer

Chosen

DashMap<CacheKey, CacheEntry>

Rejected

RwLock<HashMap>, moka

When the rejected choice is right

moka wins when you need built-in TTL/size eviction policies; RwLock<HashMap> wins for tiny low-concurrency caches

Why: Lock-free shard reads; hot-path cache lookup without contention; no background thread for eviction complexity

ADR-13

Metrics collection

Chosen

metrics crate + Prometheus exporter (metrics-exporter-prometheus)

Rejected

OpenTelemetry SDK metrics, statsd

When the rejected choice is right

OpenTelemetry metrics win when unifying metrics and traces under a single OTLP pipeline

Why: Lightweight; standard Prometheus scrape endpoint; tenant attribution via label dimensions

ADR-14

Distributed tracing

Chosen

OpenTelemetry (opentelemetry + tracing-opentelemetry) with OTLP export

Rejected

Zipkin native SDK, Jaeger native SDK

When the rejected choice is right

A native Jaeger/Zipkin SDK wins when locked to that backend and needing its backend-specific features

Why: Vendor-neutral; tracing crate integration; spans carry IsolateId + TenantId context

ADR-15

Structured logging

Chosen

tracing crate + tracing-subscriber (JSON formatter)

Rejected

log crate, slog

When the rejected choice is right

log + env_logger wins for a minimal tool not needing span context or structured fields

Why: Structured JSON lines; span context auto-propagated; same subscriber for library and binary crates

ADR-16

CPU accounting mechanism

Chosen

Wasmtime fuel metering (primary) + epoch interruption (wall-clock backstop)

Rejected

Wall-clock only, Linux cgroups CPU

When the rejected choice is right

cgroups CPU accounting wins for native (non-WASM) workloads where per-instruction fuel metering is unavailable

Why: Fuel: deterministic per-instruction (I8, P7); epoch: worst-case wall bound; two independent mechanisms prevent bypass

ADR-17

Pooling allocator

Chosen

Wasmtime PoolingInstanceAllocator

Rejected

Custom slab, jemalloc regions

When the rejected choice is right

A custom slab/jemalloc-region allocator wins when not using Wasmtime, or when instance memory layout needs control the engine does not expose

Why: Engine-native; reuses memory slots across instances without mmap overhead; aligns with P2 cold-start minimization

ADR-18

Snapshot/restore mechanism

Chosen

Manual memory-image capture (memcpy of initialized pages) + global capture; hash verification

Rejected

Wasmtime instance forking (unstable), CoW mmap

When the rejected choice is right

CoW mmap forking wins once stable (eliminates the memcpy); Wasmtime instance forking wins when the engine guarantees image integrity natively

Why: Full control over integrity verification (I4); CoW mmap deferred as Phase 5 optimization path

ADR-19

Concurrency model (scheduler)

Chosen

Tokio task per invocation + tokio::sync::Semaphore for concurrency slots

Rejected

Thread-per-request, pinned work-stealing threads

When the rejected choice is right

Thread-per-request wins when host calls are blocking/synchronous and async offers no benefit; pinned work-stealing wins for CPU-bound batch processing

Why: Task-per-request maps to async host calls; semaphore enforces per-PoP + per-tenant caps (Phase 9)

ADR-20

Cross-PoP transport

Chosen

TCP + TLS (hyper client) with persistent connection pooling

Rejected

gRPC, QUIC, UDP gossip

When the rejected choice is right

QUIC wins for lossy/high-latency cross-PoP links needing 0-RTT and head-of-line-blocking avoidance; gRPC wins when a typed multi-language RPC contract is needed

Why: Simplicity; QUIC deferred to Phase 14; gRPC adds protobuf compilation step and code-gen toolchain

ADR-21

Testing framework

Chosen

#[test] + tokio::test; nextest as runner; integration tests in tests/ per crate

Rejected

criterion-only, custom harness

When the rejected choice is right

A custom harness wins for non-Rust integration tests or hardware-in-the-loop validation

Why: Standard; nextest: faster parallel execution, better failure output; criterion for benchmarks only

ADR-22

Fuzzing

cargo-fuzz (libFuzzer) targeting host-call boundary, guest-memory marshal, invalidation deserializer

AFL++/honggfuzz win for advanced mutators or fuzzing a non-libFuzzer target

ADR-23

Benchmarking

Chosen

criterion (micro-benchmarks, CI regression gate) + edge-cli bench subcommand (soak / cold-start rate)

Rejected

hyperfine (CLI only), divan

When the rejected choice is right

hyperfine wins for whole-CLI end-to-end timing; divan wins for lower-overhead microbenchmarks

Why: criterion: per-function regression in CI; soak: cold-start rate + p99 under multi-tenant load

ADR-24

CI/CD

Chosen

GitHub Actions; matrix (stable + beta Rust); cargo clippy --deny warnings; cargo deny check

Rejected

Jenkins, CircleCI, GitLab CI

When the rejected choice is right

GitLab CI wins on self-hosted GitLab; Jenkins wins for complex on-prem pipelines with custom hardware runners

ADR-25

Containerization

Chosen

OCI image via docker buildx multi-stage (builder=rust:slim, runtime=distroless)

Rejected

Nix flake, bazel container_image

When the rejected choice is right

Nix flakes win for fully hermetic reproducible images; bazel container_image wins when already in a Bazel monorepo

Why: Reproducible; distroless minimizes attack surface; no shell in production container image

ADR-26

Reproducible builds

Chosen

Cargo.lock committed; pinned toolchain via rust-toolchain.toml; SOURCE_DATE_EPOCH set in CI

Rejected

Nix, Guix

When the rejected choice is right

Nix/Guix win when cross-language hermetic reproducibility is a hard compliance requirement

ADR-27

WASI support level

Chosen

WASI Preview 1 (wasi-common via Wasmtime linker)

Rejected

WASI Preview 2 / component model, no WASI

When the rejected choice is right

WASI Preview 2 / component model wins once stable and when composing multiple typed-interface components

ADR-28

Error handling idiom

Chosen

thiserror for library error enums; anyhow confined to binary crates and edge-cli

Rejected

Box<dyn Error>, eyre

When the rejected choice is right

eyre wins when richer report formatting (spantrace) is desired in binaries; a bare Box<dyn Error> wins for a quick throwaway script

Why: thiserror: machine-matchable errors in library crates (trap kinds, host-call errors); anyhow: ergonomic in CLI/bin only

Alternative Architectures (Roads Not Taken)

Alt-A — MicroVM per function (Firecracker model).

request --> [ Firecracker microVM boots/resumes guest kernel + runtime ] --> run --> snapshot/pause

Wins when: hard hypervisor-level isolation and arbitrary unmodified runtimes matter more than sub-millisecond cold start (untrusted multi-tenant, regulatory). Embodied by: AWS Lambda, Fly.io. Rejected because: microVM cold start and per-VM memory overhead are far higher than in-process WASM isolates (MM1); the target is high-density, sub-ms cold start.

Alt-B — V8 isolates running JavaScript directly.

request --> [ reuse warm V8 isolate, run JS/WASM ] --> isolate stays resident

Wins when: the workload is JavaScript-first and near-zero cold start at massive scale is paramount. Embodied by: Cloudflare Workers, Deno Deploy. Rejected because: it specializes to JS and meters by wall-time (non-deterministic across hardware); this project targets language-agnostic WASM with deterministic fuel accounting (MM4).

Alt-C — Container-per-request (traditional FaaS).

request --> [ schedule container, pull image, start process ] --> run --> teardown/keep-warm

Wins when: workers need full OS/syscall access and existing container images, and cold start in the hundreds-of-ms is acceptable. Embodied by: Knative, OpenFaaS, early AWS Lambda. Rejected because: container cold start and per-container memory are orders of magnitude above the < 1 ms / high-density targets (§4.1); WASM sandboxing gives the isolation without the OS weight.

Alt-D — Ahead-of-time native compilation, no sandbox (trusted plugins).

worker code --AOT--> native .so loaded into the host process, called directly

Wins when: all code is first-party and trusted, and you want zero sandbox overhead (internal plugin systems). Embodied by: native plugin architectures, nginx modules. Rejected because: multi-tenancy with untrusted code is the core requirement; removing the sandbox forfeits the isolation budget (MM1, MM6) entirely.
