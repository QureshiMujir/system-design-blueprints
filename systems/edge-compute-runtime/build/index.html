⬜ Phase 1 — WASM Runtime Foundation

Objectives
  • Compile a .wasm binary into a native-code Module via Wasmtime Engine; cache compiled artifact keyed by (WorkerId, content_hash).
  • Instantiate with a per-instance Store<HostState>; each instance owns exactly one WASM linear memory; no shared memory objects.
  • Link host imports via a Linker<HostState>; stubs return Trap in Phase 1, fully implemented in Phase 6.
  • Call an exported fetch handler; receive return values; perform clean teardown (drop Store, reclaim linear memory slab).
  • Engine config locks: cranelift_opt_level(Speed), cranelift_nan_canonicalization(true), wasm_threads(false), wasm_relaxed_simd(false), epoch_interruption(true), consume_fuel(true).
  • Scope: edge-runtime (engine, module, instance, linker, marshal); edge-core (foundational types).
  • No resource enforcement yet; fuel and epoch limits are wired but not enforced until Phase 4.
Deliverable
  • edge-runtime and edge-core crates compile (cargo build --release).
  • cargo test passes all Phase 1 tests.
  • edge-cli run --wasm fixtures/hello.wasm --handler fetch executes and exits 0.
  • Module cache hit confirmed by edge_module_cache_hit_total metric increment in test.

⬜ Phase 2 — Request/Response + Invocation Lifecycle

Objectives
  • Define canonical Request, Response, ExecutionContext, FuelMeter, EpochDeadline in edge-core.
  • Marshal inbound Request fields (method, URL, headers, body) into WASM guest linear memory using a stable binary ABI.
  • Invoke the guest fetch(req_ptr: i32, req_len: i32) -> i32 handler; unmarshal Response from the returned guest pointer.
  • Construct and populate ExecutionContext per invocation: deadline, fuel meter, subrequest count, tenant tag, trace ID.
  • Scope: edge-core (types), edge-runtime/src/marshal.rs (ABI), new edge-isolate/src/lifecycle.rs (invoke orchestration).
  • HandlerKind::Fetch is the only active entry point; Scheduled / Queue are declared but not dispatched.
Deliverable
  • invoke() round-trips a Request through a WAT worker that reads URL and returns Response { status: 200, body: url_bytes }.
  • ExecutionContext accessible inside host stub via caller.data().
  • edge-cli run --wasm echo.wasm --request '{"method":"GET","url":"https://example.com"}' prints {"status":200,"body":"https://example.com"}.

⬜ Phase 3 — Isolation Model

Objectives
  • Enforce exactly one fresh (or verified-reset) instance per request; no concurrent sharing of an Instance across requests.
  • Guarantee private linear memory: no two live instances alias the same memory region, regardless of allocator.
  • Prohibit shared mutable globals: no WASM import of mutable globals from the host; per-Store globals are Wasmtime-guaranteed.
  • Trap isolation: a WASM trap returns Err(Trap) to Rust; it does not panic the process; the faulting Instance is destroyed immediately.
  • Attach TenantId to every Isolate; propagate through every log, metric, and host call.
  • Introduce Isolate type, IsolateLifecycle, and TenantRegistry.
  • Uphold invariants I1, I2, I3, I4 (as precondition for Phase 5 reset semantics), I10.
Deliverable
  • edge-isolate crate with Isolate, IsolateLifecycle, TenantRegistry, and audit module.
  • Concurrent two-tenant test: tenant A traps; tenant B invocation succeeds; no cross-memory overlap detected.
  • Mutable global import rejected at module load.
  • cargo test --test isolation passes with 100 concurrent invocations.

⬜ Phase 4 — Resource Limits

Objectives
  • Enforce four orthogonal per-invocation limits: CPU (fuel or epoch), memory (max linear-memory pages), wall-clock (ms), subrequest count.
  • All limits sourced from ResourceLimits; resolved once per invocation at ExecutionContext creation; not adjustable after dispatch.
  • Every breach produces a deterministic, tenant-attributed Trap; no silent throttling.
  • FuelMeter and EpochDeadline are the canonical CPU accounting types (P7, I1, I8).
  • Memory cap enforced by Wasmtime's max_memory_size config (not runtime polling).
  • Subrequest cap enforced in edge-host before issuing any outbound fetch (I5).
Deliverable
  • edge-runtime enforces all four limits; trap on each breach.
  • edge-isolate destroys trapped instances immediately.
  • ExecutionContext carries accurate post-invocation accounting.
  • edge-cli bench reports fuel consumed and p99 wall-clock per worker.

⬜ Phase 5 — Cold-Start Minimization

Objectives
  • Drive cold-start time from module-compile + init + instantiate (often 10–100 ms) down to sub-millisecond via three mechanisms:
    1. InstancePool (warm pre-initialized instances per worker).
    2. PoolingAllocator (Wasmtime's pooling instance allocator to reuse memory slabs without OS round-trips).
    3. ColdStartSnapshot (serialize post-init memory + globals; restore by memcpy, skip init re-execution).
  • Reset-and-reuse decision: prefer snapshot-restore; fall back to fresh init only on snapshot miss or instance-count=0.
  • Enforce I4 (deterministic pre-request state) and I3 (trapped instances discarded, never reused).
  • Module lives in edge-coldstart; types InstancePool, WarmInstance, ColdStartSnapshot.
Deliverable
  • edge-coldstart crate compiles; InstancePool::acquire/release functional.
  • ColdStartSnapshot serializes + restores deterministically.
  • edge-cli bench reports cold-start breakdown: pool-hit %, snapshot-restore %, full-cold %.
  • Pool-hit path latency target: < 100 µs (P2).

⬜ Phase 6 — Host API Surface

Objectives
  • Expose a capability-scoped host API to WASM workers via edge-host: fetch (subrequest), kv_get, kv_put, cache_get, cache_put, header_get, env_get, log.
  • Deny-by-default: a worker accesses only bindings declared in WorkerScript.bindings (P9, I10).
  • All host calls enumerated as HostCall variants; dispatched through a single import resolver.
  • Subrequest count enforced before any outbound fetch (I5); KV/cache calls do not consume subrequest budget.
  • No ambient authority: host imports linked only to capability-checked wrappers.
Deliverable
  • edge-host crate: all eight host call families implemented and linked.
  • Worker can call fetch, kv_get/put, cache_get/put, header_get, env_get, log from WASM.
  • Capability denial returns structured error to guest (does not trap) unless capability config is invalid.
  • edge-cli run executes a worker with mocked host calls; log output visible in terminal.

⬜ Phase 11 — Cross-PoP KV/cache propagation
