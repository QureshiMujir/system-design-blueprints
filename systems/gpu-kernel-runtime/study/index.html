30. Mental Models & First Principles

MM1 — SIMT Is SIMD With Per-Lane Masking, Not True MIMD. Compressed insight: a warp executes one instruction stream; divergence doesn't create independent instruction streams, it masks lanes out of a shared one (Lindholm et al. 2008). Predicts: divergent code costs proportional to the number of distinct paths taken, not the number of threads. Bug class without it: assuming divergent branches parallelize for free. Resolving §: §15.

MM2 — Occupancy Is a Resource-Packing Problem, Not a Tuning Knob. Compressed insight: occupancy is the min() of three independent resource ceilings (registers, shared memory, warp slots) — you cannot "turn it up" without freeing one of the three (I15). Predicts: reducing register usage per thread can increase occupancy even with no other code change. Bug class without it: tuning block size blindly without checking which resource is binding. Resolving §: §15, §32.

MM3 — Warp Divergence Cost Is Proportional to Path Count, Not Thread Count. Compressed insight: a fully-divergent 32-lane warp taking 32 distinct paths costs roughly 32× a non-divergent warp — the branch, not the thread, is what serializes (Fung et al. 2007). Predicts: data-dependent branching on tid % 32 is far worse than on tid % 2. Bug class without it: writing "parallel" code that is actually 32-way-serialized under the hood. Resolving §: §15.

MM4 — Memory Coalescing Is a Warp-Collective Property, Not a Per-Thread Property. Compressed insight: bandwidth depends on the shape of a warp's 32 simultaneous addresses, not on any single thread's access pattern in isolation (I14). Predicts: transposing a matrix access pattern can change measured bandwidth by an order of magnitude with identical per-thread code. Bug class without it: optimizing a single thread's memory access and missing the warp-level pattern that actually matters. Resolving §: §14.

MM5 — A Barrier Is a Rendezvous, Not a Checkpoint. Compressed insight: bar.sync requires every participant to arrive — it is not a "mark progress" operation that tolerates stragglers (I3). Predicts: any code path that can skip the barrier for some threads deadlocks the whole block. Bug class without it: an early-return inside a conditional that some threads take, skipping a barrier the rest still need. Resolving §: §15.

MM6 — Latency Hiding via Oversubscription, Not Maximal Occupancy, Is the Real Goal. Compressed insight: Volkov (2010) showed that lower occupancy can outperform maximal occupancy when register pressure enables instruction-level parallelism (ILP) that substitutes for warp-level parallelism in hiding memory latency. Predicts: a kernel tuned to 100% occupancy is not automatically faster than one tuned to 50% with more ILP. Bug class without it: chasing the occupancy-calculator's maximum as an end in itself. Resolving §: §29, §21.

MM7 — Streams Model a Partial Order, Not a Free-For-All. Compressed insight: operations across streams have no ordering guarantee except where an explicit event dependency exists (P12) — it is a DAG, not chaos and not a total order. Predicts: code that "usually works" across streams without explicit events will eventually race. Bug class without it: assuming launch order implies completion order across streams. Resolving §: §17.

MM8 — The IR Is a Stable Contract, Never a Bypass Target. Compressed insight: every frontend and every backend agrees only on the canonical gpu-ir shape (P5) — bypassing it to "optimize" a special case reintroduces the exact drift-between-implementations failure MPT-class systems are known for. Predicts: a second frontend that talks directly to the scheduler will desynchronize from verifier guarantees. Bug class without it: an optimization shortcut that skips verification. Resolving §: §13, §20.

Glossary (§36) · 47 terms · site-wide glossary

SIMT
Single Instruction, Multiple Threads — a warp's lanes execute one instruction stream with per-lane masking (MM1)
Warp
The fixed-width (I1: 32-thread) lockstep execution group; the scheduler's fundamental unit
Block
A programmer-declared group of threads, composed of one or more warps, sharing shared memory
Grid
The full set of blocks launched by one kernel launch
Thread / Lane
A single scalar execution context within a warp
Active Mask
The per-warp bitmask (I2) marking which lanes currently execute the warp's instruction stream
Divergence
The event where lanes within a warp take different control-flow paths, requiring masking
Reconvergence
The point (the immediate dominator, I13) where diverged lanes resume executing together
Occupancy
The fraction of a simulated SM's warp-slot capacity actually utilized (I15)
Register File
Per-thread storage for scratch values; a bounded, budgeted resource (I4)
Shared Memory
Block-scoped, low-latency memory visible to all threads in a block
Global Memory
Device-wide memory visible to all threads in a grid
Constant Memory
Read-only, device-wide memory optimized for broadcast access
Local Memory
Thread-private memory backing register spill (distinct from registers themselves)
Memory Coalescing
The classification of a warp's collective memory access pattern for bandwidth accounting (I14, MM4)
Barrier / bar.sync
A block-scoped rendezvous point requiring all participants to arrive before any proceeds (I3, MM5)
Kernel
A compiled GPU-side function, the unit of launch
Kernel Launch
The act of dispatching a grid of a given kernel with a LaunchConfig
Stream
An ordered, asynchronous sequence of enqueued operations (P12)
Event
A synchronization primitive marking completion of prior work in a stream (I10)
Command Buffer
An encoded sequence of dispatch packets submitted as a unit
Command Queue
The ordered channel (ring buffer, ADR-22) through which dispatch packets are submitted
Dispatch Packet
A single encoded operation (launch, memcpy, event) submitted to a queue
DMA
Direct Memory Access — the simulated transfer engine moving data without host CPU involvement in the model
PTX
Parallel Thread Execution — NVIDIA's real virtual ISA that this project's IR takes inspiration from (§8)
SASS
NVIDIA's real hardware-specific machine ISA that PTX compiles to (out of scope, §35)
IR
Intermediate Representation — this project's canonical gpu-ir kernel representation (§11)
SSA
Static Single Assignment — the IR's register-definition discipline (ADR-07)
CFG
Control Flow Graph — the basic-block graph structure of a lowered kernel
Verifier
The IR-validation pass gating untrusted kernel input (I7, P6)
Dominator
A CFG node that lies on every path from entry to a given node; used for reconvergence (I13)
Emulator
The CPU-hosted instruction interpreter executing verified IR (§16)
Deterministic Stepping
The guarantee that identical inputs produce an identical execution trace (I11, P2)
Replay
Re-executing a captured trace to verify determinism (I11)
Differential Testing
Comparing two independent implementations/oracles on the same input to find divergence (P14)
Fixture
A named, versioned test input/expected-output pair used for conformance (§20)
Fuzzing
Randomized/mutation-based input generation to find crashes or invariant violations (§20)
Conformance
The property of passing 100% of the registered fixture corpus (§20, ADR-10)
Watchdog
A timeout-based mechanism detecting a stalled operation (barrier deadlock, FM-1)
Backpressure
Rejecting new work when a bounded resource (queue, allocator) is full, rather than growing unboundedly
Telemetry
Named counters/metrics surfaced per §7's Telemetry column and aggregated in §24
Occupancy Calculator
The formula/tool (real CUDA concept) this project's I15 model reproduces
Latency Hiding
Overlapping memory-access latency with other warps' computation via oversubscription (MM6)
Wavefront
AMD's analog to a warp, fixed at 64 lanes — deliberately distinct from this project's 32-lane warp (§31)
Unified Virtual Addressing (UVA)
A single address space spanning host and device pointers in the memory model (§14)
Active Lane
A thread currently included in a warp's active mask (as opposed to masked-off)
Immediate Dominator
The unique closest dominator of a CFG node; the basis for reconvergence-point computation (I13)
