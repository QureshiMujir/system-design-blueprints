⬜ Phase 0 — Workspace Bootstrap & IR Core §12

Objectives

Stand up the Cargo workspace, CI skeleton, and the correctness kernel: the gpu-ir register/instruction/CFG model and a minimal verifier stub — nothing that depends on the parser, scheduler, or emulator yet.

Deliverable

Compilable workspace with crates/gpu-ir (register/instruction/CFG model, reachable-block verifier stub) and crates/gpu-common, CI green, no parser/scheduler/ emulator logic yet.

Acceptance
  • cargo test -p gpu-ir passes with ≥ 20 property-test cases for CFG reachability.
  • CI pipeline completes in ≤ 5 minutes on GitHub Actions (ADR-11).
  • Zero clippy::all warnings on crates/gpu-ir and crates/gpu-common.
  • Fixture unreachable_block.json (hand-built CFG with a dead block) is flagged by the verifier stub.
Fixtures
Fixture Assertion
cfg_roundtrip.json hand-built CFG survives construction with correct successor edges
unreachable_block.json verifier stub flags a block with no predecessor from the entry block
Pitfalls
  • Modeling Instruction as a struct with an opcode tag instead of an exhaustive enum — defeats the compiler's exhaustiveness checking that later phases rely on (ADR-07).
  • Forgetting unsafe_code = "forbid" before FFI-adjacent crates are added later, leaving the lint gate ineffective.
  • Treating BlockId as a bare u32 without a newtype, inviting index/id confusion once gpu-scheduler (§15) introduces its own numeric ids.

⬜ Phase 1 — Kernel Parser & IR Lowering §13

Objectives

Implement the kernel-language front end (gpu-parser): lexer, recursive-descent parser per the §8 grammar, AST-to-IR lowering, and the full IR verifier (reachability, SSA reference validity, dominator-based reconvergence checking).

Deliverable

gpu-parser lexes and parses the §8 kernel grammar, lowers it into verified gpu-ir (reachability + SSA + reconvergence checks all enforced), with diagnostics on malformed input.

Acceptance
  • 100% of conformance/kernels/*.gpu fixtures parse and lower without verifier rejection.
  • Fixture invalid_branch.gpu (dangling branch target) is rejected with a diagnostic naming the offending line (I7).
  • Fixture ambiguous_reconverge.gpu (hand-crafted divergent branch with no unique immediate dominator) is rejected (I13).
  • Parser throughput ≥ 50,000 lines/sec on conformance/kernels/matmul.gpu (M9).
Fixtures
Fixture Assertion
vector_add.gpu parses and lowers to the expected CFG shape
invalid_branch.gpu verifier rejects dangling branch target (I7)
ambiguous_reconverge.gpu verifier rejects non-unique reconvergence point (I13)
state_space_mismatch.gpu verifier rejects ld.global on a shared-declared pointer
Pitfalls
  • Computing dominators with a naive iterative algorithm that silently produces a wrong tree on a CFG with multiple back-edges — verify against a known-correct fixture first.
  • Confusing "reachable from entry" with "on some execution path" — the verifier must check the former, which is a strictly cheaper and different property.
  • Lowering a loop construct without re-checking SSA dominance for values defined inside the loop and used after it.

⬜ Phase 2 — Device Memory Subsystem §14

Objectives

Implement gpu-memory: the device allocator, unified virtual address space, the five memory-space model (§8), host↔device transfer engine, and the coalescing-accounting model.

Deliverable

gpu-memory provides validated device allocation across all five memory spaces, host↔device transfer with a latency model, and a deterministic coalescing classifier.

Acceptance
  • Allocation/free round-trips correctly for ≥ 3 consecutive size-class boundaries (fixture alloc_boundary.json).
  • Fixture coalesced_vs_scattered.json: unit-stride access classified Coalesced, random-permutation access of the same size classified Scattered, on the same input data.
  • Simulated memcpy throughput ≥ 5 GB/s modeled (M4) on a 64 MiB transfer.
  • Out-of-bounds access fixture oob_access.json raises GpuError::InvalidAddress 100% of the time (I6).
Fixtures
Fixture Assertion
alloc.json allocation/free works across size classes
memcpy.json host<->device transfer preserves byte content
oob_access.json out-of-bounds access rejected (I6)
coalesced_vs_scattered.json classifier distinguishes access patterns (I14)
Pitfalls
  • Classifying coalescing per-thread instead of per-warp — the whole point of I14 is that it is a collective property of the warp's address set.
  • Allowing a device allocation to silently span two size classes without adjusting alignment guarantees.
  • Modeling transfer latency as a fixed constant instead of a function of transfer size — breaks the M4 throughput target at both very small and very large sizes.

⬜ Phase 3 — SIMT Grid Scheduler §15

Objectives

Implement gpu-scheduler: thread-block dispatch, warp formation, the active-mask divergence/reconvergence machinery, block-scoped barriers, and occupancy accounting.

Deliverable

A functional SIMT scheduler: correct warp formation, mask-accurate divergence handling, barrier rendezvous with deadlock detection, and occupancy accounting matching the CUDA occupancy-calculator model.

Acceptance
  • Fixture divergence_if_else.json: mask sequence for tid < 16 branch matches a hand-derived expected trace exactly, lane-for-lane.
  • Fixture occupancy_budget.json: a kernel using 64 registers/thread and 16 KiB shared memory yields the hand-computed occupancy value (cross-checked against §32).
  • Barrier deadlock fixture barrier_deadlock.json triggers the watchdog within the §4 2-second timeout and reports FM-1.
  • Warp-dispatch throughput ≥ 20M warp-instructions/sec/core (M2) on matmul.gpu.
Fixtures
Fixture Assertion
divergence_if_else.json mask sequence matches hand-derived trace (I2, I11)
occupancy_budget.json occupancy matches hand-computed value (I15)
barrier_deadlock.json watchdog fires within timeout (I3, FM-1)
mask_stack_balance.json every mask push has exactly one matching pop
Pitfalls
  • Restoring the wrong mask on reconvergence because the dominator target from §13 was computed on the AST-level CFG instead of the final lowered IR CFG.
  • Counting a thread that never reaches a bar.sync (e.g., trapped in a divergent branch with no reconvergence) as "arrived" — this is exactly FM-1's root cause.
  • Implementing occupancy as a sum instead of a min() across the three resource dimensions (I15) — always overestimates achievable occupancy.

⬜ Phase 4 — CPU SIMT Emulator Backend §16

Objectives

Implement gpu-emulator: the tree-walking instruction interpreter, per-thread register files, deterministic warp-instruction stepping, and trace capture/replay.

Deliverable

A runnable CPU SIMT emulator executing verified gpu-ir kernels lane-accurately, with deterministic stepping and trace replay.

Acceptance
  • matmul.gpu (16×16) produces output matching a hand-computed reference to bit-exact floating-point equality (fixture matmul_16x16.json).
  • reduction.gpu (sum of 1024 elements) matches the expected scalar exactly.
  • Replaying any conformance fixture's captured trace twice yields identical logs (I11) — fixture replay_determinism.json.
  • Interpreter throughput ≥ 20M warp-instructions/sec/core (M2, shared target with §15).
Fixtures
Fixture Assertion
matmul_16x16.json matrix-multiply output matches hand-computed reference
reduction_sum.json reduction output matches expected scalar
replay_determinism.json two replays of one trace are byte-identical (I11)
Pitfalls
  • Executing an inactive lane "for simplicity" and discarding its result afterward instead of skipping it — subtly wrong for any instruction with a side effect (store, register write visible to a later divergent path).
  • Nondeterministic warp-step order (e.g., iterating a HashMap of resident warps) breaking I11 silently — only a Vec or explicitly sorted iteration order is acceptable (P10).
  • Treating a floating-point reduction as associative for test-fixture purposes when the actual summation order matters for bit-exact comparison — fixtures must pin the exact reduction tree shape.

⬜ Phase 5 — Host Runtime API §17

Objectives

Implement gpu-runtime: the CUDA-like host API surface — launch(), stream creation and synchronization, event record/wait, and host-side synchronization primitives.

Deliverable

A CUDA-like host runtime API: launch validation, multi-stream async dispatch, event- based cross-stream synchronization, exhaustive error propagation.

Acceptance
  • Fixture streams_independent.json: two independent streams' kernels may interleave in completion order (no false ordering guarantee asserted).
  • Fixture event_dependency.json: stream B's kernel that event.wait()s on stream A's event never observes stream A's output before it is written (I10).
  • Launch overhead p50 ≤ 5 µs, p99 ≤ 25 µs (M1) measured over 10,000 launches.
  • 100% of invalid-launch-config fixtures return GpuError::InvalidLaunchConfig, zero panics (I8).
Fixtures
Fixture Assertion
streams_independent.json no false cross-stream ordering assumed
event_dependency.json event wait enforces correct completion order (I10)
invalid_launch_config.json oversized grid/block dims rejected cleanly (I8)
Pitfalls
  • Implementing stream.sync() as a fixed sleep-then-check instead of a real completion signal — breaks under load and violates I9's exact-order guarantee.
  • Allowing an event to signal "complete" based on enqueue time rather than actual completion of prior work — directly violates I10.
  • Silently clamping an oversized blockDim instead of rejecting it (I8) — hides a caller bug that would fail loudly on real hardware.

⬜ Phase 6 — Command Queue & Virtual Driver §18

Objectives

Implement gpu-driver: command buffers, the ring-buffer command queue, virtual-device submission, and the DMA abstraction with overlap detection.

Deliverable

A minimal virtual GPU driver: ordered command-queue submission, DMA overlap detection, and a hardware-independent device abstraction ready for a future backend (§35).

Acceptance
  • Fixture queue_order.json: 1,000 packets submitted to one queue complete in exact submission order (I9, I12).
  • Fixture dma_overlap_serialize.json: two overlapping transfers without a declared dependency execute serially, verified via a byte-level race fixture.
  • Queue-full backpressure fixture rejects the 4,097th packet on a 4,096-capacity queue (§4) with a documented error, not a panic.
Fixtures
Fixture Assertion
queue_order.json strict FIFO packet execution order (I9, I12)
dma_overlap_serialize.json overlapping DMA regions serialize correctly (I16)
queue_backpressure.json queue-full rejection is clean, not a panic
Pitfalls
  • Implementing the ring buffer with a size that silently wraps and overwrites unconsumed packets instead of applying backpressure.
  • Detecting DMA overlap by pointer equality instead of by interval overlap — misses partially-overlapping regions (I16).
  • Allowing queue submission from multiple host threads without a documented ordering rule, silently violating I9 under concurrent callers.

⬜ Phase 7 — Profiler & Instrumentation §19

Objectives

Implement gpu-profiler: timeline tracing, occupancy metrics, memory-bandwidth statistics, and export formats consumed by gpu-cli.

Deliverable

A working profiler surfacing timeline traces, occupancy metrics, and bandwidth statistics through both flamegraph and JSON export, at <1% measured overhead.

Acceptance
  • Fixture timeline_export.json: exported trace spans match the captured event count exactly (no dropped events).
  • Fixture occupancy_metric_match.json: profiler-reported occupancy equals §15's OccupancyReport.achieved_occupancy bit-for-bit.
  • Measured profiler overhead ≤ 1% of total kernel-launch wall time (M8) on matmul.gpu.
Fixtures
Fixture Assertion
timeline_export.json no dropped trace events
occupancy_metric_match.json profiler occupancy == scheduler occupancy (I15)
bandwidth_report.json reported bandwidth matches §14 coalescing classification
Pitfalls
  • Sampling-based tracing that silently drops events under high warp-instruction throughput — must be exhaustive for conformance runs, sampled only for production-scale benchmarks (documented distinction).
  • Clock-drift across a long trace causing span durations to appear negative — use a monotonic clock source exclusively.
  • Excessive per-event heap allocation dominating the very overhead the profiler is supposed to measure (self-defeating instrumentation).

⬜ Phase 8 — Conformance, Fuzzing & Differential Testing §20

Objectives

Build the full differential-conformance and fuzzing harness: malformed-kernel fuzzing, IR-validation fuzzing, command-queue fuzzing, randomized-scheduler testing, and replay- based regression testing across every prior phase's fixtures.

Deliverable

A validated runtime: full fixture-corpus regression suite, four coordinated fuzz targets, differential testing wherever a second oracle exists, and CI gating on all of the above.

Acceptance
  • 100% of Phases 0–7 fixtures pass under the consolidated runner.
  • Each of the four fuzz targets runs ≥ 1M iterations in nightly CI with zero crashes on the frozen corpus (fixture fuzz_stability.json tracks iteration count).
  • Any fuzz-discovered crash produces a minimized reproducer ≤ 200 IR instructions.
  • Replay-regression suite (I11) has zero mismatches across 3 consecutive nightly runs.
Fixtures
Fixture Assertion
fuzz_ir_verifier verifier never panics, never accepts a structurally invalid kernel
fuzz_scheduler scheduler never panics under randomized divergence patterns
fuzz_queue queue never corrupts order under randomized submission interleavings
replay_regression.json zero I11 mismatches across the full corpus
Pitfalls
  • Treating "the fuzzer found nothing in an hour" as evidence of correctness rather than absence of a counterexample within the time budget — document coverage limits explicitly (§26).
  • Minimization that produces a "minimal" reproducer that no longer triggers the original bug (a common fuzzing-harness correctness bug in itself).
  • Nondeterministic fuzz-seed handling that makes a "fixed" bug's regression test flaky instead of deterministic.

⬜ Phase 9 — Performance Engineering & Hardware-Readiness Boundary §21

Objectives

Close out the M1–M12 performance targets (§28), formalize the hardware-independence boundary (P8, ADR-21) at which a real backend could attach, and document the exact handoff contract for every PhaseDeferred("§35") item.

Deliverable

A performance-validated runtime meeting every §28 target, with a documented, trait-bounded hardware-readiness boundary and a formal deferred-features handoff.

Acceptance
  • All M1–M12 targets in §28 met or explicitly re-baselined with documented rationale.
  • Zero conformance regressions (§20) introduced by any Phase 9 optimization (P14 gate).
  • Hardware-readiness handoff document reviewed and merged, covering 100% of §35's registered deferred features.
  • v1.0.0 tag cut with a green §20 fixture corpus and green M1–M12 benchmark suite.
Fixtures
Fixture Assertion
perf_regression_gate.json no §20 fixture regresses after any Phase 9 optimization
occupancy_vs_perf.json measured throughput trend matches Volkov's (2010) lower-occupancy finding qualitatively
Pitfalls
  • Chasing a raw throughput number (M2) by relaxing a §15/§16 correctness check — directly forbidden by P1/P14.
  • Declaring "hardware-ready" without a concrete trait-conformance contract, leaving a future implementer to reverse-engineer the boundary from source.
  • Treating higher measured occupancy as unconditionally better performance, ignoring Volkov's (2010) counter-example regime (MM6).
