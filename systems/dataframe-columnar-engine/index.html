3.2 Box-by-box responsibilities

  • Reader (cx-io). Decodes a source into Arrow RecordBatches. CSV: sample-based schema inference, typed parse, quoting/escaping. Parquet: read Thrift footer, select row groups via statistics, decode pages (RLE/bit-pack/delta/dictionary), reassemble columns with validity. IPC: parse Flatbuffers schema + record-batch messages, wrap buffers zero-copy. Null semantics: producer sets validity bit per slot; reader never fabricates values for null slots. Parallelism boundary: one row group / file split per rayon task.
  • Columnar core (cx-buffer + cx-array). Owns the canonical Arrow memory layout: 64-byte-aligned, immutable, Arc-shared Buffers; ArrayData{dtype,len,null_count,buffers,child_data}. Every array kind (primitive, boolean, utf8/binary, list, struct, dictionary, null) is a typed view over ArrayData. Slicing adjusts (offset,len) without copying. Mutation never happens in place — builders produce new arrays. This is the trust + zero-copy boundary: buffers crossing FFI are the same bytes.
  • Eager path (cx-frame + cx-compute). Series = named ChunkedArray; DataFrame = Vec<Series> + Schema. Operations call kernels directly and materialize immediately. Used for interactive/REPL work and as the building block under the lazy executor. Null semantics propagate per kernel; concurrency: arrays are Send+Sync, kernels are pure functions of their inputs.
  • Lazy path — Expr/Logical (cx-expr + cx-plan). A LazyFrame records intent as Expr trees over LogicalPlan nodes (Scan/Projection/Filter/Aggregate/Join/Sort/Limit/Distinct/Union). Nothing executes until collect(). Schema is resolved + validated at build time; type coercion is explicit. This is the semantics boundary: the plan is the source of truth for what the query means.
  • Optimizer (cx-optimize). Rule-based rewrites on the LogicalPlan: predicate pushdown (filters toward scans), projection pushdown (read fewer columns), slice/limit pushdown, common-subexpression elimination, constant folding, type coercion insertion. Each rule is LogicalPlan → LogicalPlan, schema-preserving, idempotent where possible. Output is an optimized logical plan.
  • Physical plan + executor (cx-plan + cx-exec). The optimized logical plan lowers to PhysicalPlan (ExecNode trait, execute() -> RecordBatchStream): ScanExec, FilterExec, ProjectExec, HashAggExec, HashJoinExec, SortExec, SortMergeJoinExec, LimitExec. Execution is morsel-driven: the source is partitioned into morsels, rayon work-steals across cores, operators are batch-at-a-time, and results flow as a RecordBatch stream. This is the parallelism boundary — no global lock in the hot path; only the shared hash table for build, partitioned to avoid contention.
  • Sink (cx-io + cx-frame). Streams RecordBatches into a collected DataFrame or writes Parquet/CSV/IPC. Deterministic ordering is enforced only where requested (sort, or maintain_order).
  • Side services. MemoryPool (cx-memory) accounts every allocation against a per-query budget and triggers spill when reservations exceed the threshold. Schema/type system (cx-datatype) is consulted at every plan/kernel boundary. Dictionary encoder shares low-cardinality string data. cx-ffi exports/imports buffers across the Arrow C Data Interface ABI.

8. Domain Model

8.1 Arrow memory layout (general)

Every array is a typed view over ArrayData:

ArrayData {
  data_type : DataType
  len       : usize          // logical element count
  null_count: usize          // cleared validity bits
  offset    : usize          // logical offset into buffers (zero-copy slice)
  buffers   : Vec<Buffer>    // 0..N data/offset buffers, layout depends on dtype
  child_data: Vec<ArrayData> // nested children (List, Struct, ...)
}
  • Validity bitmap: 1 bit per slot, LSB-numbered (slot i → byte i/8, bit i%8); bit set = valid, clear = null. Omitted iff null_count == 0.
  • Buffers are 64-byte aligned, immutable, Arc-shared Bytes. offset lets a slice reuse parent buffers.
  • Layout per kind (number of buffers):
    • Primitive (Int/UInt/Float/Bool-as-bits/temporal): [validity?, data] — fixed-width values (Boolean packs 1 bit/value).
    • Variable binary/string (Utf8,Binary): [validity?, offsets, data] — offsets: i32 (Large: i64), value i = data[offsets[i]..offsets[i+1]].
    • List (List<T>): [validity?, offsets] + child T array; element i = child[offsets[i]..offsets[i+1]].
    • Struct: [validity?] + one child array per field, all length == parent len.
    • Dictionary: keys (a primitive index array) + values (the dictionary, any array).
    • Null: zero buffers; len only; all slots null.

8.2 Byte diagrams

Int32Array length 5, values [10, 20, NULL, 40, 50]:

validity bitmap (LSB0): bit0=1 bit1=1 bit2=0 bit3=1 bit4=1  -> byte 0 = 0b00011011 = 0x1B
  (bits 5..63 are padding=0; bitmap buffer length rounded up to 64 bytes)
data buffer (i32 LE, 4 bytes each, 64-byte aligned, slot 2 value undefined):
  offset  0:  0A 00 00 00   (=10)
  offset  4:  14 00 00 00   (=20)
  offset  8:  ?? ?? ?? ??   (NULL slot — bytes undefined, NOT read)
  offset 12:  28 00 00 00   (=40)
  offset 16:  32 00 00 00   (=50)
null_count = 1

Utf8Array length 4, values ["arrow","",NULL,"db"]:

validity bitmap: bit0=1 bit1=1 bit2=0 bit3=1 -> 0b1011 = 0x0B
offsets buffer (i32, len = 5 = len+1), monotonic non-decreasing:
  [ 0, 5, 5, 5, 7 ]
   ^arrow(0..5) ^""(5..5 empty) ^NULL(5..5, ignored) ^"db"(5..7)
data buffer (UTF-8 bytes, contiguous): 'a''r''r''o''w''d''b'  (len 7)
  note: NULL slot still consumes an offset entry; its [start,end) is well-formed (here empty)

List<Int32> length 3, values [[1,2],[],NULL]: (NULL is the outer list, distinct from [])

parent validity: bit0=1 bit1=1 bit2=0 -> 0b011 = 0x03
parent offsets (i32, len 4): [0, 2, 2, 2]
   list0 = child[0..2] = [1,2]; list1 = child[2..2] = []; list2 = NULL (offsets ignored)
child Int32Array (len 2): data = [1, 2], no nulls

Dictionary<Int8, Utf8> length 5, logical ["red","green","red",NULL,"green"]:

keys = Int8Array  len 5, validity bit3=0 (NULL): values [0, 1, 0, ??, 1]   (?? = null key slot)

decode: key 0->"red", 1->"green"; key slot 3 is null -> logical NULL (dictionary not indexed)
invariant I5: every non-null key < values.len()==2

8.4 Three-valued (Kleene) logic

U = NULL/unknown. Comparison of anything with NULL → U. Boolean ops:

AND | T U F        OR  | T U F        NOT
----+------        ----+------        ---
 T  | T U F         T  | T T T         T -> F
 U  | U U F         U  | T U U         U -> U
 F  | F F F         F  | T U F         F -> T

Operational consequences: WHERE keeps only rows where predicate is T (U and F are dropped). is_null(x) and is_not_null(x) are total (never return U). fill_null(x, v) replaces U with a value. x == x is U when x is NULL (not T).

8.7 Expression grammar (EBNF)

Expr      = Column | Literal | Binary | Unary | Func | When | Window | Agg | Cast | Alias ;
Column    = "col" "(" name ")" | "*" ;
Literal   = "lit" "(" scalar ")" ;
Binary    = Expr binop Expr ;
binop     = "+" | "-" | "*" | "/" | "%" | "==" | "!=" | "<" | "<=" | ">" | ">="
          | "and" | "or" | "xor" ;
Unary     = ( "-" | "not" | "is_null" | "is_not_null" ) Expr ;
Func      = ident "(" [ Expr { "," Expr } ] ")" ;        (* scalar: abs, lower, strptime, ... *)
Agg       = ( "sum" | "min" | "max" | "mean" | "count" | "n_unique" | "first" | "last"
            | "var" | "std" ) "(" Expr ")" ;
When      = "when" "(" Expr ")" ".then" "(" Expr ")" { ".when" "(" Expr ")" ".then" "(" Expr ")" }
            ".otherwise" "(" Expr ")" ;
Window    = Agg ".over" "(" [ Expr { "," Expr } ] ")" ;  (* partition keys *)
Cast      = Expr ".cast" "(" DataType ")" ;
Alias     = Expr ".alias" "(" name ")" ;

Example: col("a").gt(lit(10)).and(col("b").is_not_null()) ; sum(col("c")).over(col("region")).alias("region_total").

8.12 Worked example — lazy query, pushdown, execution

Query: scan_csv("t.csv").filter(col("a").gt(lit(10))).group_by(col("b")).agg([sum(col("c"))]).collect()

LOGICAL (as built):
  Aggregate keys=[b] aggs=[sum(c)]
    Filter a > 10
      Projection *            (implicit)
        Scan t.csv (all cols a,b,c,d,e)

AFTER predicate + projection pushdown:
  Aggregate keys=[b] aggs=[sum(c)]
    Scan t.csv  projection=[a,b,c]  predicate=(a>10)
  (cols d,e never read; a>10 evaluated during decode; 'a' dropped after filter)

PHYSICAL:
  HashAggExec keys=[b] aggs=[sum(c)]
    ScanExec t.csv proj=[a,b,c] pred=(a>10)

EXECUTION (numbers illustrative): file = 10M rows, 5 cols.
  - ScanExec splits CSV into 160 morsels (~64Ki rows each); rayon runs across 8 cores.
  - Each morsel decodes only a,b,c; applies a>10 → ~30% pass (3M rows survive).
  - HashAggExec: each worker builds a local hash table b→running_sum(c) (partitioned by hash(b));
    workers merge partitions; ~12k distinct b groups -> 12k output rows.
  - Result streamed as RecordBatch(es); collect() concatenates into a DataFrame.

8.13 Worked example — hash join with nulls

left.join(right, on="k", how="inner")
  - Build phase on 'right' (smaller): hash(k) -> bucket; rows with k==NULL are NOT inserted
    (SQL: NULL never equals NULL in an equi-join).
  - Probe phase on 'left': for each row, hash(k); k==NULL rows produce no match (dropped for inner).
  - left semi: emit left row if >=1 match.  left anti: emit left row if 0 matches (incl. NULL keys
    on the left -> always emitted, since NULL matches nothing).
  - Output schema = left cols ++ right cols (duplicate names suffixed _right).

8.14 Worked example — Parquet row-group skip via statistics

SELECT * WHERE ts >= 2026-01-01
File has 8 row groups, each ColumnChunk for 'ts' carries Statistics{min,max,null_count}.
  RG0 min=2025-01-01 max=2025-06-30  -> max < predicate -> SKIP (no pages read)
  RG3 min=2025-12-15 max=2026-02-01  -> overlaps        -> READ + re-filter rows
  RG7 min=2026-03-01 max=2026-04-01  -> fully inside    -> READ (no per-row filter needed)
Result: 5 of 8 row groups skipped; I/O ~ 3/8 of full scan.
Caveat: stats may be absent or wrong for a column -> fall back to reading + filtering (never skip on missing stats).

Design principles (§6)

  • P1 — Columnar + vectorized over row-at-a-time. Operate on contiguous arrays of one type, one kernel call per batch. Tradeoff: batch buffers cost memory; pipelining is coarser. Operational: SIMD + cache locality give the throughput in §4. Violation: per-row trait dispatch (dyn per element) collapses scan throughput 10–50×; the engine becomes a slow interpreter.
  • P2 — Validity bitmap + three-valued (Kleene) logic everywhere. A null slot is unknown, not a value. Every kernel consumes and produces a validity bitmap; boolean ops use Kleene tables. Tradeoff: bitmap maintenance per kernel. Operational: COUNT(col) ≠ COUNT(*); sum skips nulls. Violation: reading a null slot's bytes as data, or null = null → true, silently corrupts every downstream result.
  • P3 — Zero-copy, immutable buffers. Buffers are Arc-shared and never mutated; slicing adjusts (offset,len); "mutation" builds a new array. Tradeoff: copy-on-write allocations. Operational: arrays are freely Send+Sync; FFI export is a pointer hand-off. Violation: in-place mutation of a shared buffer is a data race and a correctness bug across views.
  • P4 — Late materialization. Carry a selection (mask/indices) and decode/gather columns last, only for surviving rows. Tradeoff: indirection on access. Operational: a 1%-selective filter touches ~1% of the output columns' bytes. Violation: early materialization makes a selective query pay full decode cost on discarded rows.
  • P5 — Push work down to the scan. Predicates and projections move toward the source so fewer bytes are read/decoded; Parquet stats skip row groups. Tradeoff: optimizer complexity; pushdown must be semantics-preserving. Operational: the cheapest row is the one never read. Violation: reading all columns then projecting wastes I/O and memory bandwidth.
  • P6 — Morsel-driven parallelism, no global sync in the hot path. Work is split into morsels; rayon work-steals; shared state (hash tables) is partitioned. Tradeoff: scheduling overhead; NUMA awareness needed. Operational: near-linear scaling until a shared structure becomes the bottleneck. Violation: a global mutex or single output queue serializes the engine and kills scaling.
  • P7 — Type safety + explicit coercion. No silent lossy casts; coercion is an explicit optimizer pass following a documented promotion lattice. Tradeoff: the user must opt into narrowing casts. Operational: Int32 + Float64 → Float64 is explicit and predictable. Violation: implicit Float64→Int32 truncation produces wrong numbers no one asked for.
  • P8 — Bounded memory + spill. Every allocation is accounted against a per-query budget; agg/sort/join spill to disk above threshold. Tradeoff: spill is slow; accounting has overhead. Operational: a big group-by degrades to disk instead of OOM-killing the process. Violation: unaccounted allocation → OOM under skew, taking down the host.
  • P9 — Deterministic results when requested. Parallel execution may reorder rows; sort and maintain_order impose a stable, reproducible order. Tradeoff: maintaining order costs a sort/merge. Operational: EXPLAIN ANALYZE and golden-file tests need reproducibility. Violation: non-deterministic ordering breaks differential tests and confuses users comparing runs.
  • P10 — Schema is law; kernels are null-aware + branchless. Schemas are validated at every plan/IO boundary; kernels avoid per-element branches (use masks/select). Tradeoff: validation cost at boundaries; branchless code is harder to write. Operational: a malformed file is rejected at the edge, not mid-execution; kernels vectorize. Violation: trusting an unvalidated schema or branchy null handling causes mid-query panics and pipeline stalls.
