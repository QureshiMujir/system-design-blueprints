  5. The hash group-by on a 500 M row table with 10 M distinct keys is running on 16 cores. One partition receives 80% of the keys due to hash skew. At what point could the result be incorrect if the partition boundary is miscomputed? (§7 I11; §8.11; Phase 6 §18; Phase 13 §25; ADR-22)

  8. cast(Utf8["1","2","nan"], Float64, safe) must produce [1.0, 2.0, NULL] not [1.0, 2.0, NaN]. Which ADR governs the null-vs-NaN distinction, and where in the cast kernel is the policy boundary? What would break if NaN were used instead of NULL? (ADR-05; §8.4; §8.5; Phase 3 §15)
  9. A sort over a ChunkedArray with 1000 chunks requires a global sort_indices. The indices reference slots across all 1000 chunks. After sort_indices returns, take must gather from the right chunk.   10. The PredicatePushdown rule pushes a filter through a Join. The predicate references a column from the right side of a left join.   11. MemoryPool::try_reserve uses AtomicUsize with what memory ordering? If Relaxed is used, under what contention pattern does the 5% drift bound (I11) break, and what is the minimum ordering that prevents over-commitment? (§7 I11; §11.6; Phase 0 §12; Phase 13 §25; ADR-21)
  12. A user calls df.group_by("k").agg([sum("v")]) where v is Float64 and contains NaN. Does NaN contribute to the sum or is it treated as null? Which invariant and which kernel sub-section govern this? How does the behavior differ from DuckDB's default? (§8.4; §8.5; I2; I8; Phase 6 §18)

Mental Models & First Principles

  1. MM1 — Columnar layout aligns the access pattern with the arithmetic. Predicts: which queries benefit from column projection; when a scan reads 1/N of the data. Without it: you read all columns for every query and burn memory bandwidth on fields that are never used. Applied: §4 (cached-column scan ≥ 5 GB/s/core), §6 Principle 1, Phase 1 (§13), Phase 4 (§16).

  2. MM2 — The validity bitmap is a separate physical channel. Predicts: which operations can be vectorized without branching; when Kleene logic diverges from two-valued logic. Without it: you write if is_null(i) { ... } per element, defeating the pipeline; or you collapse three-valued to two-valued and silently corrupt WHERE-clause results. Applied: §8.4, §8.5, I2, Phase 1 (§13), Phase 3 (§15).

  3. MM3 — Late materialization: carry a ticket, pay at the door. Predicts: when a selective filter saves the majority of decode cost; when take is cheaper than early projection. Without it: a 1%-selective filter pays to decode 100% of the target columns before discarding 99%. Applied: §6 Principle 4, §8.11 FilterExec, Phase 4 (§16), Phase 7 (§19).

  4. MM4 — The hash table, not the arithmetic, is the bottleneck in aggregation and joins. Predicts: when partitioning buys scalability; when probe locality dominates throughput; when the table must spill. Without it: you optimize the accumulator function while the probe loop stalls on cache misses. Applied: §4 (group-by ≥ 50 M rows/s), §8.11, Phase 6 (§18), Phase 7 (§19).

  5. MM5 — Pushdown is free I/O reduction; every byte not read is not decoded. Predicts: which optimizer rules have the largest end-to-end impact; when Parquet stats skip row groups vs. must read them. Without it: the optimizer skips predicate/projection pushdown and reads every column of every row group before filtering. Applied: §8.10, §6 Principle 5, Phase 10 (§22), Phase 12 (§24).

  6. MM6 — Morsel granularity governs the parallelism-vs-locality tradeoff. Predicts: when morsels are too large (one core dominates, poor load balance) vs. too small (dispatch overhead dominates). Without it: the executor serializes on skewed morsels or thrashes with too-fine scheduling. Applied: §4 (default 64Ki rows), §6 Principle 6, Phase 11 (§23), ADR-06.

  7. MM7 — Zero-copy sharing via Arc + (offset, len) is the correctness boundary for immutability. Predicts: which operations are safe to parallelize without locks; when mutation would cause a data race across views. Without it: an in-place mutation of a shared buffer corrupts the other holder's view and breaks FFI safety. Applied: §6 Principle 3, §11.1, I13, Phase 0 (§12), Phase 13 (§25).

  8. MM8 — Schema is law: validate at edges, trust in the interior. Predicts: where to place validation checks so that interior kernels can skip them; when a type mismatch is caught early vs. causing a mid-execution panic. Without it: unvalidated arrays propagate corrupt offsets or wrong null_counts through the pipeline until they produce a silent wrong result or an OOB read. Applied: §7 I1/I3/I5/I10, Phase 1 (§13), Phase 9 (§21), ADR-23.

  9. MM9 — Dictionary encoding trades index-space for value-space at a cardinality threshold. Predicts: when dictionary encoding helps (low distinct/total) vs. hurts (high-cardinality wastes the indices buffer); when to decode eagerly vs. operate on keys. Applied: §4 (threshold: distinct/total < 0.5 and cardinality ≤ 2^20), ADR-09, Phase 2 (§14), Phase 5 (§17).

  10. MM10 — The rule-based optimizer is correct by construction; the cost-based optimizer is correct by measurement. Predicts: which rewrites are safe to apply unconditionally (semantics-preserving identities) vs. which require cardinality estimates (join reordering). Without it: you either under-optimize (no pushdown) or over-optimize (a semantics-changing rewrite applied without proof of equivalence). Applied: §8.10, Phase 10 (§22), ADR-11, Deferred Features Register (CBO).

Glossary · 48 terms · site-wide glossary

Columnar layout
values of one column stored contiguously (struct-of-arrays); the basis for compression, SIMD, and column projection
Row vs column
row store keeps a whole tuple together (OLTP-friendly); column store keeps a column together (OLAP-friendly: scan few columns of many rows)
Arrow
the standardized in-memory columnar format (layout + IPC + C Data Interface) that lets engines share buffers zero-copy
Validity bitmap
1 bit per slot, LSB0; set = valid, clear = null; omitted when null_count==0
null_count
cached count of cleared validity bits; enables an all-valid fast path
Offsets buffer
for Utf8/Binary/List: len+1 monotonic offsets; value i = data[offsets[i]..offsets[i+1]]
RecordBatch
a set of equal-length columns + schema; the vectorization unit (default 64Ki rows)
ChunkedArray
a logical column made of multiple physical array chunks (avoids rechunk copies)
Dictionary encoding
store distinct values once + an integer index per slot; helps low-cardinality columns
Zero-copy
sharing buffers via Arc + (offset,len) slicing without copying bytes; key for FFI and slices
Three-valued (Kleene) logic
boolean logic with T/F/Unknown(null); null AND false = false, null AND true = null
Vectorized execution
operate on batches of values per operator call (amortize dispatch, fit cache); MonetDB/X100 model
Morsel-driven
split work into small morsels, work-steal across cores with NUMA awareness (Leis 2014)
Late materialization
carry a selection (mask/indices) and decode/gather columns last, only for surviving rows
Predicate pushdown
move filters toward the scan so fewer rows/bytes are read (Parquet stats skip row groups)
Projection pushdown
read only the columns a query needs
Logical plan
the declarative tree of relational operators (what the query means)
Physical plan
the executable tree of chosen algorithms (ExecNodes)
Volcano / iterator model
tuple-at-a-time next() pull execution (Graefe); the slow design vectorization replaces
Hash aggregate
group-by via a hash table key→accumulator; partitioned for parallelism
Hash join (build/probe)
build a hash table on the smaller side, probe with the larger
Sort-merge join
sort both inputs on the key, then merge; used for pre-sorted or range joins
Semi / anti join
semi: left rows with ≥1 match; anti: left rows with 0 matches
Expression (Expr)
a tree describing a column computation (col, lit, binops, functions, agg, when/then, window)
Window function
an aggregate computed over a partition and broadcast back per row (agg.over(keys))
Lazy vs eager
lazy records a plan and optimizes before executing (collect); eager executes each op immediately
Optimizer rule
a semantics-preserving LogicalPlan→LogicalPlan rewrite applied to fixed point
CSE
common-subexpression elimination: hoist a repeated pure sub-expr so it is computed once
Constant folding
evaluate literal-only sub-expressions at plan time
Type coercion
inserting explicit casts per a promotion lattice so operands/keys share a type
Parquet
on-disk columnar file format: row groups → column chunks → pages, with statistics + encodings
Row group
a horizontal slice of a Parquet file; the unit of predicate-based skipping and parallel read
Column chunk
one column's data within a row group
Page
the smallest Parquet read/encode/compress unit within a column chunk
RLE
run-length encoding: store (value,count) runs; great for repeated/sorted data
Bit-packing
pack small integers using only the needed bits (often hybrid with RLE)
Delta encoding
store differences between consecutive values (DELTA_BINARY_PACKED)
Statistics (min/max)
per-column-chunk [min,max]+null_count used to skip row groups
Dremel / rep-def levels
repetition/definition levels encoding nested + nullable structure in Parquet (Melnik 2010)
IPC
Arrow Inter-Process Communication: stream/file message format using Flatbuffers metadata
Flatbuffers
zero-copy serialization used for Arrow IPC schema + message metadata
C Data Interface
the Arrow #[repr(C)] ABI (ArrowSchema/ArrowArray + release callback) for zero-copy cross-language sharing
Spill
write operator state (agg/sort/join partitions) to disk when over the memory budget
NUMA
non-uniform memory access; schedule work near its memory to avoid cross-socket latency
SIMD
single-instruction multiple-data; one instruction over a lane vector (the heart of kernel speed)
Selectivity
the fraction of rows a predicate keeps; drives filter/pushdown cost
Grace hash join
a hash join that partitions both sides to disk when the build side exceeds memory
Reservation
an RAII handle accounting reserved bytes against the MemoryPool; releases on drop
