32. Mental Models & First Principles

MM1. The write barrier is the whole secret of both generational and concurrent GC — it is the mutator telling the collector "I just changed the object graph in a way you need to know about," and every advanced collector is really a barrier design (GC Handbook).

MM2. Generational collection works because it exploits a statistical fact — most objects die young — so it does the least work where the most garbage is (Ungar 1984).

MM3. Concurrent GC is a race between the marker and the mutator's allocator, and the tri-color invariant is the referee that keeps the mutator from hiding a live object behind the marker's back (Dijkstra 1978).

MM4. Pauses, not total time, are the product — a collector that is faster on average but pauses 200 ms is worse for an interactive application than a slower one that never pauses over 2 ms (P4).

MM5. A card table is a coarse rumor and a precise remembered set is a verified fact — both are true enough to be useful, and the choice between them is a bet about how much precision the mutation rate can afford to pay for (P9).

MM6. Copying collection is compaction for free — the act of collecting garbage and the act of defragmenting live objects are, in the young generation, literally the same pass (Cheney 1970).

MM7. Floating garbage is not a bug, it is rent — the price paid for letting the mutator keep running instead of stopping it to get a perfectly tight answer (P7, Yuasa 1990).

MM8. A forwarding pointer is a promise: "I used to live here, but I moved, and here is where" — every reader of that promise must either honor it (read barrier) or never need to be told (STW copy under a safepoint).

MM9. Safepoints are the seam between two different concurrency models — cooperative (mutator threads) and independent (collector threads) — and the seam has to be crossed cleanly or nothing downstream of it can be trusted.

MM10. Tuning a collector is not one knob, it is a system of coupled inequalities (§8.6, §34) — nursery size, tenuring threshold, and mark-worker count all trade against each other, and optimizing one in isolation moves the bottleneck rather than removing it.

38. Glossary

  • Garbage collection — automatic reclamation of memory occupied by objects no longer reachable by the program.
  • Tracing GC — a GC family that determines liveness by traversing the object graph from roots, as opposed to reference counting.
  • Reference counting — a GC family that tracks a per-object count of incoming references, freeing immediately at zero (§36).
  • Mutator — the application thread(s) that allocate and mutate the object graph, as distinguished from the collector.
  • Collector — the subsystem (marker, scavenger, sweeper, compactor) responsible for reclaiming garbage.
  • Reachability — the property of an object being transitively referenced from a root.
  • Root set — the set of directly-known live references: stack slots, registers, globals, handle tables (§8.8).
  • Safepoint — a program point at which every mutator thread's state is GC-legible, enabling a consistent root snapshot (I7).
  • Generational hypothesis — the empirical observation that most objects die young (Ungar 1984), motivating generational collection (P1).
  • Nursery / young generation — the small heap region holding newly allocated objects, collected frequently.
  • Old generation — the heap region holding objects that survived enough nursery cycles to be promoted.
  • Survivor space — an intermediate young-generation space (from/to pair) used during a copying scavenge.
  • Minor collection — a collection of the young generation only (also: scavenge).
  • Major collection — a collection of the old generation (mark, sweep, optionally compact).
  • Scavenge — a copying collection of the young generation (Cheney-style).
  • Copying collection — a GC strategy that relocates live objects, leaving dead space implicitly reclaimed.
  • Cheney's algorithm — the classic breadth-first, two-pointer (scan/allocation) copying-collection algorithm (Cheney 1970).
  • From-space / to-space — the two survivor regions swapped each scavenge cycle.
  • Promotion / tenuring — moving a surviving young object into the old generation, typically after an age threshold.
  • Mark-sweep — a tracing GC strategy that marks live objects then reclaims (sweeps) the rest without moving anything.
  • Mark-compact — mark-sweep extended with relocation of survivors to reduce fragmentation.
  • Tri-color abstraction — the White/Gray/Black object-coloring model used to make marking incrementally observable (Dijkstra et al. 1978).
  • White — a color meaning "not yet proven reachable" (candidate garbage).
  • Gray — a color meaning "known reachable, not yet fully scanned."
  • Black — a color meaning "known reachable and fully scanned."
  • Tri-color invariant — the safety property that no Black object may reference a White object without a Gray intermediary (I2).
  • Write barrier — mutator-side instrumentation on pointer stores that records information the collector needs (generational or concurrent-marking correctness, P2).
  • Read barrier — mutator-side instrumentation on pointer loads, needed for concurrent compaction (P5, ADR-11).
  • Card table — a coarse-grained, per-region dirty bitmap used as the generational write barrier's record (ADR-07).
  • Remembered set — a precise or semi-precise record of inter-generational (or inter-region) references (I3).
  • SATB (Snapshot-At-The-Beginning) — a concurrent-marking barrier that logs the pre-write value of an overwritten reference (Yuasa 1990).
  • Incremental-update (Dijkstra barrier) — a concurrent-marking barrier that grays the newly-stored reference at write time.
  • Concurrent marking — tracing the object graph while the mutator continues to run and mutate (P3).
  • Floating garbage — an object that becomes unreachable after being marked Black, surviving to the next cycle (P7).
  • Forwarding pointer — an indirection left in a relocated object's old location, pointing to its new location (I9).
  • Brooks pointer — a specific forwarding-pointer implementation storing the indirection as an extra header word, read on every access (Shenandoah).
  • Colored pointers — an alternative forwarding encoding storing relocation state directly in unused pointer bits (ZGC).
  • Region-based GC — a design partitioning the heap into many small, independently collectible regions (G1, ZGC, Shenandoah, C4).
  • TLAB (Thread-Local Allocation Buffer) — a per-thread slice of the nursery enabling synchronization-free bump-pointer allocation.
  • Bump-pointer allocation — allocating by advancing a cursor through contiguous free space, the fastest allocation strategy, only viable with moving/copying collection.
  • Pause time — the duration the mutator is stopped for a collection-related reason.
  • Throughput — the fraction of total CPU time available to the mutator (as opposed to spent on collection).
  • Stop-the-world (STW) — a collection phase during which all mutator threads are halted.
  • Concurrent collection — a collection phase during which the mutator continues to run alongside the collector.
  • Pacing controller — the component enforcing the mark-rate-vs-allocation-rate race constraint (§8.6, I5).
  • Termination detection — the protocol proving a concurrent-mark work-stealing pool has exhausted all reachable work (ADR-16).
  • Finalization — a post-mortem callback run on an object before its memory is reclaimed (ADR-18).
  • Weak reference — a reference that does not by itself keep an object reachable, cleared once the referent is otherwise unreachable.
  • Humongous object — an object large enough to bypass the nursery and allocate directly into the old generation (ADR-15).
  • Fragmentation — free memory scattered in small, non-contiguous spans, unusable for larger allocations without compaction.
  • Conservative scanning — a root-scanning strategy that treats any value that looks like a valid pointer as a root, trading precision for not needing type information (ADR-13).
  • Precise scanning — a root-scanning strategy using exact type/stack-map information to know exactly which values are pointers (ADR-13).
  • Pinning — marking an object as non-relocatable, typically for FFI/native-code interop (ADR-09).
  • GC-correctness stress harness — the randomized allocate/mutate/drop workload generator paired with a shadow reachability oracle, this project's primary correctness CI gate (§23, §28).
  • Reachability oracle — a shadow liveness-tracking mechanism used by tests/the harness to independently verify the collector's own liveness determination (§28).
