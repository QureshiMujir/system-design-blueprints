Mutator: the application thread(s); the only code paths that allocate (bump-pointer into the nursery via a TLAB) and mutate the object graph (every pointer store passes through the write barrier). Correctness of the whole system depends on the mutator never bypassing the barrier (I3, I8).

Write Barrier: the single mechanism serving two masters — recording old→young pointers for the remembered set/card table (generational correctness, I3) and preserving the tri-color invariant during concurrent marking (SATB or incremental-update, I2). Runs on the mutator's hot path; its per-store cost is the collector's permanent throughput tax (P2, ADR-07, ADR-08).

Young Generation: nursery (Eden) plus survivor spaces, collected by a Cheney-style copying scavenge (minor GC). Bump-pointer allocation is possible only because the young gen is moving — dead space needs no bookkeeping, it is simply not copied forward.

Card Table / Remembered Set: the coarse-grained record of old→young references so a minor GC need not scan the (much larger) old generation for roots — only dirty cards plus true roots (I3, §8).

Old Generation: free-list (or region) managed space holding promoted survivors; collected rarely by a major GC (concurrent mark, then sweep or compact).

Tri-Color Mark State: the White/Gray/Black bitmap (or per-object mark bits) that makes "has this object been found reachable yet" a first-class, incrementally-updatable state instead of an all-or-nothing STW sweep (§8, I2).

Concurrent Marker: background thread(s) tracing the old-gen object graph while the mutator continues to run and allocate; correctness rests entirely on the barrier maintaining the tri-color invariant while the marker races the mutator (P3, I5).

Major GC (sweep/compact): after mark completes, reclaims white objects (sweep) or additionally relocates survivors to reduce fragmentation (compact, forwarding pointers, optionally a read barrier if compaction is itself concurrent — Phase 10).

Safepoint + Root Scanner: the brief, unavoidable stop-the-world moment needed to take a consistent root snapshot before/at the start of a marking cycle and before a moving minor GC; the only full-STW component in the steady-state design (I7, §8).

Promotion path: an object survives enough minor cycles (age ≥ tenuring threshold) or exceeds a size class, so it is copied from a survivor space into the old generation rather than back into the nursery — the boundary crossing that requires the write barrier's remembered-set half.

8.2 Tri-Color Abstraction

State diagram:

      allocate/reset          marker visits obj,          all fields
            |                 pushes to gray stack          scanned
            v                       |                          |
        [ WHITE ] ---------------> [ GRAY ] -----------------> [ BLACK ]

            |                new object allocated black            |
            +------------------------------------------------------+
                         (allocate-black policy, concurrent mark only)

Formal invariant (I2): for every edge (a → b) in the object graph observed at any instant during concurrent marking, NOT (color(a) = Black AND color(b) = White) unless a gray object g exists such that the marker has not yet finished scanning g and b remains reachable from g. The write barrier's entire job is to prevent this forbidden edge from ever existing unobserved: it does so either by graying b before the store is visible (incremental-update/Dijkstra) or by logging the pre-write referent so it is treated as if still reachable from the snapshot (SATB/Yuasa).

8.3 Write-Barrier Taxonomy

Worked example — card-table barrier firing: mutator executes old_obj.field = young_ref; where old_obj is in the old generation and young_ref points into the nursery. The barrier computes card_index = addr(old_obj) >> CARD_SHIFT and stores dirty into card_table[card_index] unconditionally (ADR-07's fast path takes no branch on the value, only on whether the store target is old-gen — precomputed at codegen time by the host). At the next minor GC, the scavenger scans every dirty card as an extra root source alongside true stack/register roots, finds young_ref, and correctly retains/copies it forward. What it protects: the specific young object young_ref — without this barrier firing, the minor GC would see no reference to it from within the nursery/roots and would reclaim it despite old_obj being alive and pointing to it (I3 violation → I1 violation).

Worked example — SATB barrier firing: mutator executes some_obj.field = new_ref; overwriting the old value old_ref while concurrent marking is in progress. The SATB barrier intercepts the write before it becomes visible, appends old_ref to the thread-local SATB buffer (I11), and only then performs the store. When the SATB buffer is flushed to the global mark queue, old_ref is treated as reachable from the marking snapshot even though the live mutator graph no longer points to it after this store. What it protects: old_ref — without the barrier, if old_ref was White and this was its last reference, it would never be grayed, yet it may still be reachable via some other black object not yet rescanned, producing an I2/I1 violation (the classic "lost object" race first solved by Dijkstra 1978, specialized to snapshot semantics by Yuasa 1990).

Worked example — incremental-update (Dijkstra) barrier firing: black_obj.field = white_ref; where black_obj has already been fully scanned (Black) and white_ref is a not-yet-visited object. The incremental-update barrier intercepts the write and, before or immediately after the store becomes visible, pushes white_ref onto the gray stack (transitioning it White→Gray) rather than logging the old value. What it protects: white_ref — without this barrier, the newly created edge black_obj → white_ref would be exactly the forbidden Black→White edge I2 disallows, since black_obj will never be rescanned to discover it. Contrast with the SATB worked example directly above: SATB protects the object being overwritten (the old referent), incremental-update protects the object being newly stored (the new referent) — this asymmetry is precisely why ADR-08 frames the choice as a floating-garbage-vs-barrier-shape tradeoff (P10): SATB conservatively over-retains (both the old and, transitively, anything only reachable through it), while incremental-update only grays what is freshly discovered, at the cost of a barrier that must run even on stores that do not overwrite any previous reference (e.g. initializing a previously-null field).

8.4 Minor Collection (Cheney-Style Copying Scavenge)

Named steps:

  1. Safepoint reached, roots snapshotted (I7).
  2. Flip roles: current "to-space" survivor becomes scan target; nursery + old "from-space" survivor are the source.
  3. Copy every root-reachable object from Eden/From-survivor into To-survivor, leaving a forwarding pointer in the original header (I9).
  4. Cheney scan: walk the To-survivor space itself with a scan pointer trailing the allocation pointer — every field of a just-copied object is itself followed and copied if not already forwarded, until scan pointer catches allocation pointer (terminates in O(survivors)).
  5. Consult dirty cards/remembered set (I3) as additional roots for old→young edges.
  6. Age every surviving object; if age ≥ tenuring threshold or object is oversized, promote to old gen instead of To-survivor (ADR-15) — allocate from the old-gen free-list, mark the promotion in the remembered set if it retains old→young edges.
  7. Reset Eden and From-survivor as available bump-pointer space; resume mutator.

Worked scavenge: Eden holds objects A(live, referenced by root R), B(dead), C(live, referenced by A). Root scan finds R→A. Copy A to To-survivor at offset 0, leave A.forward = to+0. Cheney scan pointer visits copied-A's fields: finds A→C, C not yet forwarded, copy C to To-survivor at offset (sizeof A), set C.forward, rewrite A's copied field to point at new C. Scan pointer advances past copied-A, reaches copied-C, finds no further live fields, scan pointer catches allocation pointer — scavenge complete. B, never visited, is implicitly reclaimed (Eden is simply reset). Total work: O(|{A,C}|), independent of Eden's total size — this is P1's mechanism made concrete.

8.5 Major Collection (Concurrent Mark, Then Sweep or Compact)

Named steps:

  1. Initial mark (STW, short): snapshot old-gen roots plus every card-table-referenced object as gray.
  2. Concurrent mark: marker thread(s) drain the gray stack, scanning each object's fields, transitioning White→Gray→Black, while the mutator runs under the chosen barrier (SATB/incremental-update, §8.3).
  3. Remark (STW, short): drain any residual gray entries accumulated via the barrier during concurrent marking (SATB log flush or incremental-update stragglers) — this is where I5's race is finally settled.
  4. Concurrent sweep: reclaim White objects in the old generation, rebuild free-list spans, without stopping the mutator (Phase 9).
  5. Optional compact: if fragmentation exceeds threshold, relocate surviving Black objects using forwarding pointers (Steele 1975, Baker 1978) — STW if non-concurrent compaction, or with a read barrier if concurrent (Phase 10, Tene et al. 2011).

The sweep-vs-compact decision at step 5 is itself a threshold policy, not a fixed choice each cycle: the sweeper (Phase 9) tracks a per-region fragmentation score (live bytes vs largest contiguous free span); a major cycle triggers compaction only when the fraction of regions above a configured fragmentation-score threshold exceeds a configured proportion of the old generation (default: compact when >20% of regions exceed a 40% fragmentation score) — sweeping alone is cheaper and is the default outcome of most major cycles, with compaction reserved for the minority of cycles where fragmentation has actually accumulated to a problematic degree (P9's space/cost tradeoff applied at the sweep/compact boundary rather than just the barrier boundary).

8.6 Concurrent Marking Algorithm and the Race Constraint

The marker drains a work-stealing gray stack (ADR-16) concurrently with mutator allocation. Let mark_rate = objects traced per second by the marker pool, alloc_rate = bytes allocated per second by the mutator, avg_obj_size = mean object size, and headroom = configured safety factor (§4: ≥1.3). The race constraint (I5) is:

mark_rate  >=  headroom * (alloc_rate / avg_obj_size)

If this inequality is violated, the mark cycle cannot certify termination before the heap fills; the pacing controller responds by throttling mutator allocation (inserting allocation stalls) or by escalating the marker's CPU share, never by abandoning I5.

A second, coupled equation governs how the pacing controller actually escalates: let w = current marker worker-thread count, per_worker_rate = objects/sec traced by one worker at current cache/memory-bandwidth conditions, so mark_rate = w * per_worker_rate. Solving the race constraint for w gives the minimum worker count to restore headroom:

w_min  =  ceil( headroom * (alloc_rate / avg_obj_size) / per_worker_rate )

The pacing controller computes w_min continuously from sampled rates and either scales the live worker pool toward it (bounded by the CPU-topology ceiling, §31) or, if w_min exceeds that ceiling, falls back to throttling mutator allocation directly — the two levers named in P11 are therefore not alternatives chosen once, but two terms of the same equation applied in priority order (scale workers first, throttle allocation only once worker scaling is exhausted).

8.7 Generational Hypothesis and Promotion/Age Policy

Empirically (Ungar 1984, reconfirmed across HotSpot/V8/Go workloads) object mortality is heavily front-loaded: a large majority of allocations become unreachable within one or two minor cycles. The age counter (§8.1) increments each time an object survives a scavenge; promotion triggers at age >= tenuring_threshold (ADR-15, default threshold tuned in Phase 11) or immediately for objects at/above the humongous size class. Setting the threshold too low causes premature promotion (old gen fills with objects that would have died in the nursery, driving unnecessary major cycles); too high causes excess copy cost (long-lived objects repeatedly copied survivor-to-survivor, P8).

Ungar's original generation-scavenging design (1984) used a fixed, small tenuring threshold (often as low as 1) tuned for the Smalltalk workloads of the era; modern collectors (HotSpot's default) instead track a per-cycle age-vs-survival-rate histogram ("desired survivor size" policy) and adjust the threshold dynamically each minor cycle so that the survivor space stays within its configured occupancy target — this project's Phase 11 tuning process adopts the dynamic-histogram approach over Ungar's fixed threshold specifically because a fixed threshold cannot adapt to a workload's mortality curve shifting over the process lifetime (e.g. a warmup phase with different allocation behavior than steady state).

8.8 Safepoint and Root-Scanning Model

A safepoint is a program point at which every mutator thread's registers/stack are in a GC-legible state. The safepoint coordinator (Phase 8) requests a poll, waits for convergence across the thread registry (I7), then hands control to the root scanner, which walks each thread's precise stack map (ADR-13) plus global/static roots plus any host-registered handle tables. Only after convergence is a root set trusted as a consistent snapshot for either a minor GC's copy phase or a major GC's initial mark.

8.9 Floating Garbage and Re-Mark Handling

Objects marked Black that become unreachable after being scanned (e.g. the last reference is overwritten post-scan) are floating garbage — correctly not reclaimed this cycle (P7), reclaimed next cycle instead. The remark phase (§8.5 step 3) additionally catches objects grayed during concurrent marking via the barrier log/queue that have not yet been drained, ensuring I2 holds at the moment marking is declared complete, not merely on average.

8.10 Worked Full Example — Nursery to Concurrent Collection

Object X is allocated in Eden via bump-pointer (Phase 1). It survives minor cycle 1 (root-reachable, age→1), copied Eden→To-survivor. It survives minor cycle 2 (age→2, still referenced, now by an old-gen object P via a pointer stored earlier — the write barrier already dirtied P's card, §8.3). At minor cycle 3, X's age reaches the tenuring threshold (3); it is promoted directly into the old-gen free-list rather than copied to survivor space; because P→X is now an intra-old-gen edge (both promoted), no remembered-set entry is needed for it going forward, but the promotion itself is logged. Later, old-gen occupancy crosses the major-GC trigger threshold (§4); initial mark snapshots roots including P (reachable from a stack root), grays P, concurrent mark scans P's fields, finds P→X, grays then blackens X. X survives the major cycle as live. Months of runtime later, P is dropped by the mutator (its last reference overwritten — write barrier fires, either logging old P value under SATB or graying nothing new under incremental-update since no new reference is created), P and transitively X go White in the next cycle's initial mark (no root or black object reaches them), and both are reclaimed by concurrent sweep.

Extending the example one step further into compaction (Phase 10): suppose that, before P and X are dropped, the old generation has accumulated enough fragmentation from unrelated churn (other objects allocated and freed around P and X, leaving small unusable gaps) that a major cycle's post-sweep fragmentation score crosses the §8.5 compaction threshold. P and X, both still live and Black at that point, are relocated: P is copied to a denser region, its old header overwritten with a forwarding pointer (I9); every reference to P — including any the root set holds directly, and the field inside P pointing to X — is rewritten during the STW relocation pass (I4) before the mutator resumes. If concurrent-compaction mode (ADR-11) were active instead, that same rewrite would instead happen lazily: a mutator thread reading P mid-relocation would transparently follow the read barrier to P's new address without ever observing the stale one. This is the exact seam described in P5 — the same object, the same relocation event, handled by two structurally different mechanisms depending on whether compaction is STW or concurrent.

8.11 Malformed / Hard Examples

  • Missing write barrier on old_obj.field = young_ref: the young object is invisible to the next minor GC's root set and is incorrectly reclaimed while old_obj still holds a now-dangling pointer to it — the catastrophic case, a live-object loss (I1, I3 violation), manifesting as a use-after-free only when the mutator later dereferences the stale field.
  • An old→young pointer created by a card-marking bug that clears the dirty bit before the scavenger scans it (I12 violation): identical symptom to the missing-barrier case, but the root cause is in the refinement worker's clear-ordering, not the barrier call site.
  • A black→white violation during concurrent mark: incremental-update barrier fails to gray a newly-stored white referent because of a barrier-bypass fast path taken incorrectly (e.g. an inlined store the compiler forgot to instrument) — X is reachable only via a black object, never grayed, reclaimed by concurrent sweep while still live (I2 violation cascading to I1).
  • A mark that loses the race (I5 violated): allocation rate spikes beyond headroom * alloc_rate mid-cycle; the gray stack cannot drain before old-gen free space is exhausted; the pacing controller's stall was miscalibrated — the fallback is a forced STW full mark rather than an allocation failure (P12, FM-3).
  • A moving-GC reference not updated (I4 violation): a conservative-scan-derived root is a false positive interpreted as a precise pointer, gets "updated" to a forwarding target that is actually unrelated data, corrupting an integer that merely looked like a pointer.
  • A finalizer resurrecting an object: a finalizer stores self into a global root during finalization, making an object the collector had already begun reclaiming reachable again — handled by a dedicated finalization reachability pass (ADR-18) that must run to fixpoint before final sweep, else it is an I1 violation via resurrection.
  • A SATB buffer overflow silently dropping entries instead of flushing (a resource-exhaustion bug rather than a logic bug): under a mutation burst exceeding the local buffer's capacity, a naive implementation that drops the oldest entries rather than force-flushing violates I11 exactly as if the barrier had never fired for those dropped entries — indistinguishable in symptom from the missing-barrier case above, but only reproducible under sustained high mutation rate, making it a load-dependent variant of the same root failure class.
  • A promotion racing a concurrent old-gen sweep: an object is promoted into a region the sweeper is mid-scan on; if the promotion allocation and the sweeper's live-bit accounting are not correctly sequenced (region-local locking, Phase 9), the sweeper may treat the newly-promoted object's memory as still-free space, corrupting the free-list on the very next allocation from that span — an I1-adjacent violation rooted in a Phase 3/Phase 9 interaction rather than either phase alone.

8.12 Failure-Path Example

Concurrent marker thread panics mid-drain (e.g. a corrupted type descriptor pointer causes an out-of-bounds field read). Detection: the marker's watchdog observes a stalled gray-stack drain rate (feeds gc_mark_race_margin toward violation). Recovery: the collector treats this as P12 — halts promotion and old-gen allocation, quarantines the malformed object's region, and restarts marking from a fresh initial-mark snapshot using the conservative root scanner as a temporary fallback (ADR-13's rejected-choice-wins case) while the malformed type descriptor is logged for host-runtime-side forensics (T1, FM-6).

A second failure path worth tracing end to end: a host-runtime deploy ships new codegen that inlines a hot pointer-store call site without threading the barrier instrumentation through the inlined copy (the exact T1/§8.11 bug class, but introduced by a compiler change rather than a hand-written bug). In production, the bug is silent for hours — it only manifests once a concurrently-marked object's last reference happens to be overwritten through that specific inlined path during an active mark window. The reachability oracle's stress-harness variant (Phase 11) would have caught this pre-release because it exercises every instrumented call site under adversarial concurrent mutation; its absence from a given release's test matrix (rather than any flaw in the harness itself) is the actual root cause the postmortem (§25's forensics column) must trace back to — illustrating why §29's CI topology gates every PR touching barrier-adjacent crates through gc-stress.yml specifically, not just ci.yml's unit tests.
