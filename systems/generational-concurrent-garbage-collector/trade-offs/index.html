Roads not taken (§36)

Reference Counting

   +--------+  incr/decr refcount   +--------+
   | Object |<---------------------| Object |
   |  rc=2  |   on every assign     |  rc=1  |
   +--------+                       +--------+
        ^  immediate free when rc hits 0
        |  (no tracing pass, no pause)
   +----+------------------------------------+
   | PROBLEM: cyclic garbage (A<->B, rc>0     |
   | each, unreachable from any root) never   |
   | reaches rc=0 -> requires a supplementary |
   | cycle collector (trial deletion / tracing)|
   +-------------------------------------------+

Winning regime: workloads needing immediate, deterministic reclamation with no tracing pause at all, and where cycles are rare or explicitly avoided (weak references break them by convention). Real embodying system: CPython (refcounting + a supplementary generational cycle detector) and Swift ARC. Rejected as the primary design here because: the whole point of this project is the generational + concurrent tracing model (§1); refcounting's per-store counter-update cost (P2-adjacent but structurally different) and its need for a bolted-on cycle collector make it a poor fit for a project whose stated mandate is tracing-GC mastery (§2), not refcounting mastery.

Quantified contrast: refcounting pays its cost on every pointer assignment unconditionally (an increment plus a decrement of the old value, both atomic under multithreading), whereas this project's write barrier (§8.3) pays a comparable per-store cost only in the specific configurations where it is needed (always for card-marking, only during an active mark window for SATB) — meaning tracing's barrier cost is more variable but its floor, at a quiescent (non-marking) moment, is lower than refcounting's unconditional cost, which never goes away regardless of collection phase. Interestingly, CPython's own supplementary cycle detector is itself a small tracing collector bolted onto a refcounting base — an empirical admission that pure refcounting alone cannot handle the general case, which is the strongest argument for this project's tracing-first design.

Even where refcounting is a poor fit for the collector itself, its immediate-reclamation property remains relevant to this project's finalization design (ADR-18, Phase 9): a finalizer callback firing promptly on last-reference-drop is exactly what refcounting gives for free and what a tracing collector must approximate with the coarser granularity of full collection cycles — a tradeoff this project accepts explicitly (§8.9's floating-garbage discussion) rather than treating as an oversight.

Non-Generational Concurrent Collector (Go's Choice)

   +-----------------------------------------------------+
   |                    FLAT HEAP                          |
   |   (no nursery, no old gen, no promotion, no RS)       |
   +-----------------------+-------------------------------+
                           | concurrent mark (hybrid barrier)
                           v
                +---------------------+
                | CONCURRENT MARKER    |
                +----------+-----------+
                           | STW start/end only
                           v
                +---------------------+
                |  concurrent sweep    |
                +---------------------+

Winning regime: workloads where implementation simplicity and a smaller barrier surface matter more than minimizing full-heap mark cost — short-lived server processes, or languages whose allocation patterns do not exhibit as sharp a generational skew. Real embodying system: the Go runtime GC (src/runtime/mgc.go). Rejected as the primary design here because: this project's explicit mandate is to add generations on top of a concurrent collector (§1) — a flat design forgoes P1's core efficiency win (most objects die young) entirely, marking the whole live set every cycle regardless of age.

Stop-the-World Parallel Throughput Collection

   [ mutator STOPPED entirely ]
        |
        v
   +------------------------------------------+
   | N parallel STW worker threads             |
   | mark + sweep/compact the WHOLE heap        |
   | as fast as possible, mutator fully halted  |
   +------------------------------------------+
        |
        v
   [ mutator RESUMES ]   <- pause = full-heap trace / N threads

Winning regime: batch/offline workloads with no interactivity requirement, where maximizing total throughput (objects processed per CPU-second) matters more than any single pause length — exactly project 32's lineage (basic stop-the-world mark-sweep, parallelized). Real embodying system: HotSpot Parallel GC ("Throughput Collector"). Rejected as the primary design here because: ADR-17 explicitly locks this project to a pause-time-first target: a throughput collector's pauses scale with full-heap live-set size and are unbounded in the interactive sense this project's §4 constraints require.

Region-Based / Concurrent-Compacting With Colored Pointers

   +----------------------------------------------------+
   | HEAP as many small regions ("ZPages"/regions)        |
   +--------------------+---------------------------------+
                         | every load passes through
                         v
              +-----------------------+
              | COLORED-POINTER LOAD  |
              | BARRIER (checks bits  |
              | encoded in the ptr)   |
              +-----------+-----------+
                         | relocating? follow forwarding, fix up
                         v
              +-----------------------+
              | concurrent relocation |
              | of chosen regions      |
              +-----------------------+
   (no STW compaction pause; cost paid on every load instead)

Winning regime: very large heaps (tens to hundreds of GB) where a sub-millisecond pause target must hold regardless of heap size — exactly the wall identified in §31/§34.8. Real embodying system: ZGC and Shenandoah (OpenJDK). Rejected as the primary/default design here because: the always-on load/read-barrier cost (P5, ADR-11) is a permanent throughput tax paid on every single mutator load, not just writes — a cost this project's default (pause-time-first but not pauseless-at-any-cost, ADR-17) chooses not to pay by default, instead offering it as Phase 10's explicit opt-in for deployments that need it.
